| | |
|---|---|
| 版本 | 0.9.0 |
| 安装包 | `dsh-company-pack-0.9.0.tgz`（与本手册同目录） |
| 校验（sha256） | `72e6abcf48a996f6bc5c0eee39908b864fa84bb56f3a1d4fdbeb8174c77940c4` |
| 打包日期 | 2026-11-05 |
| 适用 DSH | `engines.dsh` 窗口内（`>=0.2.1-rc.2 <0.3.0`；已验证基线 `dsh-v0.2.1-rc.5`） |
| 许可 | MIT（`LICENSE` 随包） |

这个安装包是自包含的：bundle 补丁、六个角色 preset、浏览器端、host 行，以及 `content/`
（公司手册/模板/默认章程/状态默认值）。**没有启动器、没有 package bin、没有可写的 profile 目录。**

**交付形态**：一个 bundle 装进一个 named profile。插件内容全部在包内；运行状态与最终产物
（公司状态）全部在用户 workspace 的 `.dsh-company/`；home 只留 DSH 运行时与 host 治理
（sessions / 凭据 / workspace 登记 / lease / 方法层 / presented 账本 / 身份备份）。一个安装 =
一个公司，可顺序服务多个 workspace；不同公司才用不同 `DSH_HOME`。

## 零、前置：DSH 与 workspace

- **DSH 已安装**：官方 Desktop，或可用的 `dsh` CLI。先 `dsh --version`，确认版本在
  `engines.dsh` 窗口内；不在窗口内先升级 DSH（安装器会拒绝不兼容的包）。
- **一个 workspace 目录**：已存在、可写。不需要专用空盘；本包只在其中写 `.dsh-company/`。
- **运行时前置**：Desktop 由 DSH 自带 Node/pnpm；npm CLI / `dsh web` 的 Plugins 页需要 pnpm 在 PATH
  （或 `corepack enable pnpm`）。不要求为这个包单独安装构建工具或修改 profile 文件；用户只面对
  DSH 的 Plugins 页/CLI。
- **许可**：MIT（`LICENSE` 随包）。

## 一、安装：默认在 DSH 应用内 Plugins 页

### GUI（默认，web 与 Desktop 同一句）

1. 打开 DSH。
2. 进入 **Plugins** 页 → **Add plugin**。
3. 已发布版本输入包名 `dsh-company-pack`（可带 `@version`）；本仓 `_dist` 交付
   （尚未 publish 时）粘贴 tarball 的**绝对路径**——该入口接受包名、Git、tarball、本地目录。
4. 安装完成后确认结果是 `application: applied`；若有“重启/刷新”提示，按提示重启 profile
   （浏览器模块不会热加载）。

Desktop 用户也用这一句。**不要**用 CLI 的 profile 参数去装 Desktop——CLI 只覆盖它能碰到的那一个
profile，装错不会出现在 App 里。

三个成功（排障时分开核）：安装命令成功 → dependency 写入 → 进 `dsh.profile.bundles`；
只有第三个让功能存在。GUI 装完以 Plugins 页显示“已安装/启用”为准。

### CLI（只用于 headless/SDK/ACP 或 `dsh web` 自动化）

GUI 用户不需要这一节。CLI 的 `--profile` 只作 `dsh web` 自动化；**不能管理 Desktop**。

```sh
dsh --version                                  # 必须在 engines.dsh 窗口内
dsh --profile company --from-default-profile web --dump-default-config   # 仅首次；仅 CLI web 自动化
dsh plugin --profile company add /path/to/dsh-company-pack-0.9.0.tgz           # 或 dsh-company-pack@0.9.0
```

> **仅 `dsh web`**。CLI 不能管理 Desktop profile（双门禁闭）。
> `--from-default-profile web` 只在 profile 缺失时用；已有 profile 上再用会替换它的依赖与用户 patch。
> 公司包要求含 `dsh-web-app` 的 web template；base-only 自定义 profile 会让 preset 行 pending。

装完**重启该 profile**；CLI 是另一个进程，宿主不知道。真启动一次，stderr 不应有
`did not activate` 或 `skipping profile bundle`；`--dump-config` 有 row 不等于挂载。

### 从 DSH 市场发现（发布后）

市场是实验能力（Plugins → Experimental plugins → **Custom plugin markets**）。本版本未发布到 registry
时没有可加源；发布后按发布方给出的索引 URL/说明操作。市场 index 只做发现与展示；安装时 DSH 仍会读包
自身 manifest 的 `engines.dsh`，不兼容会被拒。

### 可选：浏览器能力（条件启用）

npm 发布的 `dsh` 不含 `dsh-browser-use` 与 `dsh-experimental-browser-use-playwright-mcp`，
所以六个角色默认**不带** browser 工具。要开浏览器，用同一个安装入口装这两个包（GUI 用 Plugins 页；
headless/自动化用 `dsh plugin --profile company add`）。装进 profile 后 preset 自动探测并启用；
也可用 `DSH_COMPANY_BROWSER=on/off` 强制。**不要**在没装包时设 `on`——六个角色会报
`browser-use-def ... never started`。

## 二、第一次启动

安装完成后：

- **GUI**：从 DSH 的 Workspace picker 选择你的项目目录（或直接打开已有 workspace），首屏即可开工。
- **CLI/web 自动化**：在项目目录启动：

```sh
cd /path/to/your-project
dsh --profile company
# 或显式指定：
DSH_COMPANY_HOME=/path/to/your-project dsh --profile company
```

workspace 优先级：`DSH_COMPANY_HOME` → 启动 cwd（合理项目目录）→ `DSH_HOME/company/settings.json`
的最近选择（便利提示）→ DSH Workspace picker（本包不自建 onboarding）。**没有 workspace 专用命令行参数，
也没有终端 TTY 询问。** 没有 workspace 时 Host 不写盘；Host boot 不等用户。

首启会：

- 在 workspace 建 `.dsh-company/`：`kb/`、`deliverables/`、`cultivation/`、
  `logs/`、`exports/`、`overrides/`；
- 只补缺地写状态实例（company/org/owners/台账/章程）；不覆盖已有文件；
- 写 `.dsh-company/bundle.json`（v3，legacy 文件名：id / createdAt / pack；`pack` 是创建时的包版本）；
- 登记 workspace（如果启动时已知道）；首屏由 DSH Workspace picker 回答（本包不自建 onboarding）；
- **不**在 workspace 根写手册/模板/kb/deliverables；**不**在 home 根写 bundle。

首启是 DSH 的 token 门：`dsh web` 打印 `?token=…` URL；无 token 401，带 token 303 +
HttpOnly cookie → SPA。原生没有欢迎页/向导；Desktop 不依赖 `welcome-notice`。

## 三、验证

先确认 DSH 版本与安装状态：

```sh
dsh --version                    # 在 engines.dsh 窗口内
# GUI：Plugins 页显示 dsh-company-pack 已安装/启用
# CLI 自动化：
dsh --profile company --dump-config | grep -c company-pack   # 期望 ≥1
```

启动后可选核对公司状态：

```sh
cat "/path/to/your-project/.dsh-company/bundle.json"   # v3 / id / pack
ls /path/to/your-project/.dsh-company/kb               # company/org/owners/motion-ledger/角色目录
```

期望：workspace 根没有本包写出的手册/模板；`.dsh-company/` 存在；启动 stderr 无
`did not activate`；有 workspace 时首屏不要求你手动“加工作区”。

如要校验安装包字节（可选）：

```sh
shasum -a 256 dsh-company-pack-0.9.0.tgz          # macOS；Linux 用 sha256sum
shasum -a 256 -c dsh-company-pack-0.9.0.tgz.sha256
```

## 四、数据布局

| 平面 | 放什么 | 谁拥有 |
|---|---|---|
| 包内内容 | `lib/**`（runtime 两半 + 类型）、`presets/**`、`content/**`（手册/模板/默认章程/状态默认值）、`locale/`、`icon.svg`、`cordis.patch.yml` | 维护者；只读 |
| 用户 workspace | `.dsh-company/`：kb / deliverables / cultivation / logs / exports / overrides / `bundle.json`（v3，legacy 文件名） | 用户；可携带的公司状态 |
| Harness home | `profiles/company`、sessions、凭据、workspace 登记、lease、`company/methods/`、`company/ledger/`、`company/identity/` | DSH + host 治理 |
| 派生索引 | `cache/company/session-search-<profile>.db`（SQLite FTS5；单进程 owner） | 可删可重建；不进备份 |

用户项目自己的项目指令文件不会被复制或覆盖；公司手册从包 `content/AGENTS.md` 注入 system prompt，
不写入 workspace。模板默认读包；要改就放 `.dsh-company/overrides/`。

## 五、升级

- **外部插件没有 Update 按钮**：升级 = 安装新版本覆盖（tarball/registry 皆可），然后重启 profile、浏览器硬刷新；必要时才 Remove 再装。
  GUI 用 Plugins 页的 Remove / Add plugin；CLI（仅 web 自动化）用
  `dsh plugin --profile company remove dsh-company-pack` → `dsh plugin --profile company add`。
- 包内容随包版本只读；`.dsh-company/` 状态只补缺，不覆盖你改过的文件。
- `.dsh-company/bundle.json` 的 `pack` 字段记录**创建这个公司状态的包版本**，不是当前
  安装版本；排障时以 Plugins 页/依赖里的版本为准。
- **降级**：先备份 → 装回旧包 → 重启；更高 schema 的 `bundle.json`/账本/记录不会被旧版静默改写。
- DSH 没有命令级回滚；回退就是装回旧版本。

## 六、备份 / 迁移

| 姿势 | 打包什么 | 不包含 / 会丢什么 | 用途 |
|---|---|---|---|
| **business** | workspace 的 `.dsh-company/` + home 的 `company/methods/`、`company/ledger/`、`company/identity/`（或已导出的 `exports/`） | sessions、`.credentials.yaml`、缓存 | 交接 / 换机器 / 业务归档 |
| **full** | 整个 `DSH_HOME` + workspace | 无；含会话正文、密钥、绝对路径 | 整机迁移 / 灾难恢复；加密、限权、不共享 |

```sh
tar -czf company-business.tgz -C /path/to/your-project .dsh-company
[ -d "$DSH_HOME/company/methods" ] && tar -czf company-business-methods.tgz -C "$DSH_HOME" company/methods
[ -d "$DSH_HOME/company/ledger" ] && tar -czf company-business-ledger.tgz -C "$DSH_HOME" company/ledger
```

恢复 business：新 home → 解 `.dsh-company/` → 用同一个安装入口装同版本/新版本 → 以该 workspace
启动；**没有 sessions，旧会话不会回来**；方法层/账本按 home 恢复（或由 host 重新导出）。
恢复 full：整 home + workspace 搬移；profile 依赖失效时重装；DSH 自己的 workspace 登记与 session cwd 是
绝对路径，搬完要重新添加工作区/接受旧会话不可续。

## 七、卸载

在 DSH 应用内 Plugin Manager 移除 `dsh-company-pack`（CLI 自动化才用
`dsh plugin --profile company remove dsh-company-pack`）。只卸插件与 profile 层；数据默认留下：

| 留下什么 | 位置 |
|---|---|
| 公司状态（kb / deliverables / cultivation / logs / exports / bundle.json） | `<workspace>/.dsh-company/` |
| 身份备份、方法层、presented 账本 | `<DSH_HOME>/company/` |
| 并发写者锁（lease） | `<DSH_HOME>/company-pack.lock`（在 home 根，不在 `company/` 里） |
| workspace 登记行（host 经 DSH registry 加的） | `<DSH_HOME>/storages/workspace.json` |
| presented 账本 storage | `<DSH_HOME>/storages/company_run_bundle_ledger.json` |
| 客户端错误日志（已脱敏） | `<DSH_HOME>/logs/company-client-errors.log` |
| 浮窗几何 / 实例心跳（浏览器本地） | 浏览器 localStorage（按 origin 隔离；换端口即新 origin） |
| 会话与凭据（DSH 所有） | `<DSH_HOME>/sessions/`、`<DSH_HOME>/.credentials.yaml` |

要彻底删除一个公司，确认备份后按面删除：

```sh
rm -rf <workspace>/.dsh-company
rm -rf <DSH_HOME>/company
rm -f  <DSH_HOME>/company-pack.lock
rm -f  <DSH_HOME>/logs/company-client-errors.log
rm -f  <DSH_HOME>/storages/company_run_bundle_ledger.json
rm -f  <DSH_HOME>/cache/company/session-search-*.db      # 派生索引，可删可重建
```

**不要**为了清插件删除整个 `DSH_HOME`——会话、凭据、其他 profile 的依赖都在那里。本包不代删用户项目。

## 八、安装失败与回退

- **版本不匹配**：安装会被拒绝并报 `incompatible-version`；先升级 DSH 到 `engines.dsh` 窗口内，
  不要用 `allow-version` 绕过。
- **安装后在界面看不到**：确认是装在当前 profile/当前 App（Desktop 与 web 是两个 profile）；重启 profile；
  看 Plugins 页与启动 stderr 的 `did not activate`。
- **CLI 报包管理器缺失**：这是 DSH 安装/运行时的问题，按 DSH 安装文档修复 DSH；npm CLI / `dsh web` 的 Plugins 页需要 pnpm 在 PATH；Desktop 用内置 pnpm。
- **workspace 没出现/首屏要 Choose workspace**：从项目目录启动或设 `DSH_COMPANY_HOME`；无 workspace
  时 Host 故意不写，等你在 DSH Workspace picker 里选。
- **`bundle.json` 损坏**：host 会停写并保留原文件；从 `$DSH_HOME/company/identity/<id>.json`
  恢复或备份后让 host 重建。
- **回退**：备份整个 home + workspace；用同一个安装入口装回上一个版本；旧版不会静默改写更高 schema 的状态文件。

## 常见问题

| 现象 | 原因与处理 |
|---|---|
| 刷新后什么都没出现 | 浏览器不热加载模块：重启 profile（Desktop 重启 App），再硬刷新页面 |
| 两个公司看到彼此的历史 | 复用了同一个 `DSH_HOME`：新开 home |
| 浏览器首屏要求 Choose workspace | 启动时没有 workspace：从项目目录启动、设 `DSH_COMPANY_HOME`，或在 picker 里选 |
| 公司数据停写 | workspace 落点不安全 / `bundle.json` 坏 / lease 冲突：看启动输出 |
| 成员会话内容被截断 | host 手册注入预算不足：看 pack README 与 `handbook-budget` 门禁 |
| 六角色报 `browser-use-def ... never started` | 没装 browser 两包却设了 `DSH_COMPANY_BROWSER=on`：装包或 unset/off |
| 升级后页面还是旧模块 | 重启 profile + 硬刷新；浏览器模块不热加载 |
