# 2026-09-25 · UX 实验轮：坐进驾驶舱，把"人被拉进来"的感受提早摸出来

状态：proposed（2026-09-25 用户定档："做完了我们就开始做实验"——体验面正是缺口）

## 问题

人机合一的机制链路已全通（B2 12/12：审批/问询/补料/缺口回流机器上都能跑），但**体验从未被感受过**。
用户要的是"提早感觉出来"：CEO 做事 → CFO/COO/VP 互动过程中需要人时，**人这一侧到底经历什么**——
打断的时机对不对、给的上下文够不够、在哪儿回应顺不顺手、一次被拉进来烦不烦。这些只有真人坐进
驾驶舱跑一场真动议才能暴露；且搁置池里 B3/B4（client 增强）的复活条件恰恰是"实验发现真需要"。

## 实验设计（一场复合动议 × 四类拉人点全覆盖）

**动议**：「大客户 X 年度维护合同续约评估」——刻意设计成四类人机接口全部命中：

1. **要审批（阻塞）**：续约报价 8.2 折（< 9 折下限）⇒ 触 CFO+CEO 双签线 ⇒ `request_signoff`
   ⇒ 驾驶舱审批面板 + 注意力中心条目 ⇒ 人点 Allow/Reject。
2. **规矩缺口（阻塞裁决）**：顺带决定"要不要给客户送开年礼品"——手册没这条规矩 ⇒
   成员按缺口路径 `ask_user_question` 问人（选项式裁决）⇒ 人点选项 ⇒ agent 回流 journal。
3. **要资料（非阻塞）**：竞品最新报价单人手里才有 ⇒ 成员在会话里说一声 ⇒
   人把文件丢进共享盘 + 说路径（退化形状）⇒ agent 读到继续。
4. **要建议（非阻塞）**：市场判断上 VP-Sales 想听人的直觉 ⇒ 会话内直接答复 ⇒
   agent 当输入消化（不阻塞、不授予落稿权）。

**人这一侧的体验流**（用户坐 `http://127.0.0.1:3081` 驾驶舱观察窗）：
注意力中心聚合等人条目 + 一键跳会话 → 审批面板（官方 ui-approval：reason/工具名/两钮）→
问询卡（选项 radio + Enter）→ 会话内补料/建议消息 → 轮末文件变更审阅卡 + present 预览（收割面）。

## 方法与轮次

1. **预检**：verify/test/preset-smoke 绿；company profile web 起在 3081；素材预置（竞品报价单
   留给用户亲手丢——那本身就是补料体验的一部分）。
2. **开跑**：用户在场，CEO 会话起真动议（真公司盘——交付物/journal 落真盘，这就是真实体验）；
   全程用户自由操作，**每次被拉进来时顺手记一句体感**（时机对吗/上下文够吗/在哪回应的/烦不烦）。
3. **留证**：我同步采集会话日志（approval/asked、question tool call、team 消息）、关键节点截图、
   用户的体感笔记（几句即可，不搞问卷）。
4. **复盘 → 分拣**：体感发现按三档分——① 文案/规矩层小修（当场改，手册/skill 措辞）；
   ② 搁置池复活（B3/B4 或其他 client 增强——**用真实体感证据裁决，不再凭空猜**）；
   ③ 新提案（实验暴露的新形状 → notes/proposed/）。
5. **迭代**：第一轮体感修完可跑第二场（换动议类型），直到用户说"感觉对了"。

## 输掉的方案

- **先做 B3/B4 client 增强再实验**：没有体感证据就做显示增强 = 又凭空猜 UX（阶段 0 的教训）；
  输给"先感受、证据驱动复活"。
- **排练场假动议**：假盘感觉不出来（用户要的是提早感受真实体验）；输给真盘真动议（产物可控：
  评估类动议无对外副作用，deliverables 三态机器盯）。
- **我代替人跑**：实验对象就是"人被拉进来的体验"，我代跑 = 没有实验对象；用户必须在场。

## 验收

- 一场动议跑完，四类拉人点全部真实命中且人侧各有一次真实回应（日志 + 截图为证）；
- 用户体感笔记落 `notes/research/`（每条：哪类接口 / 时机 / 上下文 / 回应位置 / 烦不烦 + 一句改进）；
- 复盘三档各有产出（小修当场绿 / 搁置池复活裁决有据 / 新提案落 proposed 或明确无）；verify/test 保持绿。

## 风险

- 真动议成本 ≈ $2–5 + 用户在场 15–30 分钟；模型方差可能漏触发某个拉人点（预案 = 缺哪个补跑哪个
  单点，不整场重跑——human-loop-e2e 的分段法）；
- 动议若跑偏（成员没按规矩走）：偏航本身也是实验数据（如实记），不中途救场。
