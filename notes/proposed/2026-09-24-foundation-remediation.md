# 基石整治：入口链、执行链与验证证据

状态：proposed（实施中；用户 2026-09-24 明确要求完成整个已登记范围）

## Problem

[第一批修复](../implemented/2026-09-24-foundation-first-step.md) 已补 Notes 入口、当前章程路径与六个 smoke 隔离。本条继续剩余基石问题，优先让新 agent 接任务时不误读、不盲做、不虚报完成。用户要求保留原体系，AGENTS.md 尽量少动；不能以脚本改造替代 MD 阅读与执行链诊治。

## Proposal

1. **入口链**：根入口简短路由；地图解释当前合同与决策状态；ROADMAP 明确活动/暂停/历史范围；开工按主题读相关 Notes，再核对实现。用户指定任务、继续下一项、恢复旧任务分支都有明确走法。
2. **执行链**：明确任务目标/非目标/验收 → 查相关取舍 → 计划/授权 → 小步实施与正反验证 → 同 diff 更新合同与 Notes → 按证据交接。既有 Plan/todo 载体保留，区分本仓政策与 vendor 原生要求。
3. **防错检查**：链接路径和标题锚点、当前章程 cwd 路径、日用 home 隔离；验证覆盖明确，不能误扫历史工作区或伪造新证据。
4. **可信验证**：入口探针明确 coding baseline、逐题判据与语义审阅边界；工作区独立 expected 不由运行结果生成；发布走已构建 plain Node；升 pin 后候选兼容信息验证成功才发布，并要求流程复核证据。
5. **生命周期基础**：仅修已证实的 client CSS 注入未 dispose；不改样式设计、角色内容或 vendor。

## Alternatives considered

- **重写 AGENTS / 迁移 Notes 全树 / 清空历史**：不采用。保留有效规则与决策记忆，只修入口触发、当前/历史标签和明确矛盾。
- **只写提醒或只补脚本**：都不够。MD 决定 agent 的阅读/执行路径；脚本只机械验证可判定的部分。
- **自动从 live workspace 刷 expected、关键词齐全即宣布语义全通过**：不采用，会把实际错误当基准或掩盖缺题。
- **将本仓更严格流程直接删掉并声称遵循 DSH**：不采用。先标明来源和适用范围，以 [一手研究](../research/2026-09-24-dsh-development-memory.md) 校正归因，不擅自取消用户选择。

## Acceptance criteria

- 三种任务走查可闭环：指定小修、无活动队列时继续、恢复未完成项。每种说明先读什么、何时停下问人、何时可实施、完成证据在哪。
- 新 agent 不将历史维护段、过期绿灯、归档记录当现在指令；Notes 是实施前输入与实施后证据，不仅收尾附件。
- 文档链接检查对真实错误 path/fragment 有反例；当前文档通过，新文档不漏扫，历史资产不为绿灯篡改。
- home 错误输入在运行前失败；入口探针缺题/串题/假原文/错误指令基线失败。
- oracle 反例覆盖文件缺失/多余/内容差异，至少一条独立编写的真实无 key 工作区变更链运行。
- 发布实际 tarball 安装、built 入口 smoke；sync 失败路径和 review 前置有反例，不执行真实升 pin。
- 不声称未跑的模型/浏览器/升级场景已认证；未闭合关键项不将本 Note 标为完成。
