# 2026-11-08 · SA/SQA 能力组织：按场景取用学科域（A+C）

状态：已交付（2026-11-08；用户裁定 A+C：单 skill 域路由 + 任务书声明域 + SA 五学科判定）
上游 = [SA/SQA 能力组织卡](../../_backlog/_archive/settled_issues/2026-11-07-sa-sqa-capability-organization.md)

## 决定

1. **SA 的 `systems-architecture` 顶部加「先判域」**：**固定五行**——软件 / 固件 / 电气 / 机械 / 系统测试，
   逐行写 `学科 | 在/不在 | 依据`，**不得改名、合并、替换、跳行**；产品细分或任务书给的额外域只能作
   **追加行**。依据必须可被反驳（任务书边界 / 元件清单 / 现场条件 / 产物用途），只写"不涉及"不算。
2. **两条边界 + 一类灰区**：纯软件（无物理执行器 / 无市电 / 无承力件）只用软件自己的判断——状态机、并发、
   契约、可观测性、迁移回滚，**不许硬凑**采样/供电/耐受包络；含物理件时电气与机械必须在，**不得以
   "不是我的专业"缺席**。**远程设备 / 云边协同 / 数据采集类**：判纯软件的前提是我方不交付采集件/网关/传感部件、
   也不对传感链负责；只要交付物含现场侧硬件、或我们定义传感器量程/供电/安装/防护，电气或机械至少一门判「在」。
3. **SQA 的 `vv-playbook` 顶部加「域审计」**：逐行核五行是否原样（改名/合并/替换/缺行 = 不通过）；
   排除要举证；**承接面**（需求/接口/验收判据）出现某域特征词却判「不在」→ 不通过；纯软件出现无依据的
   硬件条目 → 域审计不通过；「在」的域必须在 V&V 有验证项；结论写进 `sqa-review.md` 摘要并原样保留。
   域判定表「不在」一行的依据里作反证提到特征词（如"没有市电"）**不算**矛盾。
4. **上游声明 = VP-Eng 任务书**（住 `eng-teaming` 硬规则）：给 SA/SQA 的任务书必须写 ① 现场边界；
   ② 是否含物理执行器 / 市电 / 承力件（没有写"无"）；③ 产物用途（记录是否要举证）；并**原样带上固定五行**，
   让两侧用同一张表核对。**冲突以任务书边界为准**，SA 在依据里写明偏差，SQA 在评审里点名。
5. **边界**：不拆 skill（A）；`sa-sqa-quality-audit.mjs` 的 Q8–Q11 保持窄判据；**不改 `content/AGENTS.md`**
   （避免改注入面与 replay 新鲜度义务）；不新增角色。

## 输掉的方案

- **任务书划分优先（把「以任务书为准」写成合同）**：本轮复审中曾起草这条，理由是 v4 真跑用了任务书自己的五域拆分；
  复审判定为**未获批准的合同变更**（用户批的是固定五学科），已回退。可用形态是「五行固定 + 任务书额外域作追加行」，
  这既保留上游边界，也不让五个必答学科被替换掉。
- **B 拆域 skill（`software-*` / `hardware-electrical-*` / `mechanical-*`）**：选择本身要判断力，漏选/错选没有守卫；
  组合与挂载面变复杂。
- **只由任务书声明域（C-only）**：VP-Eng 判错会放大到两侧；纯软件仍没有「只用软件思考」的下游指令。
- **只 SA 自判**：没有上游边界，SA 自说自话，SQA 缺对照。
- **D 维持现状 + 窄判据**：BUG-034/035 的两条条件判据只覆盖「记录可举证 / 故障路径耐受」，
  纯软件场景仍无显式指令，跨域漏项靠运气。
- **把域判定塞进公司手册**：改 `content/AGENTS.md` 注入面 → 触发 replay 新鲜度义务与手册预算；
  任务书是每次动议的输入，住 `eng-teaming` 更轻、责任也更靠上游。
- **把 Q8–Q11 升级成可配置「域 → 必备判据」表**：会造第二套判据系统，与 `/req check` 抢 owner。

## 剩余风险

- 单轮样本；域判定的**依据质量**仍由人判断，探针只判「五行在不在、方向对不对、有没有裁决」。
- 含物理件方向（EE/ME 判「在」）本轮未真跑；既有电气场景由 `sa-sqa-delegation-probe.mjs` 承担（本轮未跑）。
- 云边/远程设备灰区规则已写进 skill，但没有这类产品的真跑样本。
- 本轮把「系统测试」判成「在（验证活动 / 过程域）」——这是被测应用对五行的解释；探针只核行名与判词，
  不评价该解释是否合理（那是人读）。
- 探针的 live 模式本轮首次在「模型续写既有动议」的路径上跑绿；R7 依赖会话日志 zstd（与既有探针同款）。
