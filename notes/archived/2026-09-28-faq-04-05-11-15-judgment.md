## 04/05 · 根入口文档（静态设计 + 运行时消费）

**立即借（已落地）**：① 常驻注入面纳入行预算——公司手册（186 行 ≈ 16.4KB × 每个成员会话注入）是最大
常驻面却无预算 ⇒ 进 `DOC_LINE_BUDGETS`（195）同享棘轮；② pack README 补「已知限制」段（FAQ 04 的
package README tier：合同 + Model Experience + Known Limitations）+ dev-loop §12 收尾同 diff 更新半句；
③ 「改手册对进行中会话不生效」（触达驱动注入、无 watcher）进运维 runbook 故障表一行；
④ skill frontmatter `description` = 常驻注入面（catalog 只给 name+description）⇒ role-content-plan
加「每条必含一句何时用」约定；⑤ maxBytes 两端核对——overlay 未显式配 ⇒ dsh 默认 65,536B，
基线（手册 16.4KB + CHARTER 5–9KB + persona）≈ 26–28KB 够用，结论写进 pack README 已知限制。

**有压力再借**：⑥ 重文档顶部加「前提 + 不做什么」自述（index 地图已承担排序；fresh-agent 实测迷路再加）；
⑦ 手册「不做什么」拒载审查（共享共识 vs 岗位细节，岗位细节挪 CHARTER/templates；下轮手册迭代顺手做）；
⑧ 触达驱动 nested 注入承载 CHARTER（`kb/<role>/AGENTS.md` symlink ×5 + symlink 门禁扩面 + smoke 场景）
——改变每会话 token 成本与注入形状，先在一场排练实测收益再定。

**不借**：文档内代码可执行性门禁（shell/yaml 无 schema、假阳性高）；compaction/token-meter/digest
去重（DSH 原生，插件仓无文档层可动手面）。

## 11 · 原生开发环（窄证据切片闭环）

**立即借（已落地）**：① 整片回滚常态化——被证伪的已落地切片五件套同退、修正另起新条目（dev-loop §12）；
② 「空气规则」处置——agent 推断出的未成文规则必须 gate/Note/显式作废三选一，规则不留空气（dev-loop §12 复盘一问）。

**有压力再借**：③ 闭环遵守率历史量化（git 历史抽点数「五件套同现率」，对外展示体系成熟度前跑一次，
research 卡一次性、结论入卡即迁 archived）；④ change-scope 三态共享事实（committed/staged/untracked
分层 diff 脚本；REVIEW 实际跑出「范围看错」事故再建）。

**不借**：coverage gate 的「删除解释权」（persona/skill 文本对行覆盖率无意义，preset 面完成定义 =
preset-smoke 真挂载）。

## 15 · loop 工程 vs SDD（执行循环 vs 取题/判断层）

**立即借（已落地）**：① objective 引用条目/授权原文、扩围即回授权（dev-loop §0.5 goal 写法补一句）；
② 宣布完成前对照条目原文过需求/体验验收——机器绿灯只证机制面（dev-loop §12）；
③ 门禁升格判据 = 该具体错误本仓复发过 + 可机械判定 + 负例已证；语义要求不做成 gate（dev-loop §9）。

**有压力再借**：④ 控制点自效度量（催问次数/擅自扩围/返工原因；新体系跑 2–3 笔攒基线后再量）；
⑤ 跨仓总览只放指针（多仓需求出现时建「只指向各仓工作来源」索引，绝不复制第二份进度）。

**不借**：统一流程/门禁向其他仓推广——每条门禁绑定本仓错误画像，移植即仪式。
