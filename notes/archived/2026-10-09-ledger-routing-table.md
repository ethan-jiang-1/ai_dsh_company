# 决策台账降级为纯路由表：D 台账是 D34 未清完的第三本账

状态：已消化（2026-10-09；用户令「能修的就修，能补的就补」——本轮 = 第二遍深挖 gap 修复轮，本条 = 深挖发现 N2；判据沿用 D34 对 intents.md 的同一套，不是新立法）。

## 问题

`docs/index.md` §决策台账是一张手写表：33 行、8799 字符，最长行 644 字符（D35），而它指向的 Note 只有 4061 字符——**台账行本身就是正文，不是指针**。

三个可测的病灶：

1. **16 行没有任何可解析的家**（D1–D17）。它们的「依据/出处」格写的是 `architecture §2`、`FAQ 13 决策 2` 这类**非文件、不可解析**的引用，或干脆只指向 `docs/design/`（而那份文件自认是「动工前的设计决策记录」）。**这些决定的唯一住处就是这张表本身。**
2. **胖行病史与 intents.md 同款**。D34 退役 intents.md 的三条理由之一原文是「膨胀病史三次（40.5KB 胖行 / 96 行超窗 / 61 行触限）」——台账 D31–D35 五行合计 2776 字符，单行 500+ 字符已成常态。
3. **违反上游 no-index 教义**。vendor `notes/README.md`：「Do not add a centralized `INDEX.md`; the lifecycle/class tree **is** the working inventory.」一张手写 D 号总表正是 no-index 教义要防的东西，而它当前**没有任何门禁**约束形状。

`docs/index.md:52` 当时已经自认「D 号用于追溯，不表示所有旧句仍是当前指令」——**但一个自称不算权威的东西，却是 16 个决定唯一的住处**，这不是措辞能解决的，是结构问题。

## 决定

台账降级为**纯路由表**：每行 = `D 号 | 一句话 | 决定的家`，「家」格必须是可解析的链接。

- D1–D17 的家指向各自最早的决定 Note（Grep 核对过：D10→`2026-09-21-docs-layering`、D11→`2026-09-21-vertical-rounds`、D12→`2026-09-22-r1-deploy-findings`、D14→`2026-09-22-wochen-naming`、D15→`2026-09-22-agent-workflow-community-practice` 均已存在并有 `## 决定` 节）；仍在 `docs/design/` 无主的（D1–D9）暂指该设计文档——**它们该不该迁 Note 是 N1 的范围，本条不夹带**。
- 正文（理由、输掉的方案、验证证据）归各自 Note；本表不复述。
- 已退役的决定**保留行**，标注「历史」并注明去向——编号不重用、不删行（与 git 留史一致）。
- 历史适用范围从原第 52 行那段散文压进各行「历史」标注（原来 7 个 D 号的适用范围挤在一段里，读某一行时看不到）。

## 输掉的方案

- **整表退役**（照抄 D34 对 intents.md 的处置）：否决。台账与 intents.md 有一处**关键差异**——intents 的内容「100% 派生自 Note 状态行」，**删掉零信息损失**；而台账 16 行无家，直接删 = 决定失去唯一记录。先补家（本条），再谈退役。
- **只加行预算、不加路由门禁**：否决。intents.md 就是「有行预算、仍长成 40.5KB」的先例——行预算管长度，管不住「把正文搬进表格」这个动作本身。必须卡「每行必须带可解析的家」。
- **给 D 号做自动生成**：否决。D 号是人工授予的追溯编号（授权链的一部分），生成器会把它变成派生索引，正是 no-index 教义要防的。
- **把 16 个无家决定就地新建 16 份 Note**：否决。多数是早期机制选择（D1–D9），已被 `docs/design/` 与代码承载；凭空补 16 份 Note 是**造历史**，比留指针更坏。指向现有设计文档是诚实的位置。

## 验收

- `pnpm verify` 新增 `ledger-routing ×N` PASS 行；N ≥ 20。
- **红/绿四步**（每条都实跑、还原即绿）：
  1. 把任一行「一句话」写到 >100 字符 → `ledger-routing` 红（点名「第 N 行（M 字符）」）→ 还原 → 绿。
  2. 把任一行「家」格的链接换成纯文字（无可解析目标）→ 红（「第 N 行」）→ 还原 → 绿。
  3. **删表头行** `| # | 一句话 | 决定的家 |` → 红（「找不到台账表头」）→ 还原 → 绿。
  4. 把某行加成**四列** → 红（「第 N 行（4 列）」）→ 还原 → 绿。
- `docs/index.md` 行预算：台账缩短后总行数 148→147，棘轮随之下调。
- 每条 `ledger-routing` 报的行号可复现：实施者不看对话，改一行即可复现红。

**本门禁首版有假守卫，红 C 实证后修**：首版只查「解析到的行数 ≥ 20」——数据行正则与表头无关，
删掉表头照样解析出 34 行、门禁全绿。**红 C 第一次跑没有变红**，才发现 `LEDGER_MIN_ROWS` 从未
起过作用。改为「表头在场（形状锚）+ 表头下一行是三列分隔行 + 数据行恰三列」后才真正挡住。
这正是「每个门禁必须实跑负例」的价值：没有红 C，这道门会带着一个永假的分支上线。
