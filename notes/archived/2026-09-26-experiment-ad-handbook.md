## 共同准备（约 15 分钟）

1. `cd /Users/bowhead/ai_dsh_company && source dev/env.sh`
2. `CI=true pnpm dsh web -- --port 3083 --no-open`（端口被占就换/`--port 0`；横幅给带 token 的 URL）
3. **三个浏览器 profile**（或三台机器的浏览器）各自打开同一 URL；
   **每人先连工作区**：Choose workspace → **必须点 `Edit path`** → 粘
   `/Users/bowhead/ai_dsh_company/company-workspace` → Open（漏这步会以为"没有会话"）。
4. ⚠ **开每扇门必须改 preset**（新建会话默认 = `ceo`，已实测踩坑：第二扇门开成了第三扇 CEO 门）。

## 实验 A · 冷启动可发现性（测"话题怎么被各自发现"）

**两轮对照**：
- **第 1 轮（不通报）**：甲（CEO 门）起一个真动议（开场白模板 = `docs/demo.md` 场景 F），落任务书
  `deliverables/<slug>/drafts/ceo.md`，然后**不告诉任何人**。乙（CFO 门）丙（COO 门）各自
  开自己的门、只做一件事：**找"有没有轮到我的活"**（凭直觉找，找 5 分钟找不到就报"没找到"）。
- **第 2 轮（口头通报）**：同上，但甲落完任务书后**当面说一句**"CEO 派了 `<slug>`，你看一下"。

**逐人记录**（每人一行）：

| 人 | 轮次 | 首次发现用时 | 找到了吗 | 能说出下一步吗 | preset 开对了吗 | 离台 5 分钟回来还能接上吗 |
|---|---|---|---|---|---|---|
| 乙 | 1 / 2 | | | | | |
| 丙 | 1 / 2 | | | | | |

**判据（评审）**：任何关键审批、取消或截止事项不能因为"扫盘未触发"而静默遗漏；
若用户把"列表看不到"理解成"没有权限"，路径分组方案不能进入 demo。

## 实验 D · 门的心智模型（测"哪扇门是我的"会不会被搞混）

四种形态各试 **5 分钟**，每换一种记录一行：
1. 普通共享 workspace（现状：三扇门全在一个列表里）；
2. 路径别名（`dev/homes/bob/company-workspace -> 真盘`，门用别名路径开——**已知它不会隔离侧栏**，
   看人会不会误以为隔离了）；
3. 不同浏览器 profile（每 profile 只开自己那扇门）；
4. 独立 `$DSH_HOME`（每人一个 home、各起各的服务——这个要多服务，做不了就跳过并注明）。

**每次换形态，观察四面**（评审 §五 D）：Web 侧栏怎么分组｜会话日志落在哪个 bucket｜
实际写入落没落到真盘｜`authorship-audit` / `deliverables-check` 能不能扫到。

**逐形态记录**：

| 形态 | 侧栏分组 | 日志 bucket | 写入落真盘？ | 审计能扫到？ | 人说出"哪扇门是我的"用了几秒 | 有没有"看不到=没权限"式误解 |
|---|---|---|---|---|---|---|
| 共享 workspace | | | | | | |
| 路径别名 | | | | | | |
| 多 profile | | | | | | |
| 多 home | | | | | | |

**判据（评审）**：任何方案若让人误以为"看不到 = 没权限""同一真盘 = 个人私有""卡在哪扇门 = 谁拥有授权"，
就只能作内部实验，不作为多人 UX 合同。
