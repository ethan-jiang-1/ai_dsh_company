# 2026-09-26 · 问询节流：别把人问烦

状态：已交付（2026-09-26 用户批准立项；规则落公司手册「人机接口」节）

## 问题

UX 实验场一（`renewal-x-2026`，日志 `session-306dafdf` seq 97/98/103/104）：

- seq 97 一张卡 **4 问**（竞品补料 / 续约意愿 / 礼品规矩缺口 / 数字澄清）→ seq 98 人**全答**
  （耗时 1 分 45 秒，配合良好）；
- seq 103 CEO **紧接着第二轮追问同一批内容** → seq 104 人的第三条自由文本：
  **「哎哟，别烦我了，你随便找人吧」**。

机制上四类拉人点全部命中（实验轮验收通过），**体验上是失败的**：人从"配合"转成"别烦我"。
同一轮里另两条负向答复（「暂时没有」/「判断不出来」）指向同一成因——**不是没料，是问法让人不想给**。

## 采用方案（规则，落手册）

三原则 + 依据，落 `company-workspace/AGENTS.md` §人机接口「问询节流」：

1. **同批内容不许追问**（首要）：人已表态（如选「现在给」）而内容没到 ⇒ 按缺料出稿、把「未落实」
   写进未决项，**不许紧接着再问一遍**；
2. **一张卡只放同一性质的决定**：补料 / 建议 / 规矩缺口 / 数字澄清**不混卡**——混问必逼出追问；
3. **非阻塞项不拦人**：能按显式默认假设继续的先继续（与「不在场分档」同一精神），
   只有阻塞项（审批 / 裁决）才值得把人叫来。

## 输掉的方案

- **机制面节流**（client 侧限制每卡问题数 / 合并追问）：属 client 增强，本轮只有一次追问事件、
  无独立需求证据，且手册层零成本；**留案**——触发条件 = 规矩立了仍复犯（同类第二次出现）。
- **硬性"每场动议最多问 N 次"**：过于机械，阻塞项多时会把该问的也压掉；输给"按性质分"。
- **不改、只登记**：同批追问已实证把人问烦，且这正是"人被拉进来"的核心体验面——不立规矩
  等于默认可复犯。

## 后果 / 验证

- 后果：问询变少但更准；缺料场景走"带假设继续"。
- 已执行：`handbook-smoke` ALL PASS（手册注入）；`pnpm verify` ALL PASS；`pnpm test` 190/190。
- **未验证（行为面）**：规矩是否真管住"追问"要下一场真动议实测——**文案管不住行为有先例**
  （journal 缺席：skill 硬闸门语气实测未管住）。管不住即按「输掉的方案」第一条转机制面并带新证据。
