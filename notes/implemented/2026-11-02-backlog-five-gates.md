## 问题

三件事同时不成立：

1. **状态说不出「已就绪」**。issue 轨活跃值只有 `推敲中` / `等人拍板`，于是「结论 = 做、门票写好、等着实施」只能靠状态行的 `毕业：做` 表达；两张活卡都是这个形状，一张已落地、一张落地中途，frontmatter 看不出来。
2. **门票是半句空话**。门牌写「两张门票由格式承载，门禁查形状」，但 `tools/lib/backlog-liveness.mjs` 的注释自己写着「修复就绪卡缺 `## 已修判定` → 不报警（如实不查）」——`## 验收标准` / `## 已修判定` 全靠自觉。
3. **去向是散文**。D47 的 `rfc｜note｜implementation｜pending｜none` 只活在正文和一条正则里，卡顶没有可枚举的值，机器不知道卡该去哪；研究题名页则完全没有状态。

## 决定

- **五道门 = 共享词汇，三轨保留自己的状态名**（研究 → 定性 → 落地 → 审 → 归档）。统一状态名会丢掉 `修复就绪` 的授权边界，所以只借门、不借拼写。
- **issue 加 `待落地`**：结论 = 做 + 非空 `## 验收标准` + `去向 ∈ rfc｜note｜implementation`。它**不是授权**，也不是任务源（[dev-loop §0.5](../../docs/guides/dev-loop.md) 同步一句）。
- **研究题名页加 `status: 调研中｜已定性` + `opened`**；`已定性` 必须有非空 `> 结论：`；材料不设 status（材料是证据，不是工作项）。
- **去向 = 封闭集 6 值**（新增 `rejected`，对接 `notes/rejected/`）；写卡顶 `> **结论/去向**：<值> — <落点>`，`待落地` 时落点用 inline code，关闭时换 live 链接（否则 `md-links` 红）。
- **审查三层**：机械不跳；语义审与 Note 必要性同门槛；用户验收按重要性。记录写状态行 `审查：agent｜用户｜跳过 — 理由`，跳过不许写成 verified。
- **门禁六条**（`backlog-liveness`）：`待落地` 门票 + 去向 + 毕业头；`修复就绪` / `修复已落地` 门票；归档做卡的去向值与审查记录（`opened ≥ 2026-11-03`）；题名页状态与结论；材料无 status；状态行镜像与 `毕业：` 封闭头（原有）。
- **根 `AGENTS.md` 换一条流水线行**（83/84 → 83/84，净零）：原「任务源」句与 notes 段合并，写法是门 + 交接点，不是状态机。
- **改口**：2026-10-12 按用户裁定「先格式」延后的「验收在场」检查族（`修复就绪` 必带 `## 已修判定`）本轮开启——当时的重提条件就是「缺验收卡什么都没红」。范围只到两张门票 + 去向/审查，不回溯 `推敲中` 卡。

## 输掉的方案

- **`待审` 状态**：与 `等人拍板` 重叠，模糊「谁能移动」；审查是守卫，不是位置。
- **新增 frontmatter `request:` 字段**：D47 已定记录家 = 卡顶 `结论/去向` 块，加字段会造第三处真相。
- **统一三轨状态名**：丢掉 `修复就绪` 的授权边界。
- **研究材料加 status**：一份证据一个状态 = 第二个真相源。
- **题名页 `> 状态：` 双写**：frontmatter 就在同页顶部，第二处没有读者。
