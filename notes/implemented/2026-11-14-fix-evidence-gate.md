# 2026-11-14 · 缺陷修复的证据门：修 = 改动面 + 红→绿 + 可对账提交

状态：implemented（2026-11-14 落地）

上游 = 用户 2026-11-14：「红→绿证据非常重要，一定要内化到流程里头——发生过这种事：让你批修一批 bug，你直接把状态改了之后移动了卡，但 repo 什么都没变……修必须有流程，而且必须有红绿证据，否则就是扯淡」，并要求把约定写进根 `AGENTS.md` 或 `_backlog/AGENTS.md`。
同一类病的上一次 = [落地语义](2026-11-13-landing-semantics.md)（“落地 = 可验证变更 + 实跑证据”，当时只覆盖问题轨的 `## 落地证据`）。

## 决定

**缺陷轨沿用「落地语义」的同一判据，并把它做成机械门**：归档的 `status: 已修` 卡（`opened` ≥ 2026-11-14）
必须有非空 `## 修复证据`，四行缺一即 `pnpm verify` 红（门禁 = `checks/gates/fix-evidence.mjs`）：

1. `- 改动面：` 至少一个反引号路径；真实存在，且不落在 `_backlog/`、`notes/`、`vendor/`——证据必须指向
   系统面（代码/门禁/测试/文档/内容），只改卡与 Note 不算修复。
2. `- 红：` / `- 绿：` 非空：还原什么 → 哪条断言红；接回什么 → 哪条绿。
3. `- 提交：commit <sha>`：sha 存在、提交日期 ≥ `opened`、且该提交的 changed files 与改动面相交
   （文件相等或在目录下）——“卡上说的改动面”必须真在那次提交里出现过。

**入口三处一句 + 一处细则**（一处事实一个家）：根 `AGENTS.md` 的“落地”句加缺陷轨同判据与指针；
`_backlog/AGENTS.md` 的「落地与走流程」和 `修复已落地` 行加出口物；细则住章程「缺陷的通道」；
`bugs/README` 的收口要求与模板给字段形状。写路径 = 先落代码提交（拿到 sha）→ 再归档补 `## 修复证据`。

**为什么是「提交对账」而不是只查卡面文字**：卡面可以写得像真的；把“改动面 vs 证据提交”做成交集判定，
才把“写清楚了”升级成“对得上账”。这同时挡住事故原形：只有状态翻转与 `git mv` 的提交里，没有任何
改动面路径可被对到。

## 输掉的方案

- **只写散文/只在门牌加一句**：本轮之前根 AGENTS.md 已有“落地 = 可验证变更 + 实跑证据”，事故照样发生；
  用户明确要求机械化，散文只能当入口提示。
- **复用 `guard-red-record`**：它只查「spec 标题声称守卫某事故 → 必须有负例留证行」，不查归档卡、不查
  提交、也不区分事故卡是否真的被修；把它扩成两件事会让判据与报错都失焦。
- **检查“归档提交是否改了非 `_backlog/` 文件”**：会误伤合法的文档/索引收口提交（修复常是多提交，
  归档提交只搬卡）；也和 [落地语义](2026-11-13-landing-semantics.md) 已否决的“提交黑名单”同病。
- **让门禁真执行红/绿命令**：等于在 `verify` 里跑全量测试，成本不可接受；执行归 `pnpm test` 与 pre-push，
  本门只判“是否存在且可对账”。
- **要求 PR / CI artifact**：本仓没有 PR 门禁；证据必须落在仓内、可离线复算。
- **用 `留痕：commit <sha>` 替代 `- 提交：`**：`留痕` 是“决定留痕”的裁决（Note/commit/none），语义不同；
  且多数卡用 Note。证据提交必须独立成字段，才能与改动面对账。

## 未覆盖轴

- **证据强度只到“对账”**：一次提交改了目录里另一个无关文件也能过交集判定；本门证明“有可对账的系统面
  改动”，不证明“改动就是正确修复”。正确性仍归 spec 与语义审。
- **浅克隆**：`git rev-parse --is-shallow-repository` 为 true 且 sha 不可达时跳过提交解析，PASS 行点名
  跳过数；完整历史是判据前提（本地与 pre-push 都是完整历史）。
- **存量祖父豁免**：`opened` < 2026-11-14 的已修卡不追补；新写从严（与落地语义同款前向生效）。
- **多提交修复只对一笔**：卡的 `- 提交：` 只写主证据提交；其余提交不逐一对账。
- **文档-only 修复**：`docs/` 视为系统面（允许），因此“只改文档”的合法修复可以过门——判据不区分
  “内容修复”与“文档修复”，只挡“只有卡与 Note”。
