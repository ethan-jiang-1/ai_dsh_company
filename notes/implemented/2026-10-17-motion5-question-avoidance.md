# 第五场尝试（2026-10-17）：问询规避设计成立，但观察窗存活成了新阻塞

状态：implemented（授权 = 用户 2026-10-16「再来一场?…遇到问题自己解决」的连续轮次；阻塞卡 = [BUG-021](../../_backlog/_archive/fixed_bugs/BUG-021-ask-user-question-no-scripted-answer-path.md)；commit = 见本 Note 同轮）

## 这轮想解决什么

第四场（`hefeng-recon`）卡在 `ask_user_question` 上、两场动议因问询掉线丢失（见 BUG-021）。所以本轮**改设计而不是硬撞**：在动议里**明确禁止问人**——

> 「缺料**不要问我任何问题**——我替客户答不了。把『要什么、给到哪』写成**补料清单**；依赖缺料的任务派活行写 `待补料`；**用 schedule 工具立一条跟进**，title 含 `待补料·lingang-recon·T<号>`。」

即：把「缺料」从**问询**转成**工作面上的阻塞 + 机器可查锚**。这样即使 HITL 通道不通，动议也能自己走完（这正是手册设计的本意）。

## 实测结果（三场，两个正面结论 + 一个新阻塞）

| 尝试 | 结局 | 关键观测 |
|---|---|---|
| ① `session-ecdd92d3`（临港冷链预审） | 断在 105 行、`turn/end` = **`{"kind":"error","error":{"message":"DeepSeek Messages transport failed"}}`** | **`ask_user_question` = 0**（对照第四场是 1）⇒ **问询规避设计成立** |
| ② `session-f702421c`（重跑，点名锚格式） | 断在 49 行、无 `turn/end`（观察窗进程先退） | 同样 `ask_user_question` = 0；「待补料」字样出现 175 次 ⇒ 它在按纪律走，只是没跑完 |
| ③ 第三次起窗（脱离式后台） | 打印横幅后进程即退（`curl` → HTTP 000） | 不是我的驱动问题，是**进程存活问题** |

**两个正面结论**：
1. **「不问人」的设计有效**——两场都把缺料处理成清单/`待补料` 语义，一次没调 `ask_user_question`。这说明第四场的问询**不是必然**，而是「题目允许它问」时它才会问。**手册的纪律面（待补料 + 锚）和 HITL 面（ask）是两条路，前者在无人值守下可走通。**
2. **`待补料` 语义确实被使用**（175 次），只是**还没走到 `schedule_create`**——因为两场都在中途被基础设施打断。

**一个新阻塞（本轮撞出来的）**：`pnpm dsh web` 进程**反复无输出退出**（两次 `exit 0`、一次打印横幅后即退），会话因此停在半途无 `turn/end`。这与第四场的 `MALFORMED_RESPONSE`、本轮的 `transport failed` 是同一族：**驱动侧基础设施在长会话里不稳定**。

## 所以「待补料闭环」这一格到底压到没有

**压到一半，如实记**：
- ✅ 「缺料不假装完成 + 列清单 + 用 `待补料` 语义」——**已压到**（第四场与第五场都实测到）；
- ❌ 「立 `待补料·<slug>·<T号>` 锚 → 补料落盘 → 复算 → 状态回待办 → 收口」——**未压到**（三次尝试都在跑到 `schedule_create` 之前被基础设施打断）。

**为什么不再重试**：连续三次同类中断（`MALFORMED_RESPONSE` / `transport failed` / 进程静默退出）已构成**复发证据**，按 `dev-loop §9` 的口径该做的是**修基础设施或立卡**，而不是继续用同一个方法碰运气。再起窗只是重复消耗真 API 钱。

## 结论与去向

1. **BUG-021 的严重级要上调考虑**：它不只挡「问询应答」，本轮显示它旁边还有**同一族的驱动不稳定**（进程退出、传输失败）。三场合计**四场动议中有三场没跑完**（`hefeng-recon`、`ecdd92d3`、`f702421c`），只有前三场（诊断/取证/签字沙盘）完整收口。
2. **本轮的正面产出**：证明「无人值守下用 `待补料` 语义替代问询」是**可行设计**——这给了 BUG-021 一条**绕过**路径（不改 host 也能让动议走完），已写进卡的修法 C 旁边。
3. **未做的**：`lingang-recon` 的两场残留（`2026-10-17-lingang-recon/` 半成品）**不收口、不伪造**——按第四场的同一口径留作未收口态，判据会如实报 `meta-result-pending`。
