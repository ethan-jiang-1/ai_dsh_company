# 2026-09-24 · 呈现与叙事：经营仪表 + Demo 场景 D（支柱 2，交错位）

状态：implemented（2026-09-25 凌晨交付——切片一经营仪表落地 + 切片二叙事随新动议条目交付 + 切片三触发型注册；实况见文末）

## 问题

主轴 = 自用 + 演示并重：经营深度为主线，呈现随动议素材成熟而开。现有呈现面（公司视图四面板 /
在场 / 用量）回答"这会儿谁在干什么"，回答不了"**这家公司累计干了什么、花了多少、产出什么**"——
动议史只有翻 snapshots 与 deliverables 才能拼出来。

## 方案（三个切片，按素材成熟度依次开）

1. **经营仪表**：动议台账——每场动议的日期 / 主题 / 参与角色 / 墙钟 / token 成本 / 交付物 / 结论
   摘要。数据源 = 用量页签同源数据 + session 日志 + deliverables 三态判据面（实施时核实最短
   路径）；落点 = 公司视图新面板或右栏页签（实施时按 [design/ui-demo §5](../../docs/design/ui-demo.md)
   命名表与停靠 pane 上限 2 的平台事实定）。
2. **Demo 场景 D**：一段可重放的完整叙事，素材首选新动议类型（季度会或事件复盘）；配合 replay
   harness 归档成"可重复放映"场景（判据档选择按 §9.1）。
3. **视觉打磨二期**：走查触发型——前两条目跑完后的用户走查发现新问题才开；本 RFC 只登记触发
   条件，不开空头队列行。

## 输掉的方案

- **仪表并入用量页签**：用量是会话视角（token/请求），动议是业务视角（slug/角色/交付物）——
  语义不同家；输给"一个面板答一个问题"。
- **场景 D 用既有 r2 录制**：r2 是评估型动议，叙事张力弱于事件/季度形态；素材成熟后重录更值。
- **消息级动态流一并做**：缺上游 seam，住搁置池（基座轮复活复查），不进本条目。

## 验收

- 切片 1：数据可从日志机械重建（keyless 读模型单测）+ client-load-smoke 零挂载失败 + 覆盖全部
  已归档动议（现有 7 场 + 新动议）。
- 切片 2：场景归档 + replay-smoke 判据绿（presence 档或全量零 diff，按 §9.1）。
- 切片 3：触发时另开条目。

## 风险

成本数据口径（session 日志的 token 记录形状未经核实）——切片 1 开工先做数据源窄核实，形状不
成立则该列降级为"墙钟 + 参与角色"先行，成本列等用量同源核实后补。


## 实施实况（2026-09-25 凌晨）

**切片一 · 经营仪表【已实施】**：台账唯一事实家 = `company-workspace/kb/motion-ledger.md`（10 场动议：
日期/类型/参与/墙钟/成品/一句话结论；**维护规矩挂进当轮收敛**——与 CHARTER 历史纪要同一动作追加一行，
不另起流程）。交付 = `src/lib/ledger.ts`（纯解析，表头不符返回空防渲染错行）+ `LedgerTab`（页签
`company-ledger`，workspaceFiles 数据面）+ 统计头（共 N 场 / 成品 / 未记）。验收 = keyless 4/4（**fixture
即生产文件**——直接读真台账防解析器与事实家漂移，全套 178）+ client-load + **真数据走查 PASS**
（10/10 动议渲染、截图 ledger-panel.png）。**实施教训**：`workspaceFiles.read` 的 `limit` 是**行数**
且有 maxLines 上限（8000 超限挂起——首版面板永远「读取中」；240 行覆盖短表）。

**切片二 · Demo 场景 D【随新动议条目交付】**：demo.md 场景 D（季度经营会 241s）/ 场景 E（事件复盘
100s）分镜 + 快照归档（snapshots/{q3-business-review, emergency-x-incident-review}）已由前一条目
落盘——本 RFC 立项时的"素材首选新动议类型"即此。**登记缺口（触发型）**：把 q3-business-review
做成 replay-smoke 可断言场景（照 r3-delegation 准备程序：场景组合 + 归一化 + 判据档选择）——材料
齐备，需要时再做，不空转。

**切片三 · 视觉打磨二期【触发型注册】**：触发条件 = 用户对驾驶舱七页签（需要你/注意力/看板/依赖图/
在场/用量/任务板/台账/培养）走查发现新问题——发现问题即另开条目，不开空头条目。

**落点修正**：本 RFC 原设想"仪表落公司视图新面板或右栏页签"——实际落**右栏页签**（与七页签同轨、
可浮出）；RFC 中"成本列"按其风险预案降级（session 日志 token 形状未核实——台账先墙钟 + 参与，
成本列等用量同源核实后补，列位已留）。
