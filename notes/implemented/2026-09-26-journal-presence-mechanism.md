# 2026-09-26 · journal 缺席机制：文案已证无效，需要可检测 + 换执行者

状态：已交付（2026-09-26 用户批 A+B；来源 = ROADMAP §磨清单唯一在册项；实况见文末）

## 问题

「收工留痕」是硬闸门，但**行为上管不住**：

- 打磨轮（2026-09-25）给五份 skill 的收工步加了硬闸门语气（"没写 journal = 任务未完成"），
  排练实测**红证**：draft 按工作流正常产出，journal 步照跳（8→8 篇）。
- 更早的事故同款：`emergency-x-incident-review` 场 VP-Eng / COO 未留 journal（W8 缺口，事后补记）；
  新动议×2 场又记一次"journal 缺口二犯"。
- 结论（打磨轮已裁）：**这是行为问题不是文档问题**，按"文案不够、需机制"重挂磨清单。

**缺的机制是什么**：现在既没有**检测**（缺席无人知道，直到下次复盘翻 journal 才发现），
也没有**换执行者**的检查（缺席者自己不会报自己缺席）。

## 采用方案（A+B 已交付；C 归上游留案）

### A · 仓库侧审计脚本 `scripts/journal-audit.mjs`（deliverables-check 家族）**已交付**
从会话日志（`$DSH_HOME/sessions/...`）读 `team/task` 事件，对每个 `status = completed` 的任务，
要求其 **owner 角色**的 `kb/<role>/journal/` 里有当轮条目（按 slug 或时间窗匹配）；
输出"哪场 / 哪个角色 / 哪个任务缺 journal"。性质 = **事后检测**，与 `deliverables-check.mjs` 同族
（缺 DSH_HOME 自拒、只读、keyless、可复核）。
- 价值：缺席**从"没人知道"变成"可复核的违规"**；轮末收敛时顺手跑一次。
- 局限：不拦运行时（跑完才发现）。

### B · CEO 定稿盘点步加"成员 journal 在场盘点"（**换执行者**，不是加自我提醒）**已交付**
`chairing-staff-meeting` 第 5 步已有"定稿前盘点保留账"；同处加一条**逐角色点名 journal 是否在场**，
缺席者不进收口（CEO 让其补写后再合稿）。
- 价值：检查者从"缺席者自己"换成"CEO"——**文案但换了执行者**，与 A 的"只加一句自我提醒"不是一回事。
- 局限：仍是内容层约束，得靠真动议实测（与问询节流同性质）。

### C · 运行时拦截（任务完成的前置条件）**未做（留案）**
**核过 vendor**：`packages/guard/` 只有 `repeat-tool-reminder`（advisory 循环卫生）与
`timeout-policy`（协作超时），**没有"完成前置条件"类 seam**；要拦 `team_task_complete`
得改 vendor 或自造守卫 ⇒ **归上游 seam 提案**（提"工具完成前置条件"扩展点），本仓不自建（D13）。

## 输掉的方案

- **继续加文案**（再写狠一点）：已证无效（8→8 红证）。
- **自建调度器/记忆服务**：D13 不自造；journal 是角色的记忆载体，不是机器产物。
- **机器自动生成 journal**（从会话日志折出"纪要"）：丢"角色自己写的记忆"语义，且会把
  "角色没做收工"这件事**掩盖**成"系统帮他做了"——正好是我们要检测的东西。
- **把审计做成硬门禁进 `pnpm verify`**：verify 是结构门禁（不依赖会话日志），journal 审计依赖
  `$DSH_HOME` 真跑产物 ⇒ 归属"按面选跑的审计档"（同 deliverables-check），不进 verify。
- **留着噪声大的审计**：误报多了没人看，比没有更坏 ⇒ **误报率一高就收窄或砍掉**，不留形式主义门禁。

## 后果 / 验证

- **A 已交付并标定**（`scripts/journal-audit.mjs`，维护者按需跑、**不进 `pnpm verify`**——它依赖
  `$DSH_HOME` 真跑产物，同 deliverables-check 家族）：
  - 口径 = 一场动议里**出过活**（有 completed 任务）的角色，应在 `kb/<角色>/journal/` 留痕；
    三级置信度：**确认**（文件名含 slug，或正文含 slug 且 mtime 落在本场时间窗内）/
    **在场(已归档)**（轮末收敛把已闭轮 journal 归档进 `snapshots/`）/ **缺席**（违规）。
  - **标定过程中修掉四处真缺陷**（都记在脚本注释里）：① 只认 v4 日志 ⇒ 漏掉 09-25 前 26/30 场次；
    ② 任务字段嵌在 `data.task`（不是 `data` 顶层）；③ owner 是**成员 id**（`team/member` 映射，
    Lead 的 id = 会话 id）而非角色名；④ 正文命中不限时间 ⇒ 后一场引用前一场 slug 会误判成"前一场留了痕"。
    另加**格式检查**（2026-09-26 由 A 案真动议实测补入：那场 2/6 篇 journal 结尾换行不合规，
    而只有事后 md-newline 门禁抓得到 ⇒ 并进审计当场可见；带反证）、**规则生效日 cutoff**（早于 2026-09-24 的场次归"历史"不计判——拿今天的规矩判规则生效前的行为
    是假阳性）与**归档区查询**（否则每一场已收敛的动议都被误报缺席）。
  - **反证**（红→还原→绿）：把 `kb/cfo/journal/` 整个挪走 ⇒ `renewal-x-2026` 的 cfo 由「确认」翻
    **❌ 缺席**；还原 ⇒ 回「确认」。
  - **与仓库独立记录吻合**：`renewal-x-2026`（4 角色）与 `revenue-plan-2027`（5 角色）判 ✅；
    `emergency-x-incident-review` 判 **coo 缺席**——与该角色 CHARTER 里"当轮未留 journal（W8 同款缺口）"
    的既成记录一致；`q3-business-review` 两角色经归档区判定为「在场(已归档)」。
- **B 已交付并验过行为面**：CEO skill 收口步加"定稿前另盘点 journal 在场，缺席当场退回补写"。
  完成定义 = `preset-smoke` ALL PASS；**行为面探针 PASS**（排练档，真模型 ≈$0.05）：造"一个角色有
  journal、另一个没有"的收口场景，CEO 逐角色点名——vp-sales 在场、cfo 缺席 ⇒ 换执行者的检查真的在跑。
- `pnpm verify` / `pnpm test` 保持绿。
- **仍未验证**：真动议整场下的缺席率（B 的长期效果）；审计口径对"角色换了 journal 命名习惯"的鲁棒性。
