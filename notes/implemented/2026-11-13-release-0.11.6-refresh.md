# 2026-11-13 · 0.11.6 分发重打：从只读诊断到可发布字节

状态：implemented（2026-11-13；验证见下）

上游 = 用户 2026-11-13「弥补gap吧，setup一个goal 推动落地静默自主执行」+ 同轮只读诊断的结论（1 红：`_dist` 0.11.5 落后 8 个 `src/presets/content` commit；3 U：clean-profile 安装、真挂载、浏览器页）。

## 问题

- **发布字节过期且不可追溯**：`_dist/dsh-company-pack-0.11.5.tgz` 由 `50878cd` 的脏树生成（`release-manifest.json` 记 `dirty:true`、`checks.verify/test = not-run`），之后 8 个 commit 改了 pack 源码/预设/内容；两侧版本号同为 0.11.5，收件人无法用版本号区分。
- **发布验收本身有静默红**：`release --verify` 的最后一项 `present-catalog-smoke` 用 plain node import `src/**.ts`；`startup-watch.ts:104` 的 constructor 参数属性在 Node strip-only 模式触发 `ERR_UNSUPPORTED_TYPESCRIPT_SYNTAX`。0.11.5 的 manifest 没记录过 verify，这条红从未被当成发布阻塞。
- **首跑入口两套顺序**：`AGENTS.md` 命令表写 `setup → bundle:init` 且不带 `pnpm install`，与 bootstrap/CI 的 `install → bundle:init → setup` 相反。

## 决定

1. **patch bump 0.11.6 并重打**：8 个 commit 是修复（BUG-090..151 批次、数据安全面），按补丁版本发布；`_dist` 重新 build + pack，手册同 diff 重生成；重导后 `_dist` 只留当版 tarball。
2. **加载器修在证据面，不碰产品源码**：`release --verify` 的 `present-catalog-smoke` 命令加 `--import tsx/esm`（仓库源码面 loader，同 `workflow-contract-smoke` 先例），脚本头注写明原因。参数属性是 tsc 合法语法，构建产物不受影响；为迁就 plain node 去改产品源码是把证据面缺陷转嫁给产品。
3. **staged 哨兵同步 0.11.6**：`market-index.staged.json` 的 `version` 必须等于 package（`dev-product-parity` 门禁），`requiresPublish:true` 保留；READY 用 `--allow-pre-publish-index`（显式确认不托管），发布后删 staged 再跑 `pnpm market:hosted`。
4. **首跑顺序收敛**：`AGENTS.md` 命令表只留指向 [bootstrap](../../docs/guides/bootstrap.md) 的指针，顺序唯一家回 bootstrap。

## 输掉的方案

- **重打 0.11.5 不 bump**：同版本两套字节仍无法区分；8 个 commit 含写路径/状态根修复，不重打等于继续发旧行为。
- **删 `startup-watch.ts` 的参数属性**：让产品源码迁就 plain node 的 strip-only；参数属性合法，改它只为让检查跑通，层次错。
- **给 `present-catalog-smoke` 加自举 re-exec**：ESM 静态 import 先于任何顶层 guard 求值，guard 必须换启动器文件或全改动态 import；改动面大于收益。
- **让 `--verify` 跳过 `present-catalog-smoke`**：发布验收少一项 = 把静默红洗绿。
