# 2026-10-09 · 守卫负例门禁——把 prove-it-red 从散文升成 spec 的必交配方（guard-red-record）

状态：已消化（2026-10-09 实施完成；来源 = 用户令「按照你的推荐来做吧，Set up 一个 ongoing 的 goal
然后就把它推动落地」；与 N5/replay-scene-liveness 同族——都是"把只写在散文里的规则升成机械可判"）

## 触发：一次真的假绿（实测，不是推测）

`tests/company/deliverables.spec.ts` 的 **BUG-004 守卫**（让位行的机器可查面）声称守住
「持认判定 = 占位 ∧ ¬让位」。我把它弱化成子串匹配——**正是它自己声称要防的"措辞走样也认"失效**：

```js
// 真实现：首个非空行必须一字不差
const first = body.split('\n').find(line => line.trim() !== '')
return first !== undefined && first.trim() === PLACEHOLDER_YIELD_LINE
// 弱化版：只要正文里出现过这串字就算
return body.includes(PLACEHOLDER_YIELD_LINE)
```

**全套 355 项依然全绿。** 且弱化版能让矛盾同时成立：

```
body = '占位=认领，非出稿\n\n讨论：我本可以写 让位=认领撤销，非出稿 来放弃'
isPlaceholderClaim(body) === true   // 持认
isPlaceholderYield(body) === true   // 让位  ← 两者本该互斥（BUG-004 存在就是为了这个）
```

**为什么原来的用例抓不住**：那条用例的 fixture 正文写的是「（后文提了让位但首行未改写）」——
**不含让位行原文**，所以"首行相等"与"正文包含"两种实现**都返回 false**，验不出弱化。
一条 fixture 恰好绕开被守卫性质，守卫就是纸的。

## 决定

新增门禁 **`guard-red-record`**，规则三条（机械可判）：

1. **守卫声明** = 某个 `describe('…')` / `it('…')` 的**标题里带 `BUG-nnn`**。
   标题是"我在这里守一条具体不变量"的正式声明。
2. **事故必须可解析** = `BUG-nnn` 要对得到 `_backlog/_done/_fixed_bugs/BUG-nnn-*.md` 真卡
   （悬空编号 = 声称守一个不存在的过去 → 红）。
3. **每个声明必须有自己的负例留证** = 文件里有 `// 负例留证 YYYY-MM-DD：…BUG-nnn…`
   （**按编号对齐**——一篇 spec 守 N 个事故就要 N 条，不许一条笼统行糊过去）。

首版判据（关键词扫描 head -14 行）**被我自己否决**：`事故|回归|反馈|守卫` 这类词太糊，
36 个 spec 里 10 个命中，全是噪音。改用"标题里的可解析事故号"才有明确边界。

## 判据的边界（为什么是"标题"而不是"正文提到"）

**反例**：`tests/company/signoff-tool.spec.ts:34` 的注释提到 BUG-002，但它**不声称守卫 BUG-002**
——它是在解释"mock 为何要 no-op"（BUG-002 修复给 `apply` 加了 api-session 监听，
harness 只需让 `ctx.on` 不炸）。它测的是 `request_signoff`。
若判据放宽到"正文提到 BUG 号"，这篇 spec 会被迫交一条它挣不到的红配方 ⇒ **判据会说假话**。
⇒ 只有**标题**（describe/it 的名字）算声明。

## 修复了 BUG-004 的真实盲点（不只是补记录）

补的不是"一张纸"，是**一条原本抓不住弱化的用例**：

```js
it('让位行原文出现在正文但不在首个非空行 ⇒ 非让位（钉死「首行相等」，防子串实现）', async () => {
  const bodyBesideYieldLine = `占位=认领，非出稿\n\n讨论：我本可以写 ${PLACEHOLDER_YIELD_LINE} 来放弃`
  expect(bodyBesideYieldLine.includes(PLACEHOLDER_YIELD_LINE), 'fixture 必须真的含让位行原文…').toBe(true)
  expect(isPlaceholderYield(bodyBesideYieldLine)).toBe(false)
})
```

关键在第一条断言：**先验证 fixture 真的含让位行原文**——这正是老用例缺的性质。
加之前：弱化实现全绿；加之后：同一弱化 **1 failed**。

|---|---|---|

| BUG-003（deliverables） | 观察项 code 改成别的字面量（静默吞警告） | 1 failed |

独有的。所以本条不是"测试都是假的"，而是"**至少有一条守卫，没人知道它是纸的**"。

## 输掉的方案

- **要求全部 36 个 spec 都交红配方**：否决。多数是视图模型/纯函数断言，本来就没声称守事故，
  逼它们编一条 = 制造假证据。且用户推荐已定"只对声称守卫不变量者"。
- **判据放宽成"正文提到 BUG 号"**：否决，见上「判据的边界」——会把 signoff-tool 逼成假话。
- **建"变异测试 lane"自动发现纸守卫**：**本轮不做，但不是否决**。它才是能自动证伪"守卫是纸的"
  的机制（我本轮就是手工跑了 4 次变异才发现 BUG-004）。代价 = 变异算子 × 全量跑 ≈ 分钟级，
  与门禁秒级预算冲突 ⇒ 该做成**按需/定期的探针**，不是门禁。**留作下一层判断**。
- **只修 BUG-004 的盲点、不建门禁**：否决——那就回到"下次还得靠人手工跑变异才发现"。

## 不证明什么

门禁**不制造回归、不跑 vitest**，所以它**不证明**那条留证是真的（留证写了但内容是假的，
本门禁看不出来——那要人复现，本轮 4 条我逐条复现过）。它证明的是
**"声称守卫具体事故的 spec 必须交出可复现的红的配方"**，把"没人知道能不能红"
变成"红法写在守卫旁边，谁都能重跑"。
