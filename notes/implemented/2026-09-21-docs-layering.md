# 2026-09-21 · docs/ 按性质分层（决策 D10）

## 决定

docs/ 组织为五层：导航（index）/ 设计（design/，为什么）/ 计划（plans/，接下来）/
指南（guides/，怎么操作）/ 合同（顶层按主题，现在是什么——随阶段诞生，不预建空文件）。
architecture §7 阶段表迁出为 plans/roadmap.md。

## 输掉的方案

- **"初始化/"（按时间分层的目录）**——提案人：owner。否决理由：一份初始化文档要么始终为真
  （那它是当前文档，按主题归位），要么已失真（那它是历史，归 notes/ 或 git）。按时间分层
  必然长出"烂尾层"；DSH 自己的 docs/ 也按主题（subsystems/cookbook）不按时间。
  提案里真正的诉求（初始意图要有家）由 notes/intents.md + notes/proposed/ 承接。
- **纯平铺（维持现状）**——六份文档性质已混（设计/计划/指南），实现开始后新合同文档无归位
  规则，会重新缝缝补补。

## 需要验证什么

- 第一个新文档（预计 docs/profile.md，阶段 0 收尾）按"合同出生地图"落位是否自然。
- plans/roadmap.md 被"吞掉"的维护规则（验收→合同、决策→notes）第一场阶段收尾时走一遍。
