## 过程新发现（机制面）

1. **孤儿 web 握写句柄**：驱动脚本崩溃若不杀 web 子进程，孤儿继续持有会话写句柄 ⇒ 新 web 实例对
   同会话 prompt 被拒（`already owned by an active write handle`）。修 = 驱动脚本**顶层 try/finally
   必杀 web**（本轮起已固化）+ lsof 按会话文件找孤儿 kill。这解释了"同会话跨进程续写"的边界：
   **会话写权归属进程，不归属盘**。
2. CFO 拒签后 turn 自行收口（孤儿里完成）——审批 settle 与改写不依赖发起它的脚本存活。
3. 一次性脚本的低级错（漏 helper / 路径少段 / 残留行）三次断跑——**续写类脚本开工前先 `node --check`
   + 全局搜未定义符号**；分段驱动时每段独立可续（本场的三段续跑结构就是为此）。
