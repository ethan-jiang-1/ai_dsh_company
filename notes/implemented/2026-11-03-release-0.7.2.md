## 决定

1. **版本 = 0.7.2（patch）**。包源码面有用户可见行为变化（客户端错误落盘不再被 `dataBlocked` 挡、
   错误环刷新留存），按“改内容必 bump”升 patch；不升 minor（无新能力/无公开 API 变化）。
2. **重打发布字节**：`release --prepare` + `release --verify`；tarball
   `_dist/dsh-company-pack-0.7.2.tgz`，sha256 `74ea849e…6bc4aa`，127 entries；安装手册同版重生成。
3. **market index**：随 bump 重生成 `market-index.json`（0.7.2）；`market-index.staged.json` 同步为
   0.7.2 / `requiresPublish: true`。未 npm publish 前，索引是**staged 产物**，不得托管/引导用户加源；
   发布成功后按 [publish-handoff](../../docs/guides/publish-handoff.md) 刷新时间戳并删除 staged。
4. **兼容表述**：pack README 的 `0.2.1-rc.5` 写清为“仅生命周期实验的 host 面”，与
   `checks/gates/lib/compat-tags.json` 的认证 tag 台账（仍只列 rc.2）区分；不把实验说成全链认证。

## 输掉的方案

- **继续用 0.7.1 的旧 `_dist`。** 源码已前进、字节不对应当前代码；`release --check` 拒绝是正确的，
  绕过它 = 发旧包。
- **不 bump 直接重打 0.7.1。** 同版本不同字节，违反版本纪律；已安装用户无法区分。
- **把 rc.5 加进兼容台账。** 台账语义 = 全链验证过的 pin tag；rc.5 只做过生命周期 host 面实验，
  加进去会把“实验”冒充“认证”。
- **删除 market index 等发布后再生成。** 会丢掉图标/分类/描述等发布准备；staged 标记 + 发布
  handoff 已能表达“未发布”，删除反而让 handoff 少一件可审对象。

## 后果与边界

- **未发布**：npm publish 是人工 handoff；本 Note 不声称 0.7.2 已上 registry，`staged` 标记仍在。
- 未验证：真实 npm publish、HTTPS 托管/Discover、Desktop 壳、真模型认证档。
- `_dist` 与 manifest 是发布回执（gitignored）；提交的是版本/CHANGELOG/手册/market index。
