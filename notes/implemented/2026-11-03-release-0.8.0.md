# 2026-11-03 · 0.8.0：公开面收窄 + peer 收紧 + D7 偏离文档化

状态：implemented（2026-11-03；A- D7 批次）

> 上游 = [第五轮七维打扫卡](../../_backlog/issues/2026-11-03-repo-hygiene-round5.md)
> 评分 GAP：D7 peers 50 条（3 条无引用）；根入口 barrel 漏出 presence/doors；web-only/品牌偏离未写。

## 决定

1. **0.8.0（minor，breaking）**：根入口删除 `export * from './lib/presence.ts'` / `'./lib/doors.ts'`，
   公开面 = loader 需要的 `apply` / `inject`；`pack-exports` 钉住运行时导出集合。0.x 下删除公开导出
   按 minor，不按 patch。
2. **peerDependencies 50→47**：删 `dsh-session-persistence-jsonl` / `dsh-tool-workflow` /
   `dsh-workflow-ptc`（imports + preset 行 + cordis.patch 三源核对均无引用）；`zod` 仍被
   `presented-domain` 使用，保留。`pack-compat` / `preset-row-deps` / `release-smoke` 复验。
3. **文档化两项偏离**：pack README 写清“只支持 web 组合（`workspaceRegistry` 由 web-app 提供；
   base-only/headless 不加载）”与“品牌只占 `sidebar.brand.name`，保留官方 mark/hero（single 槽最小侵入）”。
4. **未加 `manifestVersion`**：vendor 类型里是可选字段、无文档语义；在没有上游合同前不加自造字段。
   `dsh.client.inject` 的 8 条边保留：它们对应本包实际使用的 client 模块 factory（非 bundle require），
   没有“删了仍安全”的证据。

## 输掉的方案

- **保留 `export *` 发 patch。** 公开面扩大且无消费者；删导出是 breaking，必须 minor。
- **按 import 扫描直接删 9 个 peer。** 会把 patch/preset 行引用的包误删；三源核对后只删 3 个。
- **把 `workspaceRegistry` 改成可选 inject + boot 不 await。** 会改变首屏登记时序；在 web-only 是明确
  产品面的前提下，文档化边界比引入竞态更长期正确。
- **加 `manifestVersion: 1`。** 上游类型可选、无行为合同；自造字段违背“不自造 spec”的纪律。
