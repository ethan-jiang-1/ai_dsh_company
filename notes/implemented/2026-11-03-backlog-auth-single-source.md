# 2026-11-03 · 授权边界单一真相源：门牌与章程摘要改为纯指针

> 审计 = [第五轮七维审计](../../_backlog/research/repo-hygiene-round5/2026-11-03-seven-dimension-audit.md) R5-04

## 决定

`_backlog/AGENTS.md` 的 `修复就绪` 行、`_backlog/README.md` 的快速摘要都不再复述排除项，只写
“限 P1/P2；排除项见章程「缺陷的通道」”。完整边界仍只在 `_backlog/README.md`「缺陷的通道与修复授权」
一处：P0、或触碰章程/常设指令、docs 合同、company-pack 公开行为、已记录决定 → 不自授权。

## 输掉的方案

- **把完整排除项抄进门牌/摘要。** 已经是第二次截断（R4-02 修过 `bugs/README`，门牌和摘要漏了）；
  第二份清单必漂。单一真相源 + 指针是长期正确的形状。
- **删掉自授权例外。** 会让 P1/P2 修复型缺陷卡重新卡在等人；例外本身是用户裁定的制度。
- **保持现状但加一句“以章程为准”。** 门牌已经这么写过，仍然先给了一个可执行错误版本；读者会按
  第一眼看到的“直接修”行动。指针必须替代复述，而不是叠加免责声明。

## 验证（实跑）

```text
pnpm verify
# ALL PASS（backlog-liveness / md-links）
grep -rn "P0 或严重/变向" _backlog docs AGENTS.md
# 仅审计报告的历史快照命中；活跃门牌/章程摘要不再出现
```

红证：未单独制造；`backlog-liveness` 只查形状，不查授权语义，所以本轮用 grep 证明活跃面已无截断句。
门牌是自动注入面，下一次触碰 `_backlog/` 即可看到新版本（本轮已实测注入）。

## 后果与边界

- 读者仍需点一次章程才能看全排除项；这是有意的：**边界只有一个家**，代价是一跳，收益是不会漏项。
- `_backlog/bugs/README.md` 早已是纯指针；本轮把最后两处活截断收口。
- 审计报告 R5-04 的“still live”是修复前快照；报告 banner 已标 B 批落地。
