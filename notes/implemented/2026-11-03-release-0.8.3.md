> 为什么升版：0.8.2 之后 pack 源码面变了（删 `CompanyView` 与两个 spec、源码注释/README 小改），
> `sourceFingerprint` 已不匹配 0.8.2 产物；按“改内容必 bump”升 patch。

## 决定

- **0.8.3 = 0.8.2 + 不可达 CompanyView 删除 + 注释/docs 修正 + 安装手册包内内容纠正**；无用户可见行为变化。
- 发布字节 = `_dist/dsh-company-pack-0.8.3.tgz`（sha256 `470992663790361bc7a0e454dd664c9d11086b8839e3d2755c3d2877967aa248`，
  127 entries；手册同版 `c692aac5…`）。
- 发布 commit 上跑完 7 项：verify / test / release-smoke / company-entry-smoke / client-load-smoke /
  preset-smoke / present-catalog-smoke；`--stamp` 后 `--check` = **READY 0.8.3**。
- npm publish 仍人工（本机 `npm whoami` = need auth）；`market-index.staged.json` 标记 0.8.3 未发布，
  `market-index --check --hosted` 会拒绝托管。

## 输掉的方案

- **把 master 停在 0.8.2、不升版。** master 的 pack 源码已与 0.8.2 tag 不同；再发 0.8.2 会产出同版本不同字节。
- **只重打 tgz、不改版。** 同上，违反“同版本同字节”。
- **跳过 `--verify` 直接 `--prepare` + READY。** `--check` 会因 manifest checks 缺失拒绝；发布字节没被真实安装过。
