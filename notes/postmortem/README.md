# postmortem/ —— 事故复盘（编号 000N）

> 本目录回答：一个 bug 为什么到了不该到的地方，**流程为什么放过了它**。
> 不是 Agent Note（那记有意决策与备选方案），也不收设计推敲。
> 清单 = 目录本身（编号 `000N-<slug>.md`），不建集中索引；每篇的 Lessons 归文内。

## 什么时候写

一个 bug 到了它不该到的地方（真人用户、已合并的 PR、发布），且值得记的不是那一行修复，
而是流程缺口。三个条件同时成立才写：

- **微妙**：机制不直观，一个认真的工程师也得重推一遍；
- **系统性**：它逃掉的原因是测试/工具/约定上的缺口，不是一次性笔误；
- **重查代价高**：已经花了真实调试时间，将来还会再花。

## 格式

开头一段 **Executive summary**（30 秒能读完：坏了什么、根因、为何逃掉、可复用的教训），
之后是 Summary / Timeline / Root cause / Guardrails added / Lessons。
Timeline 必须给**证据坐标**（会话 id、事件序列、RPC 报错原文），不从后来的报告反推意图。

## 与其它层的关系

- 事故 ≠ 设计推敲：推敲住 `_backlog/issues/`，决定住 `../implemented/`。
- 每篇加的护栏要链接到本篇（guardrail → postmortem），让同类失败下次响起来。
- 复盘不复制当时的决定正文；只记“为什么安全网没拦住”，决定看现行 owner。
