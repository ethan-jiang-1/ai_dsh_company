## 1. 第一直觉（不绕弯）

**如果只能回答一句**：把现在声明过的 8 个 token 收成 **5 个**——`MR / REQ / IF / TC`（+ 从属的 `AC`）——
**层不进号**，**"谁验"是一个字段而不是一个号**（`verifier`；验什么才有号，`TC`），**"建议新增"不许占用三位数字**（写 `IF-???`）。
剩下的窟窿用**一个派生索引 + 一条能判红的命令**堵，不靠把前缀选得漂亮。

三个更具体、可被证伪的直觉：

1. **"前缀第一眼就对"真正难的不是选词，是"同一个概念只能有一种写法"。** 最疼的真实失败是
   `IF-###` 与 `IFR-###` 同时活着（[evidence §3.2](research_topic/2026-11-07-evidence.md)）。那不是"选错词"，
   是**词表没关门**。只要允许第二个词表存在，选哪组字母都会重演。
2. **`SYR` / `IFR` / `STR` 的第一先验确实坏**：我自己看见 `SYR-014` 先想到叙利亚（要靠上下文纠正），
   看见 `VP-01` 先想到副总裁。而 `REQ` / `IF` / `TC` 的第一先验是干净的。这不是我在猜——`VP` 那次是真事：
   v5 的 SQA 宁可自创 `V-001~V-046`，也不用 skill 里写的 `VP-###`（[evidence §3.4](research_topic/2026-11-07-evidence.md)）。
3. **真正要修的是"一个号只有一个定义点"，它现在不存在。** 21 vs 23 那天，`IF-022` / `IF-023` 是
   **真的写在 SQA 稿里**的号，还带着完整接口内容（`company-workspace/…/v5/drafts/sqa-vv.md:109`），
   而 SA 只有 21 个定义。**一个号能被写出来却不指向任何定义**——这是索引问题，不是 prefix 问题。

> 诚实一句：我自己就是被测对象。上面第 2 条是我的**自省**，不是实测；样本 = 1 个模型、1 次。
> 这正是 V1 盲测要跑的原因，也是它第一次跑就会给出数据的理由——别把我的直觉当 V1 的替代品。

## 3. 方案 A（我偏向）：五词种类轴 + 层在文档 + 派生索引

### 3.1 契约（封闭集）

| token | 是什么 | 定义点 | 谁发号 | 例 |
|---|---|---|---|---|
| `MR` | 市场需求条目 | MRD 的 JSON 账本（现状不动） | CMO | `MR-003` |
| `REQ` | **任一层**的需求条目（StRS / PRD / SyRS 共用） | 各层文档，形态见 §7 | 该文档 owner | `REQ-017` |
| `IF` | 接口需求（IRS 条目；**两端 owner 必填**） | IRS，或 SA 架构稿（过渡期） | SA | `IF-014` |
| `TC` | 验证项（方法 + 判据 + 环境）；将来的"用例/计划项"之别走 `kind` 字段，不加 token | 验证文档 / SQA 稿 | SQA | `TC-006` |
| `AC` | 验收判据，从属 `AC-<REQ 号>-<n>` | 与父 REQ 同文档 | 父 REQ 的作者 | `AC-017-2` |
| ~~退役~~ | `STR` `SYR` `IFR` `VP` `V` `VR` `FR`；`NFR` 不作 token（用 `kind` + 清单） | — | — | 出现即红 |

### 3.2 文法（这就是"机器能判红"的全部）

```
<id>    ::= (MR|REQ|IF|TC) "-" 三位数字
<ac>    ::= "AC-" <父 REQ 的三位数字> "-" <n>     # 父号必须是已定义的 REQ
<提案>   ::= (MR|REQ|IF|TC) "-???"                 # 唯一一种"尚未定义"的写法
<跨动议> ::= <动议键> ":" <id>                      # 例 smoke-test:IF-014；裸 ID 只在动议内有效
<定义>   ::= 由文档头声明的形态唯一决定（§7 R1）
```

### 3.3 三条号法（少到能记住）

1. **一件东西一个号**：号一旦出现不改、不复用；作废保留号并写 `作废`。
2. **号在动议内全局唯一**：`MR/REQ/IF/TC` 各自一条 append-only 序列，**不按层分部号**——
   按层分号等于把"层"偷偷塞回号里，只是不叫前缀而已。
3. **下一个号 = 派生索引的 max+1**；索引由命令生成，人手不写。

### 3.4 拿真实样本走一遍（U1：一条涉众诉求 → 两条系统需求）

```
StRS（CMO）    REQ-003  不用先买设备、不用改造就能用
PRD（VP-Eng）  REQ-017  报价单元 / 交付边界（同一诉求的交易面，是另一件东西 → 另一个号）
SyRS（SA）     REQ-041  试点零新增固定资产 → 追溯 REQ-003
               REQ-042  首次付费须走服务/费用口径 → 追溯 REQ-003
IRS（SA）      IF-014   A 端 owner=…，B 端 owner=…，verifier=第三方实验室 → 追溯 REQ-041
```

**要点**：下游是**另一件东西**（粒度不同），所以拿新号 + 写追溯行；**同一件东西绝不换号**。
层不写在号里，层由"它在哪份文档被定义"决定——B 为此要多付的那笔钱，见 §4(b)。

## 4. 为什么是"种类"轴，不是"层"轴

**(a) 生长性：层本身还在打架。** 材料自己就三处不一致：§1.5.3 写 `MRD→PRD→StRS`，
§2 约束 5 写 `MRD→StRS→PRD`，而 lab 真跑成 `MRD→PRD→StR→SyR→IR`
（`runtime/lifecycle-lab/real-ws/…/final.md:7`）。**把一个正在吵的维度编进号，等于把争议固化进每个 ID。**

**(b) 它把"一件东西一个编号"从口号变成可判的。** 这是我认为最硬的一条：
- 种类轴上，同一件东西被两处定义 → 号重复 → **机器判红**。
- 层码上，同一件东西在两层是 `STR-003` 与 `SYR-003`，**两个都合法，机器完全无感**。
  用户约束 2 是要挡这个；方案 B 让它**不可判**。

**(c) 先验账。** 高风险 token 数：A = **0**（`AC`/`MR` 是中风险，`REQ/IF/TC` 低），
B = **3**（`STR` string、`SYR` 叙利亚、`IFR` 航空）。唯一**实测**失败过的那类 token（`VP`）
不是"少见的词"，是**高风险词**——它在两边都退役，但先验账告诉我们别的。

**(d) 已经装上的那一半不用动。** `/prd check` 与两份模板的现行文法就是 `MR / REQ / AC`
（[prd-check.ts:132-236](../../../../packages/company-pack/src/lib/prd-check.ts)、`content/templates/{mrd,prd}.md`）。
A **只退役 `VP`、不改检查器文法**；B 要 `IF→IFR` 全量重键 + 改 3 份 preset 里 7 处文案（SA 的 `agent.cordis.yml` 与 systems-architecture SKILL、SQA 的 vv-playbook）。

## 5. 方案 B（诚实的对手）：层码六词

形态：`MR / STR / REQ / SYR / IFR / AC`（= 现行 `kb/process-docs.md` 的路线，也是 lab 真跑过的一套）。

**它真的更好在哪（我不打折）：**
1. 号自带层 → 读 `SYR-014` 就知道"系统需求、归 SA、在某份 SyRS"，人审 U8（5 分钟答 owner/verifier/追溯）少一跳。
2. **每层独立发号**：CMO/VP-Eng/SA 三个 owner 谁也不用知道别人的 max，天然不撞号。这是 A 的最大成本，B 白送。
3. 对齐 ISO/IEC/IEEE 29148 的文档族名字（StRS/SyRS/IRS 本来就是文档名）。

**它真的更差在哪：**
1. 三个自造缩写先验弱/错，且**唯一实测过的那种失败（撞角色名）就在这一边**。
2. 每加一层、每并一层（§8-2 问过"StRS/PRD 能否并"）就要改词表——与约束 4「前缀别再加」的**生长性读法**直接冲突。
3. 把还没定的层序写死进号（见 §4(a)）。
4. 一件东西跨层两个号，机器看不出来（见 §4(b)）——这条是对用户约束 2 的正面让位。

**我会翻过去的情形**：V12 人机对照显示"人找层/owner 变慢 > 60 秒且显著错"，或 V11 评审人明确说
"没有层码我不审"。到那时正确的改法也不是 B，而是 **A+：在文档头与题目加一行大字 `层：SyRS`**，不动号。

可以用"派生索引"这个一次性的东西买回来；A 赢的那项（一件一号可判）没有工程办法补。

## 7. 配套规则：让"判红"真的发生（这才是包里的主体）

一条命令（**人跑，不是角色跑**——角色不能跑脚本，硬约束 6）：`/req check <动议>`，形状照
[prd-command.ts](../../../../packages/company-pack/src/host/prd-command.ts) 的先例（固定路径、只读、返回 JSON），
扫描该动议的文档树，输出 `index.json` + 红绿清单。

| # | 规则 | 红（例子） | 绿 |
|---|---|---|---|
| R1 | **定义形态每文档声明一次** | StRS/SyRS/IRS 头部缺 `定义：表行｜小节标题` | 声明后只在该形态里认定义；PRD/MRD 的定义点 = 第一个 json 代码块（现状不动） |
| R2 | **悬空号判红**：每个号必须解到唯一定义 | `IF-022` 被写但无定义（21 vs 23） | 全解到 |
| R3 | **唯一词表 + 作用域** | 出现 `IFR-014` / `VP-03` / `VR-01`；`MR` 定义在 SyRS | 只在允许的文档定义 |
| R4 | **提案只用 `???`** | 用 `IF-099` 表达"建议新增" | `IF-???` |
| R5 | **缺层 = 红**（空过不成立） | 落地动议缺 `prd.md`——现在的结果是 10/10 PASS，这才是红 | 五层齐，或被显式声明豁免 |
| R6 | **重复定义 = 红** | 一个号两处定义（含跨文档） | 每个号一处 |
| R7 | （可选，可能过拟合）文中"N 条"必须 = 索引计数 | "21 条接口" vs 索引 23 | 相等 |

**R1 为什么必须"每文档声明"而不是"表行即定义"**——这是我盘面复核出来的一个坑，值得评审：
lab 的 `syr.md:370`（`| STR-001 | A 主管 | SYR-002… |`）与 `irs.md:323`（`| IFR-001 | SYR-025… |`）
都是**追溯矩阵**，号正好在首格。若"表格首格 = 定义"，这两处会被误认成"STR 在 SyRS 里定义了一次"→ 假红。
真实定义只有两种形态：`| **IF-001** | …`（首格加粗）与 `#### SYR-001 标题`（标题首词）。
**所以形态声明是一行成本换掉一整类假红**，值。

**不假装是门禁**：present 目前不可被 pack 否决（硬约束 11 / V6 未证），所以这一条是**操作员工具**，
不是闸门。诚实说法：**"评审材料里必须贴一次红绿"**——它比"有检查没人跑"（`/prd check` 现状）强一档，
比真门禁弱一档。别在文案里写成门禁。
