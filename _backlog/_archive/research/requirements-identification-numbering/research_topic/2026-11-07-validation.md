# 验证计划（§9 / §11）

> 本文件 = 原第三份材料的 §9、§11；节号沿用全局编号。返回 [当前 brief](2026-11-07-current-brief.md)。

## 9. 验证计划（纸面/只读；仍不动实现）

1. **V1 盲测 prefix 第一先验**：10–15 个 token 裸给模型（无文档上下文），问"看到 `X-001` 第一反应是什么"；记录第一反应、错误先验、是否能说出用途。**尚未跑。**
2. **V2 真实样本重键**：用 lab 的 16 STR / 33 SYR / 22 IFR，分别按 H1/H2/H4 重键；检查追溯可读性、AC 父号唯一性、count 声称、near-miss。**尚未做。**
3. **V3 定义语法原型**：在同一份小样本上写 D1/D3/D8 三种定义语法，比较可解析性、写作成本、双真相风险。**尚未做。**
4. **V4 提案/near-miss 负例**：把"建议新增 IF-022/023"按当前写法与 F1/F2 写法各放一份，测 Agent 是否能区分；同时测 `AC-008` 这类 near-miss。**尚未做。**
5. **V5 矩阵生成**：对 lab 样本生成 trace 矩阵，看能否暴露 PRD→SyR 的空边；比较 H1/H3/H4。**尚未做。**
6. **V6 强制点可行性**：只读核对 DSH 的 `PreToolUse` / present 包装能力；确认 pack 能否否决 present；若不能，记录"门禁 vs 操作员工具"的差距。**尚未做。**
7. **V7 迁移成本**：统计旧产物里 `STR/SYR/IFR/IF/VP/V/VR/TC` 的引用量与跨动议分布，估重键/别名/冻结的成本。**尚未做。**
8. **V8 外部可读性**：把候选 ID 贴进模拟的供应商 Excel、实验室报告、CAD 注记、邮件；让不了解系统的人/Agent 解析。**尚未做。**
9. **V9 NFR 清单**：在 SyRS 样本上跑"I1 kind+清单 / I6 必填 n/a"，看 BUG-034/035 是否会被逼出来。**尚未做。**
10. **V10 范围声明**：在 demo/决策类动议上试 L3/L4/L5，看"缺声明=红"是否可执行。**尚未做。**
11. **V11 IRS 检查点试跑**：拿 lab 的 IRS 22 条，按"两端 owner / verifier / trace / 失败态"做一次评审清单；看哪些能过、哪些不能；记录人审时间。**尚未做。**
12. **V12 人机理解对照**：同一份 IRS 样本，给人审和 Agent 各 3 个问题（谁 owner、谁验、追到哪）；比较时间/正确率。**尚未做。**
13. **V13 OpenSpec 接缝**：在一份真实/模拟 OpenSpec spec 的 requirement 上加 `Traces:`，验证跨世界解析与校验器读取。**尚未做。**
14. **V14 多 discipline 分配**：用真实样本填 allocation 附录，检查 ★ 唯一、覆盖、无前缀。**尚未做。**
15. **V15 变更/作废**：模拟一条需求冻结后变更，检查旧号作废、新号、追溯影响、文档更新。**尚未做。**
16. **V16 导出/语言**：生成一份"中文文档 + 英文 ID + 项目键"的导出样本，给模拟供应商/实验室读者解析。**尚未做。**

## 11. 下一步：先补空间（收敛由用户拍）

**给下一个 Agent 的顺序**（也是本轮之后的路线）：

1. 读 §1.5 + §1.6，用 §1.6.1 自检；答不上就回读，不要跳到方案。
2. 补 §8.5 的空白：能问用户就问；问不到就在材料里显式标"假设"。
3. 生成多个候选方案族（§6.0 的 S1–S8 可选组合），每个都应能回答 §4.Q 的 12 个用例。
4. 用 §6.5 的评估维度把 trade-off 摆出来；用 §9 的 V1–V16 收集证据；**不选**，等人拍。

**测试与它们可能区分的东西（不预设顺序/优先级）**：

- V1/V2/V7/V8：可能区分不同编码轴与词表在"第一眼/迁移/外部可读"上的差异。
- V3/V4/V5：可能区分不同定义/提案/追溯语法在"机器可判"上的差异。
- V6/V9/V10/V11–V16：可能区分不同强制点、NFR、范围、检查点、人机、OpenSpec、多 discipline、变更、导出的差异。

在上述证据齐之前，不选前缀、不写 RFC、不改 pack；卡保持 `调研中`。
