# 实证解剖：11 月 20 日后 50 张缺陷卡为何逃逸，以及代码里现在还剩什么

> **基线**：2026-11-23 仓库 HEAD（含 E2E 第一轮至第六轮收口提交）。数据直接提取自 `_backlog/_archive/fixed_bugs/` 下 `BUG-283` 至 `BUG-332` 原文及 `packages/company-pack/src` 只读扫描。**本文只呈现事实与归类，不构成新缺陷卡或实施授权。**

---

## 1. 核心数据反差：E2E 发现了它们，但 87.8% 根本不需要 E2E

11 月 20 日至 11 月 23 日之间共开出 **50 张缺陷卡**（`BUG-283`–`BUG-332`）：**49 张 `已修`**，**1 张 `已结`（撤回）**（`BUG-288`）。

按**受影响代码面**与**最终复现红证所用的测试层**统计，出现三个极其刺眼的事实：

| 维度 | 统计值 | 占比 | 含义 |
|---|---:|---:|---|
| 落在 `content` 合同族（11-20 试点范围） | **0 / 49** | **0.0%** | 11-20 试点在其自身作用域内没有再漏洞 |
| 落在 `packages/company-pack/src/{client,lib}/` | **40 / 49** | **81.6%** | 真正的高发区是客户端读模型、解析器、投影与双语 UI |
| 落在 `packages/company-pack/src/host/`（仅 host） | **2 / 49** | **4.1%** | `BUG-316`、`BUG-326`（均为培养命令双语表达漏翻） |
| 落在 `tools/`、`checks/`、`probes/` | **7 / 49** | **14.3%** | `BUG-283/284/285/286/287/289/296`（包装器、车道与产物陈旧） |
| **红→绿复现仅靠 keyless `vitest run`** | **43 / 49** | **87.8%** | **近九成缺陷根本不需要真浏览器、真模型或真进程即可触发** |
| 必须靠真进程/真浏览器/真 CLI 复现 | **6 / 49** | **12.2%** | `BUG-283/284/285/287/289/296`——**全部 6 张都是工具/车道自身的问题，产品代码 0 张！** |

**结论非常明确**：过去三天陷入「E2E 找 bug → 修 bug → E2E 再找 bug」的循环，**不是因为这些 bug 只有 E2E 才看得到**，而是因为我们在 `src/client/` + `src/lib/` 这一面上，既缺少**让错态写不出来的代码结构约束**，也缺少**E2E 之前的主动猎虫手段**，被迫拿最慢、最贵、最依赖人工巡检的 E2E 去充当“人工 fuzz + 人工静态扫描 + 人工双语检查”。

## 3. “修一漏三”的连锁现象（Patch-Induced Regression & Sibling Escape）

比单张卡更值得警惕的是**跨轮连锁反应**——第 3 至第 6 轮里有大量 bug 直接产生在上一轮修复的接缝上：

1. **边界链（6 轮连续冒头）**：`298`（文件行上限）→ `304/305`（800 窗口/失败计数）→ `317/318/320`（1000 事件/20 候选/5 条审批）→ `327/328/330/332`（漏接本会话 capped / 空态漏 3 个边界 / 文案仍写审批 / 恰好 800 误报）。
2. **身份链（4 轮连续冒头）**：`295`（截断摘要）→ `299`（按摘要去重吞审批）→ `312`（问询无 id 退回摘要撞 key）→ `325`（活体合成 id 与历史 `callId` 对不上重行）。
3. **双语链（5 轮连续冒头）**：`300`（原始 ISO）→ `302`（lib 时间/原因中文）→ `308`（对话面板双向漏）→ `316`（host 63 条回执）→ `326`（host 描述/hint/内部错误）→ `329`（client 四处中文顿号 `、`）。
4. **折叠与分箱链**：`306`（接上 `mine` 上限）→ `307`（同轮引入 4+4 控件错算）+ `309`（同块自拒记录重显）。

**根因**：每一轮都是「发现一个坏点 → 补一个局部补丁 + 一条具名用例」，而**没有把该类约束上升为类型不变量、共享原语或自动化全域扫描**。

> **关键证据意义**：不需要起浏览器、不需要写 E2E 脚本、甚至不需要运行单测——**仅靠针对根因族设计的 20 行静态扫描**，就能在 1 秒内指出“第 6 轮刚修完 `BUG-329` 与 `BUG-331` 的同一批文件里，又新进了硬编码中文与中文分号”。这直接证明了：**只要不把约束沉到代码结构与自动化扫描里，第 7、8、9 轮 E2E 仍会源源不断挖出同一类洞。**
