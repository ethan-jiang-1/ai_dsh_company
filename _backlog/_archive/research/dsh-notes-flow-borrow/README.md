# DSH notes 流程的剩余借鉴点：不是缺分类维度，是缺三把锁

> 问题：外部研究树 `_digested/development-flow/`（维护者本机，repo 外只读）把 DSH 的
> `.agents/notes/` 制度拆成八篇。本仓的 `notes/` 已经借过一轮（D35、D34、D38，两次否决
> class 子目录），但那一轮借的是**分类与证据门槛**。这一轮要回答：剩下的八章里，哪些是
> 本仓真的漏了？尤其是「子目录的孙目录」（DSH 的 `{lifecycle}/{class}/`）与 note 的
> 状态/flow，值不值得再借？
> 消费者：用户 2026-11-13 点名（「看看哪些值得再借鉴，尤其 notes 里头的子目录的孙目录，
> 再加上 notes 里头的一些状态和 flow」）；活消费者 = 下面那张卡（2026-11-14 已结）。
> 产出的卡：[notes/ 的树形与载体执行面](../../settled_issues/2026-11-14-notes-tree-and-carrier-gates.md)
> （2026-11-14 立，第一批 = B1+B2+B3；B4–B11 待各自裁决，N1–N5 不借）
> 结论：**孙目录不借，而且理由没变**（class 是第二套分类轴，closed set 维护成本换不回来；
> 两次否决仍成立）。真正的漏项是另外三件事，与「再加一层」无关：① **树形没有锁**——
> `notes/` 的形状只写在散文表里，没有门禁；实测五种不可能形状（两种未登记目录 / notes 根
> 散件 / 错误深度 / 无日期文件名）下 `pnpm verify` 全绿，与 DSH 用三条 `structure:` 报错专门防的
> 「文件对走查不可见」是同一病；② **纪律载体没有锁**——子目录的军规写在 `README.md` 里，
> 而按目录自动注入的只有 `AGENTS.md`（本轮实测：注入 `notes/AGENTS.md`，从不注入
> `notes/implemented/README.md`）；③ **忘记的判据没校准**——本仓只有一句「剩余否决仍能
> 阻止重开」，DSH 那套「字数与判定方向相反」的成对样例没借，六条 keep 理由只写了一条。
> 另有一处两门打架：`notes-archived-links`（冻结层 `.md` 链接必须全在）与 `link-debt`
> （冻结层死链只设天花板 4）对同一层两种容忍度，冻结层一旦因目标移动被要求改文，
> 「冻结」就破了。八章主轴在本仓都找得到对应物；差的是执行面，不是维度。
> 归档：2026-11-14（末张活卡已结；B4–B11 若要开卡，新卡引用本题目录）。
