# 该不该改：判断与取舍

> 事实与断点住 [实测盘点](2026-11-10-traceability-audit.md)；本文只做判断。

## 判断

**不是毫无问题，但也不需要新子系统。**

卡机制、门禁、红绿证据、根因分组都是资产；缺口只有一个概念、一个决定点、一处事实：

1. **一个概念**：没有把「重要」写成可判定的词。章程「缺陷的通道」已经有一份现成清单（P0 或触碰章程 / 常设指令、docs 合同、company-pack 公开行为、已记录决定），但它只用于「能不能自己修」。
2. **一个决定点**：缺陷轨关门时不问「留痕去哪」。
3. **一处事实**：`去向=note` 的落点可以指向卡自己，门禁只查词。

## 为什么是「材料性」

把那份授权排除项提升为一个具名谓词，授权和留痕共用：

> **材料性** = P0，或修复 / 结论触碰章程、常设指令、docs 合同、company-pack 公开行为、已记录决定。

好处：

- 不发明新词——它就是现有的授权排除项；
- 一份清单、两个消费者，不会漂成两份；
- 它把「重要」从感觉变成可对照的清单，fresh agent 能逐项勾。

## 推荐：三层

### 第一层：规则（约 15 行，改 4 处）

1. **章程「缺陷的通道」**：写出「材料性」定义，并规定：
   - 材料性修复 → 翻 `等人拍板` 请示；**同一份请示里同时给出留痕建议**（`note` / `commit` / `none — 理由`）。
   - 非材料性修复 → P1/P2 可直接修，不建卡；commit message 写根因与影响面。
2. **章程第 9 行 / 缺陷规则第 3 行**：把「当场修掉的不建卡」限定为「当场修掉且非材料性的」。
3. **收尾 skill 第 30 行 + budget-and-ops 第 53 行**：把「抓到异常 → BUG 卡」限定为「材料性异常」；非材料性写 commit。
4. **问题轨**：`去向=implementation` 只用于非材料性结论；材料性结论用 `note`，或 `implementation` + 指向承载决定的 Note 链接（伞卡模式），不得只写 commit；`none` 要写理由。

为什么把留痕挂在授权请示上：材料性修复本来就要你拍板，那一刻你在场、范围清楚、备选在桌上，多问一句「留不留 Note」成本最低。非材料性修复不需要你拍板，也就不该为它造一篇 Note。

### 第二层：机械兜底（两件）

5. **缺陷卡补留痕块**：归档时卡顶写 `留痕：Note <路径>｜commit <sha>｜none — 理由`。与问题轨的 `去向` 对称，只查形状。
6. **落点解析门**：`去向=note` 的链接必须解析到 `notes/` 下的真实文件；生效日之后的卡从严，旧卡不动。同时修掉现有 2 张卡 + 6 行索引。

### 第三层：习惯（一句 + 入口）

7. **批量分组**：同一轮 ≥3 张缺陷卡，先列根因分组表再逐卡修。11-08/09/10 已经这么做，写下来只是把有效实践固定。
8. **入口**：close-out skill 是每个非平凡收尾都应加载的钩子，先改它；`_backlog` 门牌加一行分诊路由。根 AGENTS.md 是 84/84，不做净零改写之前不动它——如果之后仍观察到 fresh agent 漏掉，再按净零改写。

## 为什么不是别的

- **每 bug 一卡**：卡是推敲层，不是修理台账；会制造大量 `已修` 噪声，也违反 notes 对机械单步的豁免。
- **新目录 / 新状态**：第二本账；五道门刚拒绝过 `落地中` / `待审`。
- **语义门禁**：P2 明确不做；能机械查的只有「落点解不解析」。
- **把轮次回执落文件**：notes/README 明确负例（轮次日记不进 implemented）。

## 风险与反证条件

- **误分类风险**：agent 可能把材料性修复说成非材料性，从而同时逃掉授权与留痕。这不是新风险——授权本来就有这条边界；把它写清只是让误判可指认。
- **过度矫正**：如果新规则导致每轮都写 Note，说明「材料性」被解释得过宽；回退到清单逐项勾。
- **反证条件**：改完规则后的 10 次材料性修复里，若仍有 ≥3 次没有留痕决定，问题就在执行钩子而不是措辞——那时再考虑把留痕问题写进 `修复就绪` 的翻转守卫（形状），或加一条 checklist。
- **门禁的边界**：落点解析只证明「链得到」，不证明「写得对」；语义审仍要人 / agent 读。

## 开放问题（我的倾向）

1. **材料性清单要不要加「对外可见 / 不可逆」？** 暂不加。现有五项已经覆盖公开行为与合同；加词会让边界模糊。
2. **`留痕` 用卡顶一行还是 frontmatter 字段？** 卡顶一行。交接契约已定卡顶块是记录家，加字段会造第三处真相。
3. **门禁现在上还是等一轮？** 现在上（新写生效）。self-link 已经实证复发，且修起来只动 `backlog-liveness` 一处；旧卡祖父豁免。
4. **入口改哪里？** 先改 close-out skill；AGENTS.md 等证据。

## 推荐顺序

1. 规则 4 处 + 8 处落点修复（同一 diff，可独立验收）
2. 缺陷卡 `留痕` 块
3. 落点解析门 + 反证
4. 批量分组一句
5. 入口（close-out skill 同轮；AGENTS.md 按证据）

## 一句话

**把「重要」写成清单，把「留痕」挂到已有的授权请示上，把「落点」变成可解析的事实。** 其余不动。
