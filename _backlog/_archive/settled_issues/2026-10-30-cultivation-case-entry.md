# 推敲：培养主任务的工作/目标优先单入口

> 立卡：2026-10-30 ｜ 状态：已结 ｜ 类型：Feature ｜ 毕业：做 ｜ 可关闭：是
>
> **结论/去向**：第一切片已落地，去向 = [case-entry Note](../../../notes/implemented/2026-10-30-cultivation-case-entry.md)。对话式梳理/候选草稿/多段背景/真人走查不在本切片；AI 起草 v2 维持独立决定。
>
> 用户 2026-10-30「继续」延续上轮结论：主任务自然语言 IA 另立项。上轮已结卡 = [培养入口收口](./2026-10-30-cultivation-entry-followup.md)；上轮 Note = [entry-followup](../../../notes/implemented/2026-10-30-cultivation-entry-followup.md)。

**问题与期望结果：** 当前主任务仍是“开始记录一项工作 → 选纠正/建议 → 期望句 + 做法证据”的旧表单：先让人选内部记录类型，再写抽象期望，工作事实被挤进正文/背景。原型的核心是“先说这次什么工作/想改善什么，再形成一条下次做法”。本卡做第一切片：单入口表单以工作事实为第一字段，目标角色显式可见，提交前有实时预览；不要求先选纠正/建议。

**当前情况：** `CultivationCompose` 有 `mode` 二选一与 chooser；`expectation` 是期望句、`body` 是做法与证据；记录没有独立的“工作事实”字段。方法层用 `body`（空则回落到 `expectation`），因此工作事实不能直接塞进 `body`。

**方案（第一切片）：**
- 记录加可选 `work` 字段（单行、有界），旧记录缺字段照旧读；不新增存储根/服务。
- 命令加可选 `--work=<encoded>`；有 `work` 时 `body` 可空（方法层仍用 `body` 或 `expectation`）；无 `work` 的旧语法不变。
- 创作面改成单表单：目标角色（默认当前角色，可改；改到别的角色即建议）、这次什么工作、下次希望怎么做、可选补充做法/证据、可选背景；表单内实时预览“目标角色 / 工作 / 做法 / 背景”。
- 去掉纠正/建议二选一：由目标角色是否等于当前角色推导 `correct`/`suggest`。
- 收件箱、已采纳、我提交的显示 `work`；正文仍叫“补充做法/证据”或“做法与证据”。

## 范围与排除项

- 范围：上述 `work` 字段、命令、单表单、预览、展示与测试。
- 排除：AI 起草/自然语言解析、完整多步向导、改方法层合同、改角色闸、新路由/Remote/数据服务、真人走查（归 Note 后续观察）。

## 验收标准

| 行为 | 通过信号 | 反例/恢复 | 判断者 |
|---|---|---|---|
| 单入口 | 打开创作面直接看到“这次什么工作/下次希望怎么做/目标角色”，不再先出现纠正/建议二选一 | 旧语法仍可提交；空字段有可读校验 | keyless + 真浏览器 |
| 目标角色 | 默认当前角色且明示；改选别的角色时文案变“建议”，命令发 `suggest <role>` | 跨角色仍由目标角色本人决定；Agent 不能自采纳 | keyless + 真浏览器 |
| 工作事实 | `work` 落记录并在收件箱/已采纳/预览里显示；旧记录无 `work` 照常显示 | 缺失标“未记录”，不猜；`work` 有界，超限拒 | 读模型/host 测试 + UI |
| 方法层 | 有 `work`、`body` 空时方法文件用 `expectation`；`body` 有内容时仍用 `body` | 旧记录方法内容不变 | host 测试 |
| 预览 | 提交前能看到目标角色/工作/做法/背景摘要，修改字段即时更新 | 预览不改状态、不落盘 | keyless + 真浏览器 |
