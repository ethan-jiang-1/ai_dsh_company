# 推敲：内部全英文 canonical + 表达层双语（角色名 / preset picker 统一）

> 立卡：2026-11-12 ｜ 状态：已结 ｜ 类型：Feature ｜ 毕业：做 ｜ 可关闭：是 ｜ 审查：用户 — 2026-11-12「要么就全英文」批准方向；agent — 结构门禁 + 语义审（表达层/内部层边界）
>
> **结论/去向**：rfc — [RFC](../../../notes/proposed/2026-11-12-internal-english-canonical.md)（已批，未实施；本卡随 RFC 成立归档）
>
> 用户 2026-11-12：同意表达层双语；绕不过去的边界「只要统一了就行」；内部不能一半英文一半中文，**要么就全英文**。

## 原始意图（用户原话）

> 「好的，挺好，那就那个这痕迹吧，显性化成issue，然后转向notes, 同意你的想法, 绕不过去的边界，那儿就是，只要统一了就行 但我们有的是全英文，有的还是全中文，这就比较荒唐了。要么就全英文。」

## 问题与期望结果

**问题**：当前内部是混合态——标识符/preset id 英文，代码注释/日志/诊断中文，persona/skills/手册/模板中文，`meta.md` 领域值与账本表头中文，picker 名字英文但描述中文，表达层只迁了页签壳。用户明确这不可接受：**不能一半英文一半中文**。

**期望结果**：

1. **表达层双语**：UI、角色显示名、命令回执、交付物/回复 zh/en；默认 zh；角色名用 `roles.*` 映射；preset picker 统一英文（边界统一即可）。
2. **内部全英文单份**：代码标识符/key/ID/数据值、模型提示/内容、persona/skills/handbook/templates、注释/日志/诊断全部英文；不建中英双份内容、不建每语言 preset。
3. **领域值/旧盘**：canonical 改英文 ID；旧 `.dsh-company` 读兼容 + 迁移 + 写英文；中文只出现在表达层 zh 标签。
4. **不伪造**：内部英文是单份 + 可机械检查；表达层 zh/en 不因内部英文降标。

## 当前情况（摘要）

- 旧 RFC 的 Phase 0/A1/A3a/A2-tab-shell 已落地：locale 字典、默认 zh、host 语言桥、页签壳、品牌；表达层基础不回退。
- 旧 RFC 的 Phase B 原为「中文正文 + `content/en` overlay」，与用户「内部全英文」冲突；已由新 RFC 取代。
- I1（内容/领域值/picker 英文）、I2（注释/日志/测试名英文）、I3（开发者文档英文）均未开始。
- 详细盘面/阶段/验收 = [新 RFC](../../../notes/proposed/2026-11-12-internal-english-canonical.md)；表达层边界 = [方向材料](../../research/bilingual-company/2026-11-12-expression-layer-direction.md)。

## 范围与排除项

**在范围内**：

- I1：`presets/**`、`content/**` 英文单份；领域值英文 ID + 旧盘兼容/迁移；picker 英文；host/model-facing 默认英文。
- I2：`src/**`、`tests/**` 注释/日志/诊断/测试名英文；内部 CJK 门禁。
- I3：README/docs/AGENTS 等开发者文档英文（是否同批由用户定）。
- E1：旧 RFC 的表达层继续（角色名 `roles.*`、面板/回执 zh/en、真页面金样）。

**明确排除**：

- 再建一份中文内部内容（`content/zh`/`content/en` 双份）。
- 每语言一套 preset id / 双语一行 picker。
- 把表达层改成全英文（表达层仍 zh/en）。
- 在 I1/I2 里顺手改业务语义；翻译只改语言，不改规则。

## 验收标准（Phase I1/I2/I3）

- **I1**：`presets/**`/`content/**` 模型可读正文无中文；领域值 canonical 英文 + 旧盘可读/迁移；picker 名称/描述英文；相关 keyless/preset-smoke/回放全绿。
- **I2**：`src/**`/`tests/**` 注释/日志/诊断/测试名无中文（allowlist = `locales.ts` zh 字典/中文夹具/zh 断言）；内部 CJK 门禁真实红→绿；`verify`/`test`/`typecheck`/`lint`/`dup` 全绿。
- **I3**：README/docs/AGENTS 英文；用户安装手册 zh/en；文档门禁同 diff；`verify` 绿（若同批）。
- **E1**：旧 RFC 的 A2/A3b/A4 表达层验收继续有效；默认 zh、切 en、角色名/面板/回执 zh/en；真页面 zh/en 金样。
- 未验项如实标「未执行」；不以 grep 代替语义审/翻译质量审。

## 抽象度

- 换公司要改吗？→ **不会**。语言是表达层偏好；公司事实/政策仍是数据，不因语言复制。
- 换产品类型要改吗？→ **不会**。内部英文 canonical 与产品类型/交付模式正交；翻译不改规则。
- 换做法要改吗？→ **会**。新增内部内容/字段/注释默认英文；新增表达层文案仍需 zh/en；加语言 = 表达层字典 + 角色/术语表。
- 只有机制本身变吗？→ 内部英文是机制/内容约定；领域值迁移是数据合同变更，单独验证。
- 第二消费者：中文表达层用户 + 英文表达层用户；内部模型/代码/日志消费者只需要英文一份。
- 搬家成本：内容翻译高（数万汉字 + 质量审）；领域值迁移高（旧盘兼容）；注释/日志中（按目录分批）；表达层已有地基。
