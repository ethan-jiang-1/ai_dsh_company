## 背景（怎么回事儿）

一台笔记本、本地盘共享（无网络盘）。同一文件可能被多方写：角色会话、多人模式的各扇门、外部
编辑器。E2 实测（2026-10-03，双进程 fs-local）：同版本守卫写 ×20 = 20/20 **静默互踩**——守卫
管新鲜度不管独占，跨进程没人排队。本卡问的 = 写完整性怎么保。

## 选定方案（怎么弄——部署约定 + 三层各管一段，零新代码）

**部署约定（第一解）**：写共享盘的 DSH 进程收敛为**一个**——单操作者模式（CEO 一个进程装下
公司，真人走 web 观察窗）。跨进程静默互踩的前提是「多实例常态写同一文件」；前提被约定移除。
并发问题的第一解是减少并发源，不是先造锁。

在此前提下三层各管一段：

| 层 | 管什么 | 依据 |
|---|---|---|
| **机制面（防）** | fs-local 实例内 per-target 锁 + 版本守卫：同进程两个会话写同一文件 = 一胜一拒（`FS_STALE_VERSION`），被拒方重读重写——丢更新在机制上无法静默发生 | 手册「写盘守卫」条；E1 实测（真角色会话 ×4 轮全绿） |
| **协调面（看得见，Agent Teams）** | 动议落**任务板**：一份稿一个任务，`writeScopes` 填要写的路径前缀，成员**认领**（ownerId）再动笔；两任务路径重叠 = `writeScopeWarnings` **提前警告**，Lead 协调分工；写完**完成任务 + 邮箱回执**；`wait_agent` 等边不轮询。真人经 web 团队面板全员可见（谁领了什么、干到哪） | Agent Teams（任务板 `expectedRevision` CAS、advisory writeScopes、持久邮箱）；pack 主通道就是它 |
| **审计面（可查）** | 占位=认领（开场落稿，首行「占位=认领，非出稿」）、派活行、稿首署名行（`authorship-audit` 机器核对）、slug 唯一 | 手册协作规矩（2026-10-03 立），全数在册 |

**为什么 Agent Teams 是协调面不是锁**（它的诚实边界）：自我声明 process-local——跨进程不
协调、无文件锁；把任务所有权/writeScopes 当锁被上游裁决否决（**假互斥比明示警告更危险**：
外部写者照样绕过、崩溃的 owner 不释放）。正确用法 = 把「谁在写什么」提前变成全员可见、机器
可查的状态 + 重叠警告；机械拦截归机制面，事后追责归审计面。**多人模式（多扇门）下 Agent
Teams 跨 home 不可达**（进程内能力）——协调面用它的**文件化投影**：派活行 = 文件版任务板、
占位=认领 = 文件版抢注、署名行 = 审计（手册已立）。

**冲突时会发生什么（可预期行为）**：① 开工前——任务板警告路径重叠，Lead 协调；② 写时撞了——
后写者得 `FS_STALE_VERSION` 被拒，重读重写（或按纪律先占位）；③ 事后——署名行 + 审计脚本查得
动是谁的手笔。
