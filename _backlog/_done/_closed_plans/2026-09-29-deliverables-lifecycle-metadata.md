## 背景 / 触发

用户反馈（2026-09-29，直面 company-workspace 的历史堆积）：

1. deliverables 里**所有话题前面没有日期**——"至少是 kick off 的日期"，第一眼看不出时间轴；
2. 任何一个 kick-off 之后的议题**最好有 metadata**——今后打整（清理/迁移/审计）才方便；
3. 历史的东西肯定还有 **archived / rejected / implemented** 的事——所以"这底下的目录结构要思考思考如何调整"。

同轮姊妹卡：[writing-collab-locks-redis](./2026-09-29-writing-collab-locks-redis.md)（写作协作的锁与感知，
含 Redis 评估）。拆两张卡的理由：本卡是**静态布局/契约重构**（不动机制，改目录、字段与门禁，可独立毕业）；
那张是**运行时协调机制**（要不要新基建，要实验证据）。两张卡的接缝 = "元数据/事件流是谁的事实家"

  机制卡毕业与否都不阻塞这里（A2 收敛补日期在无机制下依然成立；机制复活则回填量大减）。
- **仓库自己的命名先例**：`notes/implemented/` = `YYYY-MM-DD-<slug>.md`；`_backlog` 卡 = `YYYY-MM-DD-<slug>.md`
  （日期 = 立卡日，时间轴就在文件名上；2026-10-03 D33 起与 notes 树统一为全日期，原 YYMMDD 形状退役）。
  deliverables 是**全仓唯一没有日期前缀的档案层**。
- **三态合同只管文件类别，不管话题生命周期**：成品 final / 过程稿 drafts / 排练产物不进盘
  （公司手册「交付物三态」）。话题本身**没有任何状态**——"这场动议否决了/落地了/归档了"无处可查，
  只能读 final 正文的一句话结论自己判断。
- **迁移的桥——已证伪（2026-09-30 盲审实测，详见评审修正 1）**：D20 的"按 `slug`+角色身份比对、不按
  路径"**只对形状迁移成立**（平铺→嵌套，slug 不变）；slug 本身从路径首段推导（deliverables.mjs:90），
  **改名 = 改 slug = 身份变**，反向锁三连误报复现。⇒ A2/C1 的判据代价 = slug 归一化补丁 + 改名红绿
  用例（已挂毕业门决策点 1 前置）；同根因连带 `slug-unledgered` 裸匹配误报与 authorship-audit 路径
  配对报废；`tests/deliverables.spec.ts`、snapshots 形状说明仍须随迁移同 diff。
- **反向锁**：被 `present` 过的 final **永不删**（`deliverables-check` 反查）⇒ 任何"归档 = 移走"的方案
  必须让脚本认识新家，否则反向锁失效。
- **rejected 的现状是最疼的**：09-26 有一场动议中途卡死、另一场重跑共用 `renewal-y-2026`，
  产物**两场混装**而三态判据看不出（[memory-convergence-2026-09-26 README §边界 1](../../../snapshots/archive/memory-convergence-2026-09-26/README.md)）。
  若当时话题带状态（第一场标"已废弃"），撞车在盘面上一眼可辨。⇒ 状态不是锦上添花，是防混装的护栏。

### 一个需要先想清楚的概念拆解：用户说的三个词其实跨了两个轴

`notes/` 的 proposed/implemented/rejected/archived 是**开发文档**的生命周期，直接照搬会串味——
wochen 的动议是**决议**，不是代码。拆开看：

| 轴 | 管什么 | 现状 | 候选词表 |
|---|---|---|---|
| **产物态** | 这份稿走到哪一步（drafting / final'd） | **已有**（三态 + `present` 背书，机器可查） | 不动 |
| **决议结果** | 动议对**事**的结论 | 只活在 final 正文一句话里，无结构化字段 | ~~`已定稿`/`已否决`/`已搁置`/`已落地`~~ **原四词已被试金证伪（覆盖率 19%），重构方向见评审修正 3 + 试金节** |
| **位置** | 档案还在不在活跃视野 | 活跃 = 留在 `deliverables/` 根；归档 = 随轮整盘切片进 snapshots（按**轮**切片，不按话题） | live / archived |

要点：`archived` 是**位置轴**（可以机械执行：git mv）；`rejected`/`implemented` 是**决议结果轴**
（语义判断，只能 CEO/人标）；两者**正交**——一个 rejected 的话题也要归档，一个 implemented 的
话题迟早也归档。混在一个目录枚举里（如 `deliverables/rejected/<slug>/`）会让"结果"被迫等于"位置"。
本卡倾向：**结果进元数据字段，位置用目录表达**（沿 `_backlog` 的「位置即状态」精神，但只借位置轴）。

### 未决（四问）

- **该不该**：方向用户已给（要日期、要 metadata、要状态归宿）；**词表/命名/事实家归属**三决策点未拍板（见候选）。
- **何时**：本卡不依赖姊妹卡，可先行；但若与"复活 A 方案（日期注入）"合并做，则带上了机制改动面。
- **次序**：20 个存量话题的迁移是一次性脚本活；新话题从哪天开始用新形状 = 实施日（无技术依赖）。
- **放弃**：仅当用户裁决"目录改名churn 不值"——那么退守 B3（纯台账+生成索引），日期仍进不了树。

## 候选与取舍

### ① 日期怎么进树（命名）

| 方案 | 形状 | 代价 / 收益 |
|---|---|---|
| **A1 出生即带日期** `deliverables/2026-09-26-sea-entry-2026/` | CEO 建目录时就写日期 | **死结：CEO 没有时钟**——出生时它只知道 `日期待核`，目录名会先带占位再改名（两次 churn，且占位目录名难看）；否。⚠ **耦合注（2026-09-29）**：若日期卡 D2'（启用出厂 time-context）落地，死结解除——模型读到注入的真日期再命名（是读不是猜），A1 复活为真候选；命名取舍等日期卡毕业后再定 |
| **A2 收敛时补日期**（原倾向；**盲审后带前置条件，见评审修正 1**） | 动议期 = 裸 slug 目录（与今天相同）；**轮末收敛时**（维护者已经在做日期回填与台账同步的同一个动作）`git mv` 成 `YYYY-MM-DD-<slug>/` | 日期来自会话日志（权威），单写者（维护者），零机制改动；churn = 每话题一次改名；历史稿件里的旧路径引用按「历史稿不追改」保留；与 notes/、_backlog 的"时间轴在文件名上"同构。⚠ **代价修正（盲审实测）**：~~D20 判据按 slug 不按路径不受影响~~ 不成立——slug 从目录名推导，改名后反向锁三连误报 + slug-unledgered 全量误报 + authorship-audit 报废 ⇒ **前置 = 判据侧 slug 归一化补丁 + 改名红绿用例**，A2 的"低成本"标签作废 |
| **A3 永不改名，日期只进 meta** | 目录名永远 = slug；日期是 meta 首字段 | 零 churn；但"第一眼看时间轴"就要求开文件——用户的原始诉求（一眼看到日期）满足度最差 |

A2 的一个真实代价要点名：**改名发生在收敛时**，意味着"进行中"的话题在树上看不出起始日——
但这恰好与台账/`日期待核` 口径一致（进行中 = 日期未核），收敛后时间轴立即完整。

### ② 元数据载体（机器可读、供今后打整）

| 方案 | 形状 | 代价 / 收益 |
|---|---|---|
| **B1 每话题 `meta.md`**（机器可读行风格，照 `派活行` 先例） | ~~原字段样例（含 `present：-`）~~ **已被评审修正 4/5 + 第二轮合成模板取代——现行形状见"meta 合成模板"表**；CEO 动议开局建（开局字段），收敛时维护者回填（收敛字段） | 话题自带户口，不依赖中心表；角色可读可写（纯文件）；新门禁可查（meta 与台账一致性、词表合法性）|
| **B2 final.md front-matter** | 元数据写进成品首部 | final 出现得晚（否决/半途而废的话题没有 final）；且 final 是"对外文本"，掺机器字段串味；否 |
| **B3 只留台账**（现状+生成索引） | 台账是唯一家，脚本从它渲染任何索引 | 零新文件；但已实证**中心表会漏**（5 个新话题无行），且树上看不到；用户的 metadata 诉求基本没满足 |

**本卡倾向 B1+B4**：meta 是家、台账是视图。这直接回应"今后打整方便"——清理/迁移/审计扫 meta 即可，
不用 parse 散文 final。风险：又一个要维护的脚本；若评审认为过度，可退 B1+台账双写靠门禁对齐（两份事实，
靠检查不靠生成——次选，违反一处事实一个家的纪律，不推荐）。
