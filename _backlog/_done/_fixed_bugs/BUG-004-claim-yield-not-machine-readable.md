# BUG-004：占位约定可裁但不可机判——让位无机器可查标记 + 占位后重读对手文件非强制

> 严重级别：P2（次要——行为面本次成立，缺口在可审计性与仲裁的可靠性依赖自觉）｜发现：2026-10-06（多人 UX bug 猎捕 S3，用户立项）｜状态：活跃 — 已修复 2026-10-06：①手册写盘守卫行内原行扩写两句（占位后必读同组对手 + 让位首行「让位=认领撤销，非出稿」同款一字不差——195 行预算内、手册字节 19381B 余量充足）；②deliverables.mjs 立 PLACEHOLDER_YIELD_LINE + isPlaceholderYield（spec 2 例红→绿，35/35 全量 321/321）；③claim-race-probe 判据校准 v3（持认 = 首行≠标准让位行 ∧ 占位在场——正文叙述性提及让位 ≠ 撤销持认）+ 复跑 3 轮真模型行为验证：run2 = 双方都读对手文件 + CFO 门持认带证据链「占位 ∧ ¬让位」+ COO 门**首行标准让位行**完美格式 + 让位记录含事件时间戳表 + 「不产出 T1 正文、不覆盖 drafts/cfo.md、不重复劳动」；run3 = **PASS（恰一人持认）**——手册两句生效、行为面与格式面双绿。收据 = 修复 commit。

## 症状

排练实测（`scripts/probes/claim-race-probe.mjs` run1，cfo/coo 两根会话同时竞速先到先得的 T1）：

- **行为面成立（正面半边）**：两会话都先在自己文件落「占位=认领」→ 都去读了对方的文件（盘面可见性路径都走了）→ **后见者（CFO 门）读到 COO 占位后正式让位**——文件升级 v2 写「让位记录 · T1」并转干自己的 T2；COO 完整拿下 T1。约定的仲裁途径真实生效。
- **缺口半边一（可机判性）**：手册钉死了占位行格式（首行一字不差「占位=认领，非出稿」——机器可查），**让位没有任何规定格式**——CFO 的让位是自由文本（「让位记录」标题）。结果：任何机械判读（审计、探针判据、未来的门级提示）都无法把「占位后让位」与「占位持认」分开——本次探针 v1 判据就把让了位的 cfo.md 误判成持认领，报了假 FAIL。
- **缺口半边二（仲裁可靠性）**：并发窗口内**双占位真实发生过**（两会话各写占位互不见）——收场靠的是双方占位后**自觉**重读对方文件（手册没有这条动作要求）。本次两个会话都恰好做了；任何一个不重读就终稿，终态就是真双认领。约定的安全性当前依赖行为自觉，不是规矩。

## 根因（假设）

占位约定的设计止步于「可查」（占位行格式）没到「可裁」（认领归属的机器可判状态机）；per-role 占位文件互不可见 ⇒ 并发窗口天然存在；「占位后读同组对手文件」这条仲裁动作没写进手册（收工留痕节只写了占位格式）。

## 暴露的失败类

约定型协作的**半机械化类**：声明（占位）有格式、撤销（让位）无格式 ⇒ 审计闭环断在撤销端。同族横切面：互审稿命名（-review.md 有格式）、任务板认领（team_task claim 是 CAS 全机械）——两个邻居都比占位约定机械化程度高。

## 修复关联

最窄落点 = **手册层两句话**（不改机制）：①让位标记格式——让位时把首行改写为「让位=认领撤销，非出稿」（与占位行同款一字不差，机器可查）；②占位步后**必须重读同组对手文件**再决定持认或让位（把 run1 的自觉行为升为规矩）。配套 = 判读支持（audit/探针认 claimed = 占位 ∧ ¬让位）。任务板 CAS（team_task claim）是更彻底的机制路径，但两根会话是否共享任务板（per-team vs per-workspace）未核——升格前先验。
