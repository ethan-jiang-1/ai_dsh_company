# 推敲：台账面板的 UX 深挖（真浏览器探索 → 修/立卡 → 判据）

## 这是什么（自说明，给没摸过这个仓库的人/Agent）

「台账」是公司页（`conversation.view` 里的「公司」整页视图）四个子页之一，实现 = `packages/company-pack/src/client/LedgerTab.tsx`（156 行）。
它把 `kb/motion-ledger.md` 里的**动议表**按行列出：标题 / 日期 · 类型 · 参与 / 一句话结论（两行钳制 +「全文」按钮）。
**它不是成品目录**——这是本轮最重要的订正，见下节。
**谁在用**：公司角色（CEO 等）与维护者——查"某场动议定了什么"、这家公司累计决策过什么。
**现在长什么样**：尚未开浏览器（见「验证计划」第 0 步）。

## 本轮范围（收缩后）

1. 真浏览器打开台账，量**已受控的事实**是否在渲染层成立：40 行首屏是否完整、"全文"按钮是否真出现在
   量到溢出的那 16 行上、展开/收起是否稳定（这几点读码说"应该对"，但**没有任何 keyless 判据钉住真文件**）。
2. 真实任务：从动议表里挑一行（如 `role-boundary-diagnosis-2026`，摘要 525 字），计时"**说清这场动议
   定了什么**"——这才是这个面板的真实任务。
3. 三态截图：首屏 / 展开一行全文 / 空态或读取失败态；逐张读图。
4. 发现的明确缺陷：同 diff 修 + 判据，或立 BUG 卡。
