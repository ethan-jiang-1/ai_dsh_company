# 推敲：台账面板的 UX 深挖（真浏览器探索 → 修/立卡 → 判据）

> 立卡：2026-10-19 ｜ 状态：推敲中 ｜ 类型：Task ｜ 毕业：未定 ｜ 可关闭：否

## 这是什么（自说明，给没摸过这个仓库的人/Agent）

「台账」是公司页（`conversation.view` 里的「公司」整页视图）四个子页之一，实现 = `packages/company-pack/src/client/LedgerTab.tsx`（156 行）。
它把公司盘里的**成品交付物**按行列出：日期 / 类型 / 参与 / 墙钟 / 成品 / 一句话结论。数据面 = `remote.workspaceFiles`
（**文件驱动**，和培养页签同款；读 `company-workspace/deliverables/*/meta.md` 与 `deliverables-archive/*/meta.md`）。
**谁在用**：公司角色（CEO 等）与维护者——它是"**找某份成品**"的入口，也是"这个公司到底交付过什么"的全景。
**现在长什么样**：先跑起来看一眼（见「验证计划」第 0 步），本轮不预设结论。

## 为什么它排第一（意图：先摘最容易摘到的大果）

| 证据 | 数值 | 出处（可复核命令） |
|---|---|---|
| 真实条目数 | **993**（当前 98 + 归档 895） | `find company-workspace/deliverables company-workspace/deliverables-archive -type f \| wc -l` |
| 数据面性质 | **文件驱动**（确定性好，真数据现成，不用造种子） | `LedgerTab.tsx` 头注 + `remote.workspaceFiles` 用法 |
| 历史痛点 | **7 份**文档提到 `LedgerTab`（全公司面最高） | `grep -rl LedgerTab notes/ _backlog/ docs/` |
| 交互面 | 仅 1 个交互点（几乎纯只读） | `grep -c "onClick\|onSubmit\|onChange" LedgerTab.tsx` |

**推论（待验，不许当结论引用）**：992 条真数据 + 只读 + 文件驱动 ⇒ 这是**现在唯一能拿真数据压规模**的面板
（培养面板那 300 条是合成负载），也是"找成品"这一真实任务最可能被规模拖垮的地方。

## 本轮范围

1. 真浏览器打开台账，**量**：首屏渲染条数与耗时、能否滚到底、有无折叠/筛选/按日期分组/搜索控件。
2. 用**真数据**做一个真实任务并计时：「找到 2026-10-17 那份临港预审的成品，并说出它的参与角色与结论」。
3. 三态截图：首屏 / 中部 / 尾部 + 空态或加载态；逐张读图记录"第一次用的人会怎么想"。
4. 发现的**明确缺陷**：同 diff 修（带判据：keyless 或新场景档）或立 BUG 卡（带现场证据）。

## 范围外

- 不改台账的**信息架构**（要不要合并 `deliverables` 与 `-archive`、要不要改字段）——那属产品决策，实测后另开卡。
- 不动 `meta.md` 的写法与归档流程。
- 不做用量/在场面板（见父卡「不做」段）。

0. 前置：`source run/env.sh` → 起 web（`pnpm dsh web`，token URL 从启动横幅读）→ 公司页 → 台账子页。
