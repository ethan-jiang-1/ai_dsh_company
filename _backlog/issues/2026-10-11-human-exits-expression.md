# 推敲：对人的出口面·表达层——高管消化漏斗与 DSH 底层支撑

> 立卡：2026-10-11 ｜ 状态：推敲中 ｜ 类型：Feature ｜ 可关闭：否
> 同日拆卡：说什么（语言规范）= [语言层卡](2026-10-11-plain-language-human-exits.md)；本卡只管**以什么形呈现**。
> 用户定性（2026-10-11）：「毕竟是助手，大量内容如何让高管快速消化和决策」。

**问题与期望结果：** 语言层解决"出口说的是人话"；本卡解决"人话以什么形到达高管——十秒定向、
一分钟消化、随时下钻、拍板只需点一下"。期望结果 = 表达模型（四层漏斗 + 五机制，逐条映射
DSH 底层支撑）与借用/不做清单成稿，用户挑定后与语言层卡同 diff 或分批转实施。

**当前情况：** 表达层盘点已完成（vendor tag dsh-v0.2.0-rc.2 源码 + 活体槽树 cordis_inspect 双核实）。
核心发现：**高管消化所需的呈现支撑大半已在底层、零代码可用**，我们缺的是"用起来"（runbook 一句、
persona 表达款）而非新机制；本仓自建件（八页签/委派卡/公司视图）在公司场景已是生态先例。

**表达模型（推敲产物——四层漏斗）：** 高管消化的不是"全部内容"，是漏斗；每层一句职责、
上层链接下层：

| 层 | 职责 | 载体（现有） |
|---|---|---|
| **十秒层** | 定向：公司怎么样、有什么等我 | 右栏页签（待办/台账/在场）+ present 卡描述 |
| **一分钟层** | 消化：结论/下一步/要拍板 | CEO 回复人话首段 + final 一分钟摘要 |
| **十分钟层** | 审阅：对比、分歧、边际宽度 | final 报告体（表格化） |
| **取证层** | 信任：出处、复算 | drafts/sources（只有争议时才进） |

**五机制（漏斗的运转件，全部有底层支撑）：**
1. **决策成卡**：凡"要拍板"必 `ask_user_question`（选项 label=动作、description=一句后果），
   散文只给背景——拍板从阅读任务变点击任务，卡自然进「待办」收件箱。
   （V4 反例：拍板事埋在 1473 字收口回复尾部的散文里。）
2. **对比成表**：≥2 选项的取舍一律 GFM 表格（选项×维度、每格短語）——聊天原生渲染
   （ui-primitives `MarkdownText` = GFM+TeX）。V4 final 四象限表已是正例。
3. **数字带锚**：人话段关键数字挂 `[数字](final.md#L24-L30)` 锚链接——一步到依据，
   信任靠点击不靠通读（ui-chat §Reference previews：文件链接点开即右栏预览，含行号定位）。
4. **过程折叠**：管理层浏览器 TranscriptView 切「紧凑」（Settings → General；compact 折过程行、
   只露最终回答，偏好随浏览器持久化）——"agent 密度对人折叠"的原生解；配右栏钉「待办」「台账」
   页签（浮窗摆位有几何记忆，本仓 float-geometry）。
5. **细节外链**：**会话是谈话、文档是文档**——CEO 聊天回复保持短（人话首段+链接出去），
   长形住 final/drafts；侧栏预览全家桶兜底（markdown 分页、**电子表格浏览器直开**、
   Word/PPT 本地转 PDF、PDF/HTML/图片——ui-sidebar-documentpreview，支持面比手册 rc.2 收割条目写的宽）。

**未决问题：**
1. 机制 1/2/3 是 persona/手册文案款（与语言卡 A3 同 diff 可落）——确认即做？
2. 机制 4 的 runbook 落点：demo.md §前置 vs multi-human.md 开门节（合同层一处，实施时定）。
3. open-in-app 挂不挂：host+client 两包成对（`dsh-host-open-in-app` + `ui-open-in-app`，
   会话头/预览头"在默认应用打开"）——Excel 党一键原生打开交付物；两行 + client-load 验证。
4. LedgerTab 长行 clamp（自语言卡迁来，治标小补）随哪批做。
5. 观察项（不立项）：聊天内嵌图表——`MarkdownText` 不渲染 mermaid；本地图片可内联
   （pathImages 词汇），CEO 写 SVG 图表文件+引用理论可行；先看表格+台账够不够再议。

**下一步：** 用户挑定未决 1–4（5 留观察）⇒ 与语言卡同 diff 或分批出实施申请。

## 范围与排除项

- 只管**对人的呈现形**；语言规范 = 语言层卡；agent 间通信形态不动（用户明裁双轨制）。
- 不重造 UI：八页签/委派卡/公司视图已在；本卡不新增大 UI 面。

## 已知与未决

- **诚实缺口：assistant 长文不折叠**——过程折叠只盖工具/过程行，不折助手自己的长散文
  ⇒ 由机制 5 补（回复短、长形外链），不开"换渲染器"的口子。
- **表达 pattern 借鉴**（生态里"有意思的表达"，作原则记，不搬代码）：**渐进披露**
  （Turn Process Folding 折过程露答案；ui-workflow-run 披露树 run→phase→member、完成层默认闭合；
  DisclosureRow 原子）——与四层漏斗同构，"结论层常显、细节按需展开"；**状态即文本+语义色**
  （workflow-run 成员行：dot+name+状态列，本仓页签已同款续用）；**一份事实多视图**
  （chat/trajectory/公司三视图 + 预览渲染器选择 = 双轨制的 UI 形）。
- **生态盘点边界（诚实记账）**：离线可核 = vendor 全量 + 出厂 bundle + 本 harness 可装清单
  （同一包族）；社区插件市场不可离线浏览、未盘点。最接近的官方协作件 client-ui-agent-team 已借。

## 方案与取舍

- **做（建议默认全收未决 1/2/4；3 听刚需）**：机制 1–5 的文案款与 runbook 句（零代码）；
  open-in-app 两行收割（视未决 3）；LedgerTab clamp（未决 4）。
- **不做**（输掉的方案，防重议）：
  - turnDataSource 轮末"摘要脚注"扩展位（ui-chat §Completed-turn footer）——CEO 回复已是摘要，
    再挂脚注 = 同信息第二事实源；
  - `tool.view.cordis` 交互卡（cordis_run 卡内交互区）——无当前刚需，登记为未来"可点人话卡"机制位；
  - 换 `conversation.chat.node` 渲染器做人话皮肤——大手术、治标、维护面随上游漂；
  - 引入图表库——ui-demo 先例裁决：零依赖 SVG/CSS 够用，图变大再议。

## 关闭条件

表达模型 + 借用清单获用户确认，未决 1–4 有拍板，实施申请已记录去向；或用户裁定不做/延后并写明条件。
