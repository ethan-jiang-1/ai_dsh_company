# 推敲：对人的出口面·表达层——高管消化漏斗与 DSH 底层支撑

> 立卡：2026-10-11 ｜ 状态：等人拍板 ｜ 类型：Feature ｜ 可关闭：否
> 同日拆卡：说什么（语言规范）= [语言层卡](2026-10-11-plain-language-human-exits.md)；本卡只管**以什么形呈现**。
> 用户定性（2026-10-11）：「毕竟是助手，大量内容如何让高管快速消化和决策」。

**问题与期望结果：** 语言层解决"出口说的是人话"；本卡解决"人话以什么形到达高管——十秒定向、
一分钟消化、随时下钻、拍板只需点一下"。期望结果 = 表达模型（四层漏斗 + 五机制，逐条映射
DSH 底层支撑）与借用/不做清单成稿，用户挑定后与语言层卡同 diff 或分批转实施。

**当前情况：** 表达层盘点已完成（vendor tag dsh-v0.2.0-rc.2 源码 + 活体槽树 cordis_inspect 双核实）。
核心发现：**高管消化所需的呈现支撑大半已在底层、零代码可用**，我们缺的是"用起来"（runbook 一句、
persona 表达款）而非新机制；本仓自建件（八页签/委派卡/公司视图）在公司场景已是生态先例。

**表达模型（四层漏斗候选，待实施申请纳入）：** 高管消化的不是"全部内容"，是漏斗；每层一句职责、
上层链接下层：

| 层 | 职责 | 载体（现有） |
|---|---|---|
| **十秒层** | 定向：公司怎么样、有什么等我 | 右栏页签（待办/台账/在场）+ present 卡描述 |
| **一分钟层** | 消化：结论/下一步/要拍板 | CEO 回复人话首段 + final 一分钟摘要 |
| **十分钟层** | 审阅：对比、分歧、边际宽度 | final 报告体（可用表格等合适结构） |
| **取证层** | 信任：出处、复算 | drafts/sources（只有争议时才进） |

**五机制（现有底层能力；按场景选择表达结构）：**
1. **决策成卡**：**阻塞型中途拍板 + 收口时的拍板事**必 `ask_user_question`（选项 label=动作、
   description=一句后果），散文只给背景——拍板从阅读任务变点击任务，卡自然进「待办」收件箱；
   **非阻塞中途项不拦人**（带显式默认假设继续、轮末摘要列「待人确认」——与手册「问询节流」
   对齐，防"别烦我"复发）。（V4 反例：拍板事埋在 1473 字收口回复尾部的散文里。）
2. **对比成表（有条件默认；DSH 原生 GFM）**：多个选项需要按共同维度权衡时，用短 GFM 表格（选项×维度、单元格写短语）；只有两个简单选项，或窄屏表格会降低可读性时，用短列表。V4 final 四象限表是正例。
   （ui-primitives `MarkdownText` = GFM+TeX）。
3. **数字带锚（仅关键数字）**：可将关键数字链接到 `[final.md#L24-L30](final.md#L24-L30)` 作为查证入口；这是取证入口而非每个数字的装饰，重复数字、背景数值不要求单独链接。
   链接可打开右栏预览并定位文件行（ui-chat §Reference previews）。
4. **过程折叠**：管理层浏览器 TranscriptView 切「紧凑」（Settings → General；compact 折过程行、
   只露最终回答，偏好随浏览器持久化）——"agent 密度对人折叠"的原生解；配右栏钉「待办」「台账」
   页签（浮窗摆位有几何记忆，本仓 float-geometry）。
5. **细节外链**：**会话是谈话、文档是文档**——CEO 聊天回复保持短（人话首段+链接出去），
   长形住 final/drafts；侧栏预览全家桶兜底（markdown 分页、**电子表格浏览器直开**、
   Word/PPT 本地转 PDF、PDF/HTML/图片——ui-sidebar-documentpreview，支持面比手册 rc.2 收割条目写的宽）。

**推敲结论（按用户确认；具体批次实施仍需授权）：**
1. 机制 1/2/3/5 的内容和表达合同与语言层卡同批定义；由 CEO persona/手册落规则，不增加第二事实源，不做自建 UI。
2. 机制 4（紧凑 TranscriptView + 钉住常用页签）操作说明并入 `docs/demo.md` §前置，因为这是公司观察窗的统一开门操作，属于 demo 合同；`multi-human.md` 只在多人形态专属流程需要时链接，不复制步骤。
3. `open-in-app` 不需配置改动；作为批 3 的现场观察，核实出厂入口实际可用，再把已验证的出厂能力补进公司手册。若现场不成立，先记录环境/运行态证据，不自行改上游或假设机制坏了。
4. LedgerTab clamp 与可访问全文入口归批 3，不当作内容长度治理替代。现状 title 只提供悬停提示，不能作为键盘/触屏全文查看的验收。
5. 聊天图表继续观察，不纳入本次实施申请；仅当表格+链接无法支持真实动议表达时，凭样本另开推敲。

**剩余待决：**无影响本轮规划的产品选择。批 2 采用上述有条件表格默认与关键数字链接规则；通过场景检验例外是否清楚、能否避免窄屏横向滚动和无意义的链接噪声。其他已确认边界：三批顺序；两卡共用一份 RFC；行为场景先立，真实模型有界观察，长期语料/遵从率暂缓。

**与语言层卡的批次交接（2026-10-11，本轮用户确认建议默认及次序）：**
- **批 1｜来源治理**：本卡不增加独立实现；遵循语言卡批 1，摘要来源归 meta/台账 owner（用户已决定不设长度硬门禁）。
- **批 2｜表达规范**：采用四层漏斗；阻塞拍板用 `ask_user_question`；有多个选项需按共同维度权衡时默认短 GFM 表，简单二选或窄屏退化为列表；对关键结论/复核数字给文件行锚，不要求重复或背景数字逐项加锚；会话回复给短首段，详情进入 final/drafts；对话流自身不承诺折叠 assistant 长文。
- **批 3｜浏览和显示**：紧凑模式开窗走查与 runbook；LedgerTab 有界行显示 + 非 hover 全文入口；核实 open-in-app 后补公司手册说明。不新增插件/渲染器、不引图表依赖。

## 范围与排除项

- 只管**对人的呈现形**；语言规范 = 语言层卡；agent 间通信形态不动（用户明裁双轨制）。
- 不重造 UI：八页签/委派卡/公司视图已在；本卡不新增大 UI 面。

## 已知与未决

- **诚实缺口：assistant 长文不折叠**——过程折叠只盖工具/过程行，不折助手自己的长散文
  ⇒ 由机制 5 补（回复短、长形外链），不开"换渲染器"的口子。
- **表达 pattern 借鉴**（生态里"有意思的表达"，作原则记，不搬代码）：**渐进披露**
  （Turn Process Folding 折过程露答案；ui-workflow-run 披露树 run→phase→member、完成层默认闭合；
  DisclosureRow 原子）——与四层漏斗同构，"结论层常显、细节按需展开"；**状态即文本+语义色**
  （workflow-run 成员行：dot+name+状态列，本仓页签已同款续用）；**一份事实多视图**
  （chat/trajectory/公司三视图 + 预览渲染器选择 = 双轨制的 UI 形）。
- **生态盘点边界（诚实记账）**：离线可核 = vendor 全量 + 出厂 bundle + 本 harness 可装清单
  （同一包族）；社区插件市场不可离线浏览、未盘点。最接近的官方协作件 client-ui-agent-team 已借。

## 方案与取舍

- **做（依用户确认分三批）**：批 2 的表达规范与批 3 的 runbook/显示改进；
  open-in-app 无需组合改动（已在组合，现场核实 + 收割清单补记）；LedgerTab 有界显示与全文入口。
- **不做**（输掉的方案，防重议）：
  - turnDataSource 轮末"摘要脚注"扩展位（ui-chat §Completed-turn footer）——CEO 回复已是摘要，
    再挂脚注 = 同信息第二事实源；
  - `tool.view.cordis` 交互卡（cordis_run 卡内交互区）——无当前刚需，登记为未来"可点人话卡"机制位；
  - 换 `conversation.chat.node` 渲染器做人话皮肤——大手术、治标、维护面随上游漂；
  - 引入图表库——ui-demo 先例裁决：零依赖 SVG/CSS 够用，图变大再议。
