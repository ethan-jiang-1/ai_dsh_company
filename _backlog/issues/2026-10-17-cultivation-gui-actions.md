## 现场事实（两问的答案）

### ①「命令没挂上」= 那个实例没装包，不是命令坏了

[实测 2026-10-17] 我所在的 GUI 就是用户提问的那个：`http://127.0.0.1:3080`，`DSH_HOME=/Users/bowhead/.dsh`、
`DSH_PROFILE=web`。三条独立证据：`~/.dsh/profiles/web/package.json` 的 `dsh.profile.bundles` 里**没有** `dsh-company-pack`；
我这个会话的工具面里**没有**本包工具（`cultivation_propose` / `request_signoff` 双双缺席，而它们由本包 host 面无条件注册）；
`lsof` 实测全机两个 HTTP 实例 = 3080（日用）与 3083（`/Users/bowhead/ai_dsh_deep_research` 的 research profile，cwd 实证），
**本仓没有 dev web 在跑**。⇒ 在那儿敲 `/cultivation …` 只是一行普通文本，不解析；不是命令面坏了。

这条事实的既有唯一家 = [demo.md §前置 1](../../docs/demo.md)（原话：日用 `~/.dsh` 里也有个同名 `web` profile，
装的是日用插件集、没有公司五角色）；自检一行 = `source run/env.sh && pnpm dsh --profile web --dump-config | grep -c company-pack` ≥ 1。

dev 组合里命令面确实是挂着的：培养机制探针判据④（`commands/list` 含 `cultivation`，且 `correct` 真落记录到公司盘）
在 2026-10-13/15 实跑 ALL PASS——收据 = [agent-cultivation-loop](../../notes/implemented/2026-10-13-agent-cultivation-loop.md) ⑤，
探针 = [cultivation-method-layer-probe.mjs](../../probes/session-context/cultivation-method-layer-probe.mjs)。

### ② 面板里的命令是**纯文本**，板没有动作面

三壳（公司页第四子页 / 侧栏页签 / 浮窗）共用 [CultivationBoard.tsx](../../packages/company-pack/src/client/CultivationBoard.tsx)，

UI→host 动作通道（remotes 选择面由 vendor 组装、dynamic cordis = session-scoped 且 trust 等同 bash）⇒ v1 用命令族 =
平台原生『人侧直控面』；按钮留待上游开放通道后另立卡引用本 Note」。**本卡就是那张另立的卡**（2026-10-17 补立）。

## 机制核证（原否决的前提被证伪）

[读码，钉版 vendor] 平台**有**原生的人侧动作通道，而且 vendor 自己就在用：

- 会话面：`SessionFace.command(line)`（`vendor/dsh/packages/api/session-controller/src/client/contract/session.ts:147`）——
  注释写明「Execute one slash-command line against this session's agent… outcomes render as flow nodes, never as a
  response echo」，实现 = `remote.commands.execute(sessionId, line, [])`，只回 `{ matched }`。
- 同款先例：`vendor/dsh/packages/client/ui-permission-presets/src/client/index.ts:126` 用
  `sessions.binding(sessionId)?.session.command('/permission <preset>')` 驱动一条真命令；同文件另有一个
  `commandUi.decorate` 的 `popupSelect` 先例（裸 `/permission` → 选择器 → 选中提交完整命令行）。
- host 端每条命令都记 `command/run` + `command/done`，且**来源一律 `source: { kind: 'user' }`**
  （`vendor/dsh/packages/interaction/commands/src/index.ts` 的 `execute`）——与人敲命令同一事件、同一份留痕。
- `remote.commands.execute` 返回完整 `CommandExecution`（`result.kind` + `result.text`），即 host 写的中文话术原话；
  `SessionFace.command` 内部调它、但把文本丢掉。
- 远程面由 vendor 装配（`vendor/dsh/packages/api/remotes/src/client/index.ts:8` 引 `commandsRemote`）⇒ **不需要 pack 自造 remote**。
- 命令行的**多行能力**：`parseCommand` 的名字正则允许命令名后跟换行，`rawInput` 原样保留；本包 host 的 `splitBody`
  只按**第一个 `::`** 切分（正文里再出现 `::` 无妨；「期望行为」那一句里不能有）。

槽位归属也已核：`sidebar.right.pane.tab` = keyed + `scope: 'session'`
（`vendor/dsh/packages/client/ui-sidebar-right/src/client/index.ts:217`）⇒ 页签体天然带自己会话的 `sessionId`。
客户端测试基座：本仓 `tests/client/` 全是 `renderToStaticMarkup` 静态渲染，**没有 jsdom/交互层** ⇒ keyless 只能证
「按钮在场 / 只读降级 / 线构造」，「点了真落盘」必须真浏览器（`client-load-smoke` 只证挂载、不点按）。

## UX 视角：谁、在什么时刻、想干什么（2026-10-17 换位重写）

### 使用者的三个真实时刻（不是一个）

| 时刻 | 人在干什么 | 心里的问题 | 界面现在给了什么 |
|---|---|---|---|
| **T1 读完收件箱** | 一次动议/一轮会话收尾后，看看有没有人给我提了东西 | 「这条在说什么？凭什么？我该采纳吗？」 | 只有 kind + 一句话期望 + 标题 + 出处；正文（证据）读进来了却不显示 |
| **T2 同类任务跑完之后** | 刚才那个活儿，方法到底有没有用上？ | 「有效吗？该不该留？」 | 什么都没有——`verify` 要自己想起来、还要手打 id |
| **T3 发现方法不灵/走偏** | 某个角色又按老毛病干了一遍 | 「怎么把这条撤掉？」 | 什么都没有——`revoke` 要自己想起来、还要打对 slug |

**这条换位思考的第一结论：四个动作不属于同一个时刻**，把它们平铺成四个同等地位的按钮是错的。
`adopt`/`reject` 属于 T1（当下有注意力）；`verify`/`revoke` 属于"事后"（T2/T3），而事后恰恰是最容易忘、
也最需要被"提示到"的时刻。培养回路能不能真跑起来，取决于 T2 有没有人回填——这是整个回路最容易死的地方。

### 六个状态：人从"看到"到"服气"要走完的一段路

1. **发现**：得先知道"有活给我"。现在「需要我处理」和 journal 待审、赞踩、「怎么养」四块平铺堆在一个面板里，
   新人第一眼分不出哪个是"要我动手的"。→ 待办必须在最上、且只列给我的。
2. **判断**（最容易被体验打回的一步）：人不敢盲采纳。他需要**证据原文**（提案正文）、**谁提的**（本人还是分身、
   哪个角色）、**影响面**（采纳后哪些会话会带着它开工）。现在正文读进来了（`readRecord` 2000 字窗）却只在行里
   显示 `title` + `expectation`。→ v1 必须能就地展开看正文（数据已具备，零新增读取）。
3. **下判**：采纳应当**轻**（一键、可逆），拒绝应当**重**（要写理由——等于你欠提出者一个解释）。
   重的那个不能显得麻烦：给快捷理由（"口径不符/已有方法/暂不需要"）+ 可自由写。
4. **回执**：点完必须"落地"——行从待办区挪到已采纳区，并留一行"谁/什么时候/成了什么方法"。
   **不能让行原地消失**（消失 = 人以为丢了）。
5. **生效预期**（误解高发点）：采纳改的是**未来新开的该角色会话**，不是当前这段对话。
   这句话必须出现在**点击之后的回执里**，不是埋在使用说明里——否则"我点了怎么没反应"是必然的。
6. **事后验证**：`verify` 是这条回路的闭环。没人填，方法层就只涨不验（面板已区分"未验证 ≠ 已掌握"，
   但没有任何提示）。→ v1 至少让"未验证"显眼且一键可填；怎么在最合适的时刻提醒（T2）留到第 2 轮。

### 判断所需的四条信息（决定 v1 的信息密度）

谁提的（本人纠正 / 哪个角色的建议 / 哪个角色的分身）｜为什么提（期望行为一句话）｜证据原文（正文，可展开）｜
影响面（采纳后进哪个角色的方法层、何时生效）。这四条现在数据面全都有，缺的只是**呈现**（准确说：正文被挡在读模型之外，见 G2）。

### 人的输入清单 × 每个条目的把手（无困惑审计，2026-10-17 补）

判据来自用户口径：**① 分身需要的外部输入都要容易"进去"（提交/选择/采纳）；② 不让任何"看到却不知道去哪操作"的条目存在；
③ 不熟悉的人能很快掌握**。逐条审计画面上会出现的东西：

| 人要给分身的 | 载体 | 今天从哪进 | 入口好找吗 | 给完之后 |
|---|---|---|---|---|
| 纠正：教自己的角色一条做法 | 记录 `kind=correction` | `/cultivation correct …`（命令） | ✗ 只有命令 | 进本人收件箱 → 本人采纳 |
| 建议：教别的角色 | 记录 `kind=suggestion` | `/cultivation suggest <角色> …` | ✗ 只有命令 | 落对方收件箱 → 对方本人采纳 |
| 采纳 / 拒绝 | 记录 `status` | `/cultivation adopt｜reject` | ✗ 只有命令 | 方法部署 / 理由留档 |
| 验证：这条方法到底有用吗 | `record.verification` | `/cultivation verify <id> pass｜fail` | ✗ 只有命令 | 面板显示已验证 |
| 撤回：方法不灵了 | 方法目录删除 | `/cultivation revoke <slug>` | ✗ 只有命令 | 新会话不再加载 |
| 赞 / 踩：对某条回复的即时评价 | feedback 事件 | 消息上的 👍/👎 | ✓ **已有**（平台原生） | 面板「人的赞踩」块实时显示 |
| journal 素材：会话里学到的东西 | `kb/<角色>/journal/*.md` | 分身自己写 | 不需要人给 | 轮末人审收敛进 CHARTER——**面板没入口，也没"不用你管"的标注** |
| 公司事实：交付物 / KB | company-workspace | 人直接写文件 | 不属本面板 | 由手册约束 |

**审计出的四个缺口（v1 必须关掉的困惑源）**

- **G1 创作没有入口**（判据 ①）：纠正/建议只能敲命令。**我上一轮建议"v1 不做创作面"是错的判断**——它把
  「人给分身输入」的一半留在命令里，正是判据 ① 要消掉的东西。⇒ 创作面进 v1。
- **G2 判断没有材料**（判据 ②③）：正文（提案全文）**被读模型刻意挡在客户端之外**——
  [cultivation.ts](../../packages/company-pack/src/lib/cultivation.ts) 的 `recordBody` 注记写着
  「Return the persisted proposal body without exposing it in the Client record view」，所以面板只能显示正文首句
  （`title`）。人只能盲判。⇒ v1 要把正文带进读模型 + 就地展开；这条要**修订那条设计注记**，理由写进 Note。
- **G3 不需要你动的条目没有标注**（判据 ②）：journal 素材块和「我提交的 · 待对方处理」行看起来都像待办，
  但前者要等轮末收敛、后者归对方处理。⇒ 改框架与文案（素材 ≠ 待办；「等对方处理，你无需操作」）。
- **G4「自己写的纠正还要自己再点一次采纳」**（判据 ③）：自己提交的纠正进自己的收件箱，同一个意图要两步。
  这两步本身是**有意**的（先记下、再决定部署，留痕），v1 的化解不是自动化，而是**提交后把新行高亮、且就近有采纳按钮**
  （一个视野里走完）；「记下来并采纳」要 host 回结构化 id，列 v1.1。

## 交互设计草案（v1：面板决策面）

**待处理行**（`status: open` 且归我的角色）：

```
[CEO分身的纠正]  ★ 收口前逐项列出未决项
   做法：收口盘点先列未决清单，按 owner 分行…（点「展开」看全文）
   出处：deliverables/xxx/final.md · 2026-10-16
   ［采纳］ ［拒绝］
```

**已采纳行**：

```
method-r-2026… ［未验证］
   收口前逐项列出未决项 · 采纳于 10-16 · 新开的 CEO 会话会加载它
   ［这条有用］ ［没起作用］        （= verify pass / fail，文案用人话，不用 pass/fail）
   ［撤回…］                        （次要位置；点了先展开后果说明再确认）
```

要点：**待办行只放两个主动作**（采纳/拒绝）；验证与撤回在已采纳行，且撤回是次要位置——
减少一屏四键的误触面。非角色会话（viewer 缺席）不出死按钮，维持现在的"请选择负责的角色"。

**失败态（三种，都要给原话 + 指路）**：

| 触发 | 现在会发生什么 | v1 要显示 |
|---|---|---|
| 跨角色采纳（按钮按在了别的角色会话） | host 拒绝 | 「这条归 CFO，请在 CFO 的会话里采纳」+ 一个"去那个会话"的动作（可选） |
| 记录已被处理/撤回后再点 | host 拒绝 | 「这条已经处理过了」+ 建议重读（自动刷新一次） |
| 方法 slug 重名 | host 拒绝 | host 原话 + 提示换个方法名（将来给"改名采纳"入口） |

**撤回的后果说明**（比"再点一次确认"更重要）：撤回 = 删掉该方法目录 + 该记录**不能再被采纳**（host 的 adopt
只收 `open` 态）+ 新开的该角色会话不再加载它；运行中的会话不受影响。确认界面把这四句说清，再让点"确认撤回"。

**不改的东西**：host 命令语义与角色闸、记录文件格式、「采纳只对新会话生效」的事实。

## 迭代框架：脊柱与可 churn 面

用户口径是"框架按长期迭代、别一下咬死"，所以先把**不打算动**和**准备被改**的分开：

| | 内容 | 为什么 |
|---|---|---|
| **脊柱（不改）** | 记录文件与 frontmatter 格式；host 命令族语义与角色闸；"一个动作 = 一条记录上的一个决定"；人侧留痕（`source: user`） | 这些是数据与权限面，改了会让已有记录/方法失效 |
| **可 churn（预计每轮都改）** | 入口位置（面板行 / 裸命令弹窗 / 会话内卡片）；按钮文案；分组与排序；空态；确认的形态；是否展开正文的默认值；批量 | 这些是体验面，改它们不动机制、不动已有数据 |

**单向门 vs 双向门**（决定"现在必须想清楚"还是"以后随便改"）：

- 单向门（现在就定）：V1 只做"人对自己角色的记录下判"——不引入跨角色代判、不引入自动采纳阈值、不引入批量。
- 双向门（留给反馈）：按钮长什么样、放在行内还是行尾、验证用"有用/没用"还是"通过/未通过"、
  撤回是两段确认还是弹窗、待办要不要按"分身提的 / 人提的"分组。

**为迭代留的代码缝**（写进实施口径，避免第二轮重做机制）：
① 动作面抽成纯模块（线构造 + 结果折算 + **一处集中的文案表**）——文案是迭代里改得最多的东西，必须集中；
② 三个壳只做"取数据 + 传回调"，薄到换壳不动机制；③ keyless 判据只钉**行为**（点后会发出哪条命令、
失败时报什么），不钉外观（外观交给真浏览器探针与视觉夹具）。

## v1 的 UX 完成定义（人可观察，不用看代码）

1. 新人不看说明，能在 30 秒内指出"哪几条是给我的"，并说出其中一条要它做什么。
2. 不抄任何 id，能完成一次采纳，并在点击后**正确回答**"什么时候生效"（答案 = 新开的该角色会话）。
3. 拒绝一条时不需要写作文（快捷理由可用），且回执里能看到自己的理由留档。
4. 一次失败（跨角色/已处理）后，能说出"为什么没成、下一步该去哪"。
5. 能看出"哪些已采纳的方法还没验证"，并完成一次回填（用"有用/没用"的人话）。
6. 不看说明能自己提交一条（给自己的纠正、或给别的角色的建议），并知道它去了哪、下一步谁动。
7. 扫一眼面板，没有"看到却不知道去哪操作"的条目：要么就地有把手，要么明确写着"不用你操作/等谁处理"。

## 体验协议（写好后怎么找人试、看什么）

- **对象**：2–3 人，其中至少 1 人没用过培养面板（新人是主要信号源）；1 人可以是熟悉命令族的自己人（对照组）。
- **任务**（只说目标，不教操作；观察者不插话，卡住 60 秒才提示）：
  T1「找出要你处理的，并说说其中一条在讲什么」→ T2「把它采纳掉」→ T3「说出什么时候生效」→
  T4「拒绝另一条并写下你的理由」→ T5「跑完一个同类任务后回填验证」→ T6「撤回一条，说出后果」。
- **记录什么**（下一轮的输入）：每个任务耗时与卡点；有没有去会话里翻回执；原话里出现的问题
  （"这按钮按了会发生什么？""为什么没变化？""去哪个会话？"）；有没有误击撤回/拒绝。
- **反馈落到哪**：观察记录进本轮毕业 Note 的验证节；据此排第 2 轮的改动清单（见下节预案）。

## 预测会被打回的地方（第 2 轮预案，先想好免得慌）

1. **"我看不到它到底要我干什么"** ⇒ 正文展开做成默认展开前 N 行（而不是折叠按钮）。
2. **"没人会想起验证"** ⇒ 在会话收尾处提示（机制面另议：可能是面板角标 + 会话末尾的一句提醒），或把
   "未验证"条数放进面板标题徽标。
3. **"拒绝太麻烦"** ⇒ 快捷理由按钮 + 理由可空（host 现在要求非空，需与 host 语义一起改，属另一个切片）。
4. **"入口找不到"** ⇒ 加裸 `/cultivation` 弹窗装饰（把命令本身变成能点的），或把培养入口从右栏页签提到会话头部。
5. **"我一次要处理十条"** ⇒ 批量采纳（但批量会放大误触，需配合更强的信息密度，放第 3 轮）。

## 推敲（红队：漏洞、反例、边界）

1. **权限口径变了半句，机制没变**：host 不区分命令来源（远程 `execute` 一律 `source: user`）⇒「人侧」的定义从
   「人敲终端」变成「人在 UI 里发起」。守卫仍是「模型没有这个工具」，**不是**「模型不能触发 UI」。反例：本包的 peer 里就有
   `dsh-browser-use`（playwright MCP）⇒ 理论上一只带浏览器工具的分身可以驱浏览器点按钮。但这条道在按钮之前就存在
   （一样是在 composer 里打字），**本轮不引入新面**；结论 = 不能再拿「命令是人敲的」当绝对句，
   研究稿那句「不把前端隐藏按钮当安全保障」继续成立。
2. **静默失败**（第一号 UX 风险）：`command()` 只回 `matched`；跨角色、记录不存在、方法重名等 host 错误都在 `result.text` 里，
   客户端看不到。UX 结论 = **失败必须可读**，这把通道选择从"分层偏好"变成"体验必需"（见待裁点 2）。
3. **会话身份**：`scope: session` 已核；但「浮窗是否仍是同一 scope」与「面板开着时切换会话」实施时必须实测。
   按在错会话上会被 host 角色闸拒（安全），但用户看不到原因 ⇒ 回到第 2 条。
4. **并发/重复点击**：host 侧 `installMethod` 独占建文件（返回 false 即不覆盖）+ 记录 `open` 态守卫 ⇒ 第二击不会损坏数据；
   客户端仍要飞行中禁用 + 完成后重读。
5. **误触面变大**：多人合同早写了「同一台机器上谁都能按那个按钮」（[multi-human.md](../../docs/multi-human.md)「多人合同」节）；
   按钮把「一键采纳」摆进待办列表。UX 缓解 = 待办行只放两个主动作、撤回进次要位置且说明后果、按钮带对象（`采纳`后面跟着期望行为）。
6. **两个互动面**：面板按钮与裸 `/cultivation` 弹窗（`commandUi.decorate`，vendor 有 `/permission` 的 `popupSelect` 先例）
   服务不同时刻；v1 只做面板，弹窗列为第 2 轮候选（预案 4），避免一份行为两套交互同时返工。
7. **文案纪律**：本包 client 面历来硬编码中文（vendor 的 locale 字典规则是 vendor 包纪律）——本卡既不追齐也不扩大该偏离；
   但文案必须集中在动作面模块里一处（迭代要改的就是它）。
8. **生效边界**：见 UX 六状态的⑤；撤回后**新**会话不再加载（运行中会话是否刷新不是合同主张，
   探针实测 watcher 会刷新，但文案不得承诺「立刻全局生效」）。

## 输掉的方案

- **pack 自有 business Remote**（面板 → 自定义 host RPC）：仍然做不到（remote 选择面由 vendor 装配）——但本卡不需要它。
- **只做「复制命令到剪贴板」**：零权限争议，但用户问的是"能不能点"，且复制后仍要切输入框粘贴回车；性价比低。
- **四个动作平铺成同等按钮**：看起来最"完整"，但违背"动作属于不同时刻"，且放大误触。
- **一次就做「创作表单 + 面板动作 + 命令弹窗 + 批量」**：一轮吞掉四个时刻的交互，反馈无法归因。
- **只做表单一类创作面**：用户的原话冲着面板待办来的，方向反了。
- **越层只为一个 toaster 拿回执**：见待裁点 2——现在收进"体验必需"的论证里，而不是分层口味。

## 范围与排除项

- **v1 做**（若批准）：治理动作（采纳/拒绝/验证/撤回）+ **创作面**（纠正 / 建议表单）+ 判断材料（正文带进读模型并就地展开）+
  无困惑重排（G3：素材与待办分开说）+ 回执与生效说明 + 失败可读 + 只读降级 + 动作后刷新 + keyless 判据 + 真浏览器验收 +
  体验协议与 Note/合同痕迹。
- **v1 不做（要动 host 语义，逐个列 v1.1+）**：记录里加「出处」字段（今天人经命令写的记录 `source` 恒为「（会话内提交）」，
  要能填出处就得改命令语法）；拒绝理由可空（host 现要求非空）；「记下来并采纳」（要 host 回结构化 id）；
  「撤回我提的建议」（状态机没有撤回态）；批量采纳；跨角色代判；自动采纳阈值。
- **不做**：盲弹窗装饰（第 2 轮候选）；多人身份/认证隔离；把 pack 装进日用 `~/.dsh`
  （release 安装路径另议，见 [安装手册](../../_dist/安装手册.md)）。

## 落地切片（S1–S6；每片一个红绿环、一片一 commit）

顺序按「最堵的先通、最便宜的先吃、判断要先有材料」排；每片的完成定义 = 该片最窄检查实跑绿 + 上一片不回归。

| 片 | 内容 | 关掉哪个缺口/判据 | 证据（先红） |
|---|---|---|---|
| **S1 动作面纯模块**（无 UI） | 线构造（correct / suggest / adopt / reject / verify / revoke）+ 结果折算（host 原话 → 成功/失败文案）+ **文案表集中一处** + 通道封装（走 `remote.commands.execute`，局部最小面 + 单独注入块，缺席即降级） | 判据 ② 的失败可读；后续所有片的共同地基 | 新 keyless spec：边界输入（期望句含 `::`、正文含换行与 `::`、理由含换行）、error → 文案、未匹配 → 不可用 |
| **S2 面板治理动作 + 回执** | 待办行「采纳/拒绝」（拒绝内联理由）；已采纳行「这条有用/没起作用」+「撤回…」（后果说明 + 两段确认）；飞行中禁用；成功后刷新；失败行内出 host 原话；未注入即只读降级 | 判据 ①②（治理这半进面板） | `cultivation-board.spec.ts` 增（桩动作面断言线内容/按钮在场/角色不符不出/降级）+ `client-load-smoke` |
| **S3 无困惑重排**（只动结构与传统文案，最便宜） | 待办置顶且只列给我的；journal 块改「素材（不用你操作）+ 什么时候谁会动它」；「我提交的」加「等对方处理，你无需操作」；赞踩降到次要；「怎么养」改写为"点哪里做什么"，命令语法收进折叠的「熟手命令行」 | 判据 ②③（G3 的直接答案） | 静态渲染断言（关键文案与块序）+ 视觉夹具 |
| **S4 判断材料** | 读模型带正文（改 lib + 其往返 spec），面板就地展开（默认展开前 N 行，不藏按钮） | 判据 ②③（G2：不敢盲判） | `tests/company` 读模型新断言（正文在场且往返）+ board 渲染断言 + 探针截图 |
| **S5 创作面** | 面板顶部「给你的角色留一条方法」/「给别的角色提建议」→ 表单（期望行为单行 + 正文多行 + suggest 选角色 `Pill` + 校验：非空、期望句不得含 `::`）→ 提交后刷新并**高亮新行**（G4） | 判据 ①（G1：创作入口） | 表单/board spec（校验与线内容）+ 真探针走一次创作提交 |
| **S6 真机验收 + 体验档** | 探针：①采纳成功 ②跨角色失败出原话 ③创作提交后记录落盘；截图；随后按「体验协议」跑人 | 判据 ①②③ 的人机共评 | 探针判据 + 体验观察记录进毕业 Note |

**为什么是这个顺序**：S1/S2 先通"最堵的采纳类"（你最初的问法）；S3 最便宜却直接吃判据 ②③，所以排在创作面之前；
S4 必须早于"逼人下判"的完整体验（没有材料就是逼人盲判）；S5 补齐判据 ① 的另一半（创作）；S6 收口并给下一轮喂料。

**host 面影响：v1 零语义改动**——唯一碰到 host 面的是 S1 从 `remote.commands.execute` **读**它的返回；
所有"要动 host 语义"的（出处字段、理由可空、记下来并采纳、撤回我提的建议、批量）都在范围外逐条列明。

**为第 2 轮留的缝**：S1 的文案表（迭代改得最多的就是它）；S3 纯文案/结构（不改逻辑）；S5 表单是独立组件
（将来可换成弹窗或会话内卡片）；keyless 只钉行为、外观归真浏览器档。

**已知风险**：面板会变长（可能需要折叠/分组，属双向门）；真页面探针导航脆（降级口径见验收节）；
多行正文控件要本包自写（ui-primitives 无 textarea，属新增 UI 面）。

## 待裁点（请用户逐条裁定；已按 UX 视角重排）

1. **v1 切片的范围（修订）**：治理四动作 + 创作面 + 判断材料 + 无困惑重排（推荐——按判据 ① 创作面必须进，
   否则"人给分身的输入"仍有一半留在命令里）｜ 只做治理四动作（上一轮的建议，现不推荐）。
2. **失败可读性（体验必需，不是架构口味）**：用 `remote.commands.execute` 让面板行内显示 host 原话（推荐）｜
   用 `session.command()` 只拿 `matched`，失败时提示"看会话回执"（更贴平台 UI 会话面，但人得去会话里翻原因）。
3. **v1 的入口数量**：只做面板（推荐，先验一个入口的失败/刷新语义）｜ 只做裸 `/cultivation` 弹窗（命令本身变成能点的）｜
   两者都做（两个时刻各一入口，但两套交互同时返工）。
4. **撤回的安全设计**：说清后果 + 两段确认（推荐）｜ 只加确认不说后果 ｜ 不确认（与命令行一致，但一键删方法）。
5. **验证的时机**（可延后但不该忘）：v1 只把"未验证"做实 + 一键回填（推荐）｜ v1 就加"事后提醒"（需要在会话收尾处
   找挂点，属机制面新缝）。
6. **S3「无困惑重排」要不要进 v1**：进（推荐——它是判据 ②③ 最便宜的答案，只动结构与传统文案）｜ 留到第 2 轮
   （但那样第一轮体验里，journal 素材块与「我提交的」还会看着像待办）。
