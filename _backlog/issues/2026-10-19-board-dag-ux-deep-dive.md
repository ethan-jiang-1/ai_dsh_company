# 推敲：看板 + 依赖图的 UX 深挖（正确性优先：板面必须等于投影真值）

> 立卡：2026-10-19 ｜ 状态：推敲中 ｜ 类型：Task ｜ 毕业：未定 ｜ 可关闭：否

## 这是什么（自说明）

「看板」与「依赖图」是公司整页视图的两个子页，实现都在 `packages/company-pack/src/client/company-panels.tsx`
（`BoardPanel` / `DagPanel`，与在场、用量合在同一文件，共 374 行）。数据面 = 会话的**团队投影** `agentTeam`
（`rows.agentTeam.val`：成员 + 共享任务列表，含 owner / 状态 / 依赖 / 修订号）。
**谁在用**：CEO/维护者把它当"公司现在在干什么"的**指挥视图**——看错 owner、状态或依赖，就会**指挥错**。
**渲染**：看板 = 按状态分列的任务卡；依赖图 = 任务节点 + 依赖边（`fitScale` 缩放适配宽度）。

## 为什么它排第二（以及为什么它的风险性质与台账不同）

| 证据 | 数值 | 出处 |
|---|---|---|
| 投影覆盖面 | **1722 / 1738** 会话带 `agentTeam` | 扫 `runtime/harness-home/storages/session_projcache/sessions/*.json` |
| 真实任务量 | 共 **379** 个任务；非空会话 **84**；**最大板 21 条**；中位 **0** | 同上（`rows.agentTeam.val.tasks` 长度统计） |
| 交互面 | 几乎纯只读（各 0–1 个交互点） | `grep -c "onClick\|onSubmit\|onChange" company-panels.tsx` |
| 历史痛点 | `BoardPanel` 2 份、`DagPanel` 1 份 | `grep -rl <组件名> notes/ _backlog/ docs/` |

**风险性质**：只读 ⇒ 不会误操作；但它被当**指挥视图** ⇒ 失败模式是**看错**（渲染/口径与投影不一致）、
**看不到**（空态/加载态/陈旧）、**看不完**（21 条时的换行与列高）、**窄栏读不出**（依赖边与长标题）。

## 本轮范围

1. **正确性判据（本卡的核心）**：拿一条真实会话的 `agentTeam` 投影，断言看板/依赖图里显示的任务数、owner、状态、
   依赖边与投影**逐项一致**（不是"看起来对"，是断言）。
2. 三态：空板（0 任务）/ 加载态 / 21 条大板 —— 各一张截图 + 读图记录。
3. 窄栏（右栏拖窄到最小可用宽度）下看板列与依赖边的可读性；长标题换行。
4. 刷新语义复核：面板自称的刷新间隔/图例文案与实际一致（培养面有过"文案说 5s 实际 30s"的先例，这里**必须**核）。
5. 发现的明确缺陷：同 diff 修 + 判据，或立 BUG 卡。

## 范围外

- 不改任务投影本身（`agentTeam` 的产生面）与其 schema。
- 不做拖拽改状态、不做任务编辑（那是新功能，不是 UX 深挖）。
- 不碰任务板表格（另卡：`2026-10-19-taskboard-table-ux-deep-dive.md`）。

## 验证计划（步骤级）

0. 前置：`source run/env.sh` → 起 web → 公司页 → 看板 / 依赖图子页。
1. 选**最大真实板（21 条）**对应的会话；用 RPC 读该会话的 `agentTeam` 投影，落一份"真值快照"。
2. 在页面上按 aria/结构取出板面任务数与每张卡的 owner/状态；与真值快照逐项比对 ⇒ 断言（差异 = 缺陷，带截图）。
3. 依赖边：投影里的依赖关系式（A → B）在图上是否存在（抽 3 条比对）。
4. 三态截图（空板 / 加载 / 21 条）+ 窄栏一张；逐张读图。
5. 收口：门禁 + 真入口复跑 + 结论回填。

## 验收标准（毕业门票）

- [ ] **存在一条可复跑的"板面 = 投影真值"断言**（任务数 + owner + 状态 + ≥3 条依赖边），并在真数据下跑绿；
- [ ] 空板 / 加载 / 21 条 / 窄栏四态有截图 + 读图记录；
- [ ] 刷新语义与图例文案经核对（一致 ⇒ 记录；不一致 ⇒ 修文案或修行为，带判据）；
- [ ] 明确缺陷：同 diff 修 + 判据，或立 BUG 卡；门禁与真入口复跑绿；记录/索引同步 + push。

## Review 指南（给 review 的人/Agent）

- **要证伪的假设**：① "板面与投影一致"（这恰恰是本卡要证的第一件事，先别信）；② "最大板 21 条不成问题"
  （21 条在窄栏里可能就是糊的——要图）。
- **口径**：本卡只认**投影真值**做基准；截图审美争议不算缺陷，**不一致才算**。
- 复核命令：`python3 -c` 扫 `session_projcache`（见父卡/调研文档给出的取法）。
