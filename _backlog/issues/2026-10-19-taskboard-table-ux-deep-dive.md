# 推敲：任务板的 UX 深挖（与看板口径一致性 + 入口可发现性）

> 立卡：2026-10-19 ｜ 状态：推敲中 ｜ 类型：Task ｜ 毕业：未定 ｜ 可关闭：否

## 这是什么（自说明）

「任务板」有两副面孔，都在 `packages/company-pack/src/client/TasksPanel.tsx`（162 行）：
① **会话头部的入口按钮**（点开 = 打开右栏的平台任务板页签）；
② **页签体表格视图** `TasksTableView`（纯展示）：成员行 + 共享任务表（owner / 依赖 / **修订号** / 状态标签 待办·进行中·完成·已删）。
数据面与看板**同源**（`agentTeam` 团队投影）。
**谁在用**：角色/维护者在会话里想"我该干什么、谁在等谁"时点开它。

## 为什么它排第三（不是不重要，而是与看板强相关）

| 证据 | 数值 | 出处 |
|---|---|---|
| 真实任务量 | 同看板：379 任务 / 最大板 21 条 | 扫 `session_projcache` 的 `rows.agentTeam.val.tasks` |
| 交互面 | 1 个交互点（入口按钮）——比看板多一条"点了打不开/开错地方"的失败面 | `grep -c "onClick..." TasksPanel.tsx` |
| 历史痛点 | 2 份文档提到 `TasksPanel` | `grep -rl TasksPanel notes/ _backlog/ docs/` |

**为什么单独立卡**：它与看板**同源不同视图**——同一个任务在两处显示，**不一致就是 bug**；
而且它多了**入口按钮**（可发现性 + 键盘可达）这条看板没有的失败面。同源两视图的口径漂移是最隐蔽的一类缺陷。

## 本轮范围

1. **一致性抽样**：抽 3–5 个真实任务，比对"任务板表格"与"看板卡片"的 owner / 状态 / 依赖 / 修订号是否一致
   （不一致 ⇒ 缺陷，带两侧截图与投影真值）。
2. **入口可发现性**：会话头部入口按钮——找得到吗（首屏可见/需要悬停才知道）、键盘可达吗（Tab 顺序 + Enter 打开）、
   打开后落点对不对（右栏任务板页签，不是别处）。
3. 21 条表格下的列宽/换行/是否可滚到底；状态标签与"已删"的呈现。
4. 三态截图（0 任务 / 加载 / 21 条）+ 读图记录。
5. 明确缺陷：同 diff 修 + 判据，或立 BUG 卡。

## 范围外

- 不做任务编辑/拖拽/筛选（新功能）；不改表格数据面（投影）；不重复看板那一轮的渲染问题（看板卡负责）。

## 验证计划（步骤级）

0. 前置：`source run/env.sh` → 起 web → 进一条**有任务**的会话（真值快照法同看板卡）。
1. 取真值快照（投影）→ 打开任务板页签 → 按结构读表格行 → 逐项比对（任务数 / owner / 状态 / 依赖 / 修订号）。
2. 与看板交叉比对同一任务（两处一致性）。
3. 入口按钮：键盘 Tab 到它 → 焦点可见？Enter 打开 → 落点是否为右栏任务板页签？
4. 截图 + 读图；收口门禁与复跑。

## 验收标准（毕业门票）

- [ ] 存在**一致性判据**（任务板 vs 看板 vs 投影三方，≥3 个任务逐字段一致）并在真数据下跑绿；
- [ ] 入口按钮：可发现性 + 键盘可达 + 落点正确三件都有断言；
- [ ] 三态截图 + 读图记录；
- [ ] 明确缺陷：同 diff 修 + 判据，或立 BUG 卡；门禁与真入口复跑绿；记录/索引同步 + push。

## Review 指南（给 review 的人/Agent）

- **要证伪的假设**：① "同源两视图必然一致"（本卡首要证伪对象）；② "入口按钮显然看得见"（没跑的人不知道）。
- **口径**：一致性以**投影真值**为唯一基准；样式分歧不算缺陷。
