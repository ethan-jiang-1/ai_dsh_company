# 推敲：对人的出口面统一「人话翻译段」——语言规范层（双轨制）

> 立卡：2026-10-11 ｜ 状态：等人拍板 ｜ 类型：Feature ｜ 可关闭：否
> 同日拆卡：呈现/渲染与 DSH 表达件支撑 = [表达层卡](2026-10-11-human-exits-expression.md)；本卡只管语言。

**问题与期望结果：** 用户 2026-10-11 两轮裁决：①「Agent 上下文对 Agent 挺好，对人不行——CEO
或任何角色进来的是人话业务，对模型知识不一定充分，吐出来的必须让常人管理层一读就懂」；
②「内部内容用 Agent 习惯的没问题，但最后总得有一段翻译给人一下子抓明白的」⇒ **双轨制**。
期望结果：每个**对人的出口面**固定携带「人话段」（复用既有三件套形状：结论 ≤3 条业务语言 /
下一步 谁·何时 / 要拍板的事），agent 间通信（drafts、任务书、成员消息）保持密度不动。
本轮推敲完成 = 出口面清单、规范落点、判据方案与不做清单成稿，用户拍板后转实施申请。

**当前情况（证据，2026-10-11 实测）：**
- 已 normed 的面：final 首屏「一分钟摘要」+ present description（手册 2026-10-10 批单）；
  CEO persona 同款硬要求；decision-memo 模板带禁词款（禁 闸门/T号/锚/等级/slug）。
  V4 final 摘要与 CEO 收口对话回复（1473 字，session 日志实取）基本合格——**对话流出口现状不差**，
  仅尾部漏「机制事实」黑话（workspace_doors=2、闸门 grep 误伤）。
- **重灾区 = meta「一句话结论」→ 台账行 → 台账页签链**：V4 meta 一句话结论实测 **835 字**单链句
  （全库 norm 72–100 字；吸收 handoff 2026-10-11 §3 待落卡项①），直灌管理层常驻面板
  （[LedgerTab](../../packages/company-pack/src/client/LedgerTab.tsx) 整行渲染 `row.summary`，无 clamp）。
  台账行随动议复杂度退化：最长 sea-entry 184 字、realtime-recon 165、renewal-u 157，
  夹 κ>0.70 / allowed-once / fail-closed 等内部术语。
- 模板在推密度：[templates/meta.md](../../company-workspace/templates/meta.md) 要求「一句话结论」
  「数字带【事实/假设】标注」——诚实标注的义务该住 final 报告体，灌进行内人话正是 835 字的成分之一。
- ask 卡文案：手册已有「把上下文备到人能一眼决定」总则；V4 无 live 样本（授权走普通用户消息），未核。

**DSH 盘点结论（用户点名先做；vendor tag dsh-v0.2.0-rc.2 + 活体槽树 cordis_inspect 核实）：**

「给人生成摘要」的机制件**（session-title 是标题非内容摘要；`conversation.chat.node` 按节点类型
换渲染器可换整条消息流，属大手术且治标）。⇒ 杠杆在**内容面规范 + 判据**，不再挂 widget。
判据基建现成：deliverables-check 词表/占位闸门先例（META_TYPES / G1–G4）、replay 行为场景、
corpora 独立标注先例。

**推敲结论（按用户本轮确认）：**
1. 不设一句话结论的硬字数上限；不以 100/120 字作机械判据，也不截断。V4 活跃 meta 的 835 字行是已确认反例，批 1 要改成准确、适于台账扫描的业务短句；长度问题通过规范和实际阅读判断治理。
2. 只修 V4 活跃长行；现存其他历史台账行不追改。新行遵循定稿规范；归档目录沿用现有历史豁免，不追溯门禁。
3. 先交付规范与来源治理，不声称已证明模型遵从或人话质量。批 2 为语言要求立代表正例与反例场景；真实模型观察采用有界单场，不将其纳入快速回归。语料标注/长期遵从率暂缓，触发条件为规范已使用一场且仍出现可复现的表达失败。
4. ask 卡问题及选项同批纳入 A3：问题写清待决定事项，选项 label 用可执行动作、description 写一句关键后果；只有阻塞性选择才打断当前推进，非阻塞事项带明示假设继续并在收口列待确认。

## 方案与取舍

- **A 规范层（主体，建议做）**：统一原语 = 既有「三件套」，不是新发明。
  - A1 `templates/meta.md`「一句话结论」规格重写：业务语言、适于台账扫描且不设机械字数上限、
    避免机制名、口径名与内部术语；**【事实/假设】标注义务移到
    final 报告体**，行内条件性用自然语言（「条件估算」「未实测」）。
  - A2 `kb/motion-ledger.md` 头部维护规矩补同款一句；台账行 = meta 一句话结论的引用不改写。
  - A3 CEO persona 补款：对人的收口回复 = 人话首段三件套，机制细节（工具名/门禁/判据号）
    折「另：」尾段或进 final；ask 卡问题与选项用业务语言。
  - A4 手册总则：双轨制一句话（全员适用，不只 CEO）——落点实施时定：并入「成品首屏说人话」
    条目扩写（不加行）优先，行预算顶格不许净增行。
- **B 行为验收层（让 A 不靠自觉）**：
  - B1 不增加禁词或长度门禁；语言质量由行为场景与人的判读验收。
    V4 的 G2 已证明子串禁词会误伤叙述性用词，避免以黑名单代替语义验收；
    语言质量走场景与人工判断，不宣称由机械门禁证明。
  - B2 行为场景：replay 场景先立代表正反例；真模型行为只作有界观察，语料标注暂缓。
- **C（已迁表达层卡）**：LedgerTab 行 clamp 等呈现面事项 → [表达层卡](2026-10-11-human-exits-expression.md)。
- **D 不做**（输掉的方案）：① 翻译中转 agent——加时延加成本、破坏「写的人负责翻译」的单一 owner；
  ② 把 drafts/成员通信改浅——用户明裁内部保持 agent 习惯（那是好上下文）；
  ③ 上游提 seam——上游无此件且这是内容面事，不构成机制缺口。
  （换 chat.node 渲染器做人话皮肤等**呈现层**否决项见表达层卡，不在此重复。）
