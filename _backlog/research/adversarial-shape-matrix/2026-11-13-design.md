# 对抗性边界矩阵 + 跨载体一致性 spec

> **结论先行**：问题不是 spec 数量，是 spec 的**形状**。现有 238 个 spec 是「每个模块在自己的夹具上证明自己的行为」；缺的是「所有载体在同一组敌意形状上证明同一个不变量」。补三类资产 + 一道门禁；P0 只覆盖三个 choke point，不按 66 张卡逐张补测试。
>
> **路径约定**：`新建:` 前缀 = 本文提出的计划落点，当前树不存在；其余反引号路径均为现行文件。

## 1. 现状：资产很多，但都是「实现形状」

|---|---|---|
| 测试体量 | `tests/` 27.8k 行 > pack 源码 22.2k 行；238 spec / 1827 tests | 不是「写得少」 |
| 缺陷来源 | BUG-080..146 共 66 张（除 140），**66/66 出自探索卡** | 回归套件在缺陷存在期间一直绿 |
| 形状覆盖 | `tests/` 40 文件 / 248 处 `.dsh-company` 字面量；只有 13 个 spec 提 symlink | 形状覆盖按模块各自手写、稀疏且不均 |
| 负例来源 | 52 个 spec 带「负例留证」注释 | 负例是**发现之后**补的回归钉 |
| choke point | 三条收敛判据 **282 行**（company-root 202 / safe-file 44 / write-gate 36），只有 **1 个 spec 69 行、4 个形状** | 共享入口本身没有接口级契约测试 |
| 载体数量 | **23 个 src 文件 / 55 处** `.dsh-company` 字面量 + 15 个 `RUN_BUNDLE_PATHS` 消费者；**6 个写入口自拼路径 + 自做 temp/rename** | 同一事实被 N 个载体各自解释，收敛判据可被绕过 |

一句话：**现有 spec 是实现的回声**。回声能确认你说过的话，不能告诉你哪里说错了。

## 2. 三种资产 + 一道门禁

### A. 世界形状库（shape library）：把「敌意环境」变成可构造的输入

不是 66 个 bug 的用例集，是 5 条轴的可枚举值。轴从卡里归纳，但**不按卡列**：

| 轴 | 值（首版） | 代表卡 |
|---|---|---|
| 根形状 | 缺失 / 普通目录 / 文件 / symlink→外 / symlink→内 / 中间目录 symlink | 129、134 |
| 叶形状 | 缺失 / 普通文件 / 目录占位 / symlink→外 / symlink→内 | 122、132、138 |
| 内容形状 | 合法 / 空 / 截断 JSON / 坏 JSON / 旧 schema / 缺字段 / 超预算 / 非 UTF-8 | 123、085 |
| 生命周期 | 新鲜 / 二次运行 / 两 writer 交错 / stale lock / gate blocked / 重启 / temp 后崩溃 | 101、106、115、144 |
| 权威/来源 | 用户写 / 模型写 / 旧版 / workspace 外 / 派生 vs 权威不一致 | 090、109、125 |

每个 shape = `{ id, axis, apply(): { ws, outside, cleanup }, expected, catches? }`；构造器返回可清理的 workspace + 一个**外部目录**（用来断言「没写到外面」）。落点 `新建:tests/support/world-shapes.ts`。

### B. 不变量矩阵（invariant matrix）：判据不是行为，是性质

| 不变量 | 断言 | 抓的卡 |
|---|---|---|
| **Safety** | 任意形状下，写入口要么写进根内，要么抛/返回 typed refusal；外部目录字节不变 | 122/128/129/131/132/134/135/136/137/138/142/143 |
| **Agreement** | 同一形状下，所有读载体归一到同一等价类（ok / missing / unsafe-or-corrupt）；允许的偏离必须显式登记 | 109、123、127、130、134、136 |
| **Atomicity** | 失败注入后旧字节完整；临时件不被读成数据；目录替换不是先删后建 | 110、114、138 |
| **Idempotence** | 第二次运行字节不变 / 不重复追加 | 101、143 |
| **Non-destruction** | unsafe / missing 上不做破坏性动作（revoke / purge / export） | 090、091、114 |
| **Convergence** | 派生视图 = f(权威文件)；权威坏时不产生「干净空」 | 103、109、118、145 |

矩阵的骨架（`新建:tests/host/contract/` 下）：

```ts
// 期望表是审过的政策，不从实现导出
const POLICY = {
  'root-symlink-out': 'unsafe',
  'leaf-dir': 'unsafe',
  'json-corrupt': 'corrupt',
  missing: 'missing',
} as const

describe.each(SHAPES)('shape: $id', (shape) => {
  it.each(WRITERS)('$id never writes outside', (writer) => {
    const { ws, outside, cleanup } = shape.apply()
    try {
      const result = capture(() => writer.run(ws))
      if (result.kind === 'ok') expect(insideOnly(ws, writer.writes)).toBe(true)
      expect(outsideUntouched(outside)).toBe(true)
    } finally { cleanup() }
  })
})
```

一致性 spec 的关键是**归一化**，不是让载体返回同一个字符串：

```ts
const toClass = {
  companyFileProblem: (v) => v ?? 'ok',                  // null = 可读；类型里的 'corrupt' 从不产生（待修）
  companyFileProblemAt: (v) => v ?? 'ok',                // 'unsafe' | 'missing' | null
  plainFileProblem: (v) => v === null ? 'ok' : v === 'missing' ? 'missing' : 'unsafe',
  readCompanyText: (v) => v === undefined ? 'unreadable' : 'ok', // 更粗：missing/unsafe 都折成 unreadable
}
// 不变量：所有载体在 ok / not-ok 上一致；not-ok 内部允许更严或更粗，但必须在 allowedDivergence 里声明
```

### C. 载体登记（carrier registry）：一张地图，防止新载体绕过

`新建:tools/lib/carrier-registry.mjs`（纯数据；tests 可 import `tools/lib` 纯逻辑，gate 是 `.mjs`——单家）：

```js
export const CARRIERS = [
  { id: 'catalog.regenerate', module: 'src/host/ledger/catalog.ts', symbol: 'regenerateCatalog',
    kind: 'writer', companyRoot: true, coveredBy: 'company-root-matrix' },
  { id: 'company.fileProblem', module: 'src/host/run-bundle/company-root.ts', symbol: 'companyFileProblem',
    kind: 'reader', companyRoot: true, coveredBy: 'file-shape-agreement' },
  // …
]
export const EXEMPT = [
  { module: 'src/host/logging/rotating-log.ts', reason: '写 runtime 日志，不在公司盘' },
  { module: 'src/host/workspace/workspace-resolution.ts', reason: '写 saved workspace 到 home，不在公司盘' },
]
export const KNOWN_GAP = [
  { module: 'src/host/ledger/governance-export.ts', bug: 'BUG-147', reason: '仍直拼 exports；P0 不修，门禁列出' },
  { module: 'src/host/run-bundle/bundle-manifest.ts', bug: 'BUG-148', reason: '仍直拼 bundle.json；P0 不修，门禁列出' },
  { module: 'src/host/cultivation/cultivation-storage.ts', bug: 'BUG-149', reason: '只校验到 cultivation 父目录；P0 不修，门禁列出' },
]
export const FACTS = [
  { id: 'company-file-shape', contract: 'docs/contracts/data-model.md', classes: ['ok', 'missing', 'unsafe'] },
]
```

**`KNOWN_GAP` 是 P0 与 147/148/149 的接口**：已知未收口的公司盘写入口登记在这里，门禁**不判红但必须在 PASS 行列出**；修完迁入 `CARRIERS`，再由 Safety 矩阵覆盖。它防的是「已知缺口静默消失」，不是「缺口不存在」。

**为什么必须登记而不是靠自觉**：BUG-144 就是「gate 靠调用点记得调」；BUG-119/121 是「新增写路径漏了」。登记 + 门禁把「记得」变成机械事实。

**盘点已经撞到第一个 Agreement 缺陷**：`companyFileProblem` 的返回类型声明了 `'corrupt'`，实现只产生 `missing`/`unsafe`；`companyFileProblemAt` 注释写 corrupt、实际返回 unsafe。两个载体对同一形状的词表不一致——这正是 Agreement spec 的第一条红证（先修词表，再谈测试）。

### D. 门禁：`新建:checks/gates/company-root-carriers.mjs`

- 扫 `src/host/**/*.ts` 里同时出现写/读原语与公司盘路径特征的模块；
- 每个命中必须在 `CARRIERS`、`EXEMPT`（带理由）或 `KNOWN_GAP`（带 bug 链接）；
- 登记里的模块/符号必须存在；`coveredBy` 必须能对上 spec 标题；
- 失败信息报 `file:line`，缺失文件报「缺失」不抛异常；
- 红证（按 [gate-change-definition](../../../.agents/skills/gate-change-definition/SKILL.md)）：在 `src/host` 加一个 `zz-probe.ts` 直接 `writeFileSync(join(ws,'.dsh-company/x'))` → 红；删文件 → 绿。

## 3. 判据怎么保持独立（这是成败点）

1. **政策表放 spec 顶部**，来源 = `docs/contracts/*` + Note，不 import 实现的常量/枚举。
2. **归一化适配器显式写**：每个载体的输出映射到 canonical class；映射不了 = 发现一个词表不一致的缺陷，先修词表。
3. **允许的偏离要声明**：`readCompanyText` 把 missing 和 unsafe 都折成 undefined 是设计选择，不是错误；但必须在 `allowedDivergence` 里写清「它更严/更粗」，否则 spec 红。
4. **红证先于绿**：每条矩阵先去掉对应守卫（root symlink 检查 / 目录占位检查 / write-gate），看它红；还原看绿。红证原话进 Note。
5. **不测错误文案**，只测 typed error 类与不变量；文案归 UI/i18n 的面。

## 5. 落地顺序（按杠杆，不按卡）

**P0（先做，1–2 人日）**
1. `新建:tests/support/world-shapes.ts`：根/叶/内容三轴的 12–16 个 shape。首版必须含盘点出的**零覆盖形状**：截断/半写 JSON、`bundle.json` 的 symlink/目录占位、`exports/` symlink、TOCTOU（判据与写入之间替换）、`*At` 变体与 `createCompanyDir` 越界分支。
2. `新建:tests/host/contract/company-root-safety.spec.ts`：`SHAPES × WRITERS`，断言「不写外 + typed refusal」。
3. `新建:tests/host/contract/file-shape-agreement.spec.ts`：4 个读载体的归一化一致性（先修上面那个 corrupt 词表）。
4. `新建:tools/lib/carrier-registry.mjs` + `新建:checks/gates/company-root-carriers.mjs` + 红证。
5. `tests/README.md` 映射表加一行：改 host 读写面 → `pnpm test tests/host/contract`。

**P1（1–2 人日）**：startup（missing/corrupt/unsupported）、cultivation（records 不可达 / revoked / 坏记录）、ledger（presented vs catalog vs 导出）三组 Agreement + Non-destruction。

**P2（1 人日）**：smoke 进程矩阵（lease 接管、崩溃半写、重启）；`docs/testing.md` §3.8 补一句「新持久化路径 ⇒ 矩阵行 + 登记」。

**不做**：把 66 张卡逐张写成 spec（又一次回归）；引入 fast-check（形状离散可枚举，属性库只增加依赖与不确定性）；5 轴全组合（爆炸，用代表形状 + 载体族控制）。

## 6. 验收标准

- [ ] 每条轴至少 1 个 shape，shape 有 id / 构造 / 清理 / 预期类。
- [ ] 每个 `companyRoot: true` 的 writer 在 safety matrix 有一行；每个 read carrier 在 agreement spec 有归一化。
- [ ] 任意 shape 下，`outside/` 字节不变（断言，不是口头承诺）。
- [ ] 新写入口不登记 → `pnpm verify` 红，信息报 `file:line`。
- [ ] 三个红证：去掉 root symlink 检查 / 去掉目录占位检查 / 去掉 write-gate → 对应矩阵红；还原绿。
- [ ] `pnpm test` 增量 < 5s；`pnpm verify` 增量 < 1s。
- [ ] 现有 238 spec 不删（P0 只加不改；去重留到 P3）。

## 7. 风险与反制

| 风险 | 反制 |
|---|---|
| 矩阵变成实现的镜像 | 期望表在 spec 顶部、来自合同；禁止 import 实现的 POLICY 常量；每族留一个红证 |
| 平台差异（symlink/FIFO） | 首版只用可移植形状（symlink / dir / 文件 / JSON）；special file 标可选 skip |
| 门禁误报 | `EXEMPT` 带理由；先观察档再升硬档；失败信息点名 |
| 维护成本 | 登记单家 + 门禁强制；不靠自觉 |
| 矩阵腐烂 | `tests/README.md` 映射 + gate；新载体不进矩阵就红 |

## 8. 与现有纪律的关系（不是新发明）

- [testing.md](../../../docs/testing.md) §3.7 `prove-it-red`、§3.8「红/场景先行」已经要求红证与红先行；缺的是**常设的形状清单**——没有清单，「红」只能来自已经知道的 bug。
- `tools/lib/surface-matrix.mjs` + [surface-matrix.spec.ts](../../../tests/evidence/surface-matrix.spec.ts) 已是「矩阵数据 + spec 断言」的先例；本设计只是把同一形状用到 fs/状态面。
- 覆盖率阈值保留，但**不把行覆盖当安全证据**；另记「轴覆盖」：每个注册载体在每个轴至少一个形状。
- 现有 238 个 spec 保留为行为回归；矩阵是新增的一层，不替代它们。
