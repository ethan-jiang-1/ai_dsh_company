# 候选方案族与假说（§6）

> 本文件 = 原第三份材料的 §6；节号沿用全局编号。返回 [当前 brief](2026-11-07-current-brief.md)。

## 6. 候选假说（并列，不排名）

### 6.0 先看方案族，再看单个 token

> 下面是"族"级别的候选，每族可以再选具体 token；不是排名，不是推荐。H1–H6 对应 S1–S6；H7（上游不编号）与 H8（UUID）是另外两族。

| 族 | 一句话 | 代表 | 可能的好处 | 可能的代价 |
|---|---|---|---|---|
| S1 种类编码 | ID 只说"是需求/接口/验证" | REQ/IF/TC | 先验强、决策少、前缀不随层增长 | 层不可见；需求可能全局分配 |
| S2 层编码 | ID 说"哪一层" | STR/SYR/IFR | 层一眼可见；分配简单 | 先验弱/错；双号诱惑 |
| S3 种类+层 | 两者都编 | SYS-REQ-001 | 层+种类都可见 | 更长；两个判断 |
| S4 文档限定 | ID 带文档码 | PRD-REQ-001 | 定义点明确；无全局分配 | 像文档号；改名成本 |
| S5 层级数字 | 用大纲号 | 1.1/2.3 | 无 token 先验问题；短 | 插入重排；种类不可见 |
| S6 全局序号+字段 | 不透明序号+type 字段 | R-0001 | 分配简单；不复用 | 外部不可读；类型靠字段 |
| S7 双轨 | 人读文档用层名，Agent 用种类号 | 文档标题+REQ/IF/TC | 人机各取所需 | 双真相/映射成本 |
| S8 OpenSpec 中心 | OpenSpec 为主，外部 ID 只做 trace | capability+Traces | 贴合 SW/FW 现状 | EE/ME/供应商没有 OpenSpec |

> 每个假说列"可能的好处/可能的代价/可能推翻它的证据"。没有任何一个被选中。

### H1 只编种类：`REQ / IF / TC`（+ `AC` / `MR` 从属）

- **可能的好处**：token 先验强；每个条目只问"是需求/接口/验证"；层由文档承载；前缀不随层增长。
- **可能的代价**：层不可见；需求可能全局分配；AC 父号耦合；跨动议要项目键。
- **可能推翻它的证据**：V2 重键后追溯不可读；V7 显示全局分配/迁移成本过高；V1 显示 `REQ` 跨层被误读。

### H2 只编层：`STR / SYR / IFR`（+ `REQ/AC` 上游）

- **可能的好处**：层一眼可见；分配简单（每层自己序列）；跨层撞号低。
- **可能的代价**：token 先验弱/错（string/航空）；同一需求两层会起两号；与用户"前缀别加"张力。
- **可能推翻它的证据**：V1 盲测第一反应错误；V4 样本出现同一需求两个号。

### H3 种类+层：如 `SYS-REQ-001`

- **可能的好处**：种类与层都可见；定义点按层明确。
- **可能的代价**：较长；两个判断；表格/Excel 宽度；与"前缀别加"冲突。
- **可能推翻它的证据**：V4 外部文档可读性差；V2 显示写作成本高。

### H4 文档限定：`PRD-REQ-001` / `SyRS-REQ-001`

- **可能的好处**：定义点在 ID 里；无全局分配；跨文档引用明确。
- **可能的代价**：像文档号；文档改名/迁移；长度；AC 子号更长。
- **可能推翻它的证据**：V4 外部读者把 `PRD-001` 当文档号；V7 文档改名成本。

### H5 层级数字：`1.1 / 2.3`（Kiro 式）

- **可能的好处**：无 token 先验问题；自然大纲；短。
- **可能的代价**：插入会重排；种类不可见；跨文档要文档名；AC/TC 怎么编未定。
- **可能推翻它的证据**：V2 编辑样本时出现重排/断引用。

### H6 全局序号+类型字段：`R-0001` + `kind`

- **可能的好处**：分配成本较低；无前缀先验；永不复用。
- **可能的代价**：外部不可读；种类只在字段；供应商 Excel 里无法一眼判。
- **可能推翻它的证据**：V4 外部场景无法解析；V1 第一反应"这是什么"。

### H7 上游不编号，只用文档+章节

- **可能的好处**：空间更少；上游文档保持"文档"。
- **可能的代价**：章节号不稳；上游追溯粒度粗；用户"编号必须有"可能覆盖它。
- **可能推翻它的证据**：V4 上游引用在改章节后断掉；用户否掉。

### H8 不透明 ID + 注册表（UUID/哈希）

- **可能的好处**：零撞号；永不复用；机器友好。
- **可能的代价**：人/外部不可读；与"ID 贴进 Excel/CAD"直接冲突。
- **可能推翻它的证据**：V4 外部可读性；用户约束 1。

### 6.5 评估维度（待拍，不预设权重）

| 标准 | 要问什么 | 怎么测 |
|---|---|---|
| 第一眼正确 | Agent 裸看 token 是否立刻理解 | V1 |
| 人的 review | 人能否在 5 分钟内回答 owner/verifier/trace | V11/V12 |
| 外部可读 | 供应商/实验室/客户能否解析 | V8 |
| 一件东西一个编号 | 是否会出现同一需求两个号 | V2 |
| 机器可判 | 定义/引用/提案是否可区分 | V3/V4 |
| 不新增前缀 | 是否违反用户约束 4 | 方案审查 |
| 迁移成本 | 旧产物/旧引用要改多少 | V7 |
| OpenSpec 兼容 | SW/FW 的 Traces 是否可落 | V13 |
| 多 discipline | 派工/验证分家是否可表达 | V14 |
| 并发/分配 | 两个 Agent 同时写会不会撞 | V2/V9 |
| 上下文成本 | 契约能否进 handbook 预算 | 字节估算 |
| 可维护 | 新人/新 Agent 能否学会 | V12 |

> 权重由用户拍；本材料不预设哪条更重要。
