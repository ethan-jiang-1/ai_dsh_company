## 2.5 上一次吸收（2026-10-04）为什么没生效

这一节是整个对账里最该先读的：**我们不是没读过 DSH 的测试策略，五周前就吸收过一轮。**

- **证据**：`checks/gates/doc-budget.mjs` 的行预算注释原文——`['docs/testing.md', 75] // 2026-10-04 立测试宪法
  （_digested/test-strategy 消化采纳轮；用户点破 DSH「后缀即层」实践）`。今天生效的 `docs/testing.md §1.1`
  「资产命名语法」、§1 九层证明边界、§3 九条证据纪律，都是那一轮的产物。
- **那一轮落了什么**：宪法文本（层表 / 纪律 / 命名语法）+ `tests/README.md` 的「改动面 → 最窄检查」表 + 后续四个新鲜度门。
- **那一轮没落什么**：执行下限（覆盖率不是门）、失败类矩阵、证据账本、真入口必需 lane、资产盘子（census）。
- **为什么没落（三条，都能在仓里查到）**：

  1. **宪法当天就顶格**。`doc-budget` 注释写着 testing.md「**同 diff 压回 75 顶格**」「⚠ 顶格：下一句加进来前先迁」。
     此后每条新规则都要先腾地方，最省力的落点自然变成 README 与 skill——**政策家的容量限制了机制的出生**。
  2. **enforcement 通道只有两条**（pre-push + verify），而那一轮吸收的多数条目（真实入口、世界验证、prove-it-red）
     都**不可机械判**，于是只能留在散文层。散文在 agent 仓里衰减得最快：`§3.7 prove-it-red` 写了半年，
     直到 `guard-red-record` 才真的挡住弱化守卫（见该门禁头注）。
  3. **有一处被明确否决、且否决得对**：`notes/archived/2026-10-05-rfc-tdd-loop.md` 的「输掉的方案」写着
     **重门禁 = 仪式性合规**（"门禁查文本只挡缺席不挡空壳——写空节即过"）。这条判断今天仍然成立，
     所以借鉴方案里**任何"检查 Note 里有没有某节"的 gate 都不该提**（本方案 B2 因此放 skill，不放 gate）。
- **代价**：那一轮**没有留下 Note 说明"哪些决定故意不建"**。于是五周后同一批问题被重新发现、重新讨论——
  这正是 `notes/` 存在的理由（决定 + 输掉的方案），也是 DSH 每条政策都链一篇 owning note 的原因。
- **教训（本文档的立论）**：借鉴时真正要决策的不是"抄哪条规则"，而是**每条规则的载体**：
  gate（可机械判）/ skill 完成判据（语义、每次执行）/ Note（决定与理由）/ 显式作废。
  上一轮全部落在"散文 + 少量 gate"，所以**规则在，机器不在**——这就是"老要调整测试资产"的根因。

## 3. 七个结构性缺口（症状 → 机制缺位 → 证据 → 后果）

### D1 命名不产生选中：资产可以「存在但永不进入任何 lane」

- **症状**：33 个冒烟 + 69 个探针全标「常驻」，但只有 6 条进 `smoke:fast`；其余靠头注「何时跑」的**散文契约**。
- **机制缺位**：DSH 的 M1 是「后缀 → 配置」的机械互斥；本仓的后缀只是**词表**（`docs/testing.md §1.1` 自称"政策不设新门"），
  一个 `.mjs` 放错目录/写错头注，仍然"存在"，但没有东西会跑它。
- **证据**：`checks/smoke/fast.mjs` 的 `CASES` 只有 6 项；`ci.yml` 只跑 `verify`；`fast.mjs` 头注自己写着
  "便宜 smoke 不在 pnpm test / verify / pre-push 里，坏了没人知道——2026-11-13 实测 two-axis 与 replay 两条红"。
- **后果**：资产腐烂不是意外，是默认。测试资产围栏那轮（`a3efa236`）修的两条红资产就是这一类的收据。

### D2 分层轴是「目录」，不是「证据形态 × 入口真实性」

- **症状**：层表按 `pnpm verify` / `pnpm test` / 冒烟 / 重放 / 发布 排列，读者知道"有什么"，但不知道"这层能证明哪种失败"。
- **机制缺位**：DSH 分层的合法性来自"这层是唯一能看见该失败类的层"；本仓的层没有被失败类反向定义，
  于是"这条该放哪层"只能靠经验，且没有判据检查"放错层"（例如用 jsdom 断言浏览器行为）。
- **证据**：`docs/testing.md §1` 的「不证明什么」列已经写了一半（"不证明真渲染交互"），但没有把**失败类**作为主键；
  `tests/README.md` 的 11 行映射表主键是目录（`src/host/`、`src/client/`、`content/`）。
- **后果**：66 个边界缺陷不是"某层没测到"，而是"没有人按失败类问过一行"。见 `adversarial-shape-matrix` 研究题。

### D3 没有执行下限：覆盖率不是门，是手动档

- **症状**：188 个被插桩文件里，3 个 0%、5 个 <50%、30 个 <80%；有阈值的只有 10 个（5.3%）。
- **机制缺位**：DSH 用 per-file 100% 把"未覆盖行"变成"死代码提示"；本仓的阈值是**手选 10 个模块的百分比下限**，
  且 `test:coverage` 不在 pre-push、不在 CI——**低于阈值不会挡住任何提交**。
- **证据**：`vitest.config.ts` 注释自述"阈值是发布前/独立轮的手动棘轮，不塞进 pre-push"；
  `pnpm test` 不跑 coverage；`ci.yml` 不跑 test。
- **后果**：新代码可以整体零覆盖地合入（`carrier-registry.mjs` 是**写入口登记表**，0% 覆盖；
  `probe-window.mjs` 0%），而没有任何机械信号。这是"下一次漏洞"的温床。

### D4 没有决策程序与缺口账本：选层靠经验，缺口靠记忆

- **症状**：改动面映射是路径表；没有"这类变更最低该配什么证据"的分类；没有"显式未覆盖"的登记处。
- **机制缺位**：DSH 的五步程序把"够了没有"变成 7 个 yes/no + 一行显式未覆盖；
  本仓 `docs/testing.md §5` 的「已知未覆盖面」是散文（多人交互 UX + E1/E2 + candidate-scan），
  没有 owner、没有触发条件、没有到期复核。
- **证据**：`docs/testing.md §5` 最后一条；`checks/README.md` 的「待触发复查」表是**唯一**接近"缺口账本"的东西，
  但它只管发布/培养面，不管测试面。
- **后果**：同一个担忧会以"口头担忧"的形式反复出现（宪法自己写了"口头担忧第二次提起 → 立卡或明确否决"，
  说明这是已发生过的病）。

### D5 真入口证据不在任何 required lane：「verify 绿」只等于「结构一致」

- **症状**：`preset-smoke` / `client-load-smoke` / `release-smoke` / `company-entry-smoke` / `replay-smoke` /
  `ui-scene-smoke` 全是"改动后跑 / 发布前跑"；没有任何东西保证它们被跑过。
- **机制缺位**：DSH 把真入口证据放进必需 job（`ci-consumers` 含 built smoke + web snapshot），
  并把"不在 required job 里的证据"明确定性为"文档，不是门"。本仓的 required lane 只有结构 + keyless 单测。
- **证据**：`ci.yml` 只 `pnpm verify`；pre-push 只 `smoke:fast` 6 条；`_backlog` 记的发布事故
  `9f74ce71`——`release --verify` 里 `present-catalog-smoke` 因 plain-node TS 语法**静默红**，
  "这条红从未被当成发布阻塞"（原文见 `notes/implemented/2026-11-13-release-0.11.6-refresh.md`）。
- **后果**：这正是 DSH postmortem 0001 的同类（"绿单测 + 坏产品"），只是我们的规模小；
  而且它解释了为什么每次收口都要"临时决定跑哪几条"——**没有一条是被机器保证的**。

### D6 组装转录层几乎是空的：产品面行为只有真模型 e2e

- **症状**：`snapshots/` 只有 1 个合成场景（foundation-workspace），供 `replay-smoke` 跑管线；
  公司行为回放随真实证据移出产品仓。
- **机制缺位**：DSH 让"录制一次、回放永久"成为必需 job——真模型证据以近 unit 成本进门禁。
  本仓的替代品是 `product-team-e2e-smoke` / `presence-e2e-smoke` 等真模型冒烟：**有 key 才跑、按人触发、分钟级、花钱**。
- **证据**：`snapshots/README.md` 首段与 `docs/testing.md §2`（"公司行为回放已移部署仓；本仓只保留合成管线场景"）；
  `tests/README.md` 的 preset 行仍写着"行为判据面 → 场景同 diff 必带（两件套组队 = product-team-e2e-smoke）"——
  政策要的是"场景"，载体却是**不可回放的真模型冒烟**。这是政策与资产之间的口径裂缝。
- **后果**：persona / skill 文案的行为判据只能靠"当时有 key 的人愿意花 $1–2"，不可重复、不可 CI、不可回归。

### D7 没有性能层，也没有可靠性词表

- **症状**：无 benchmark、无预算；flake 出现时只有"单向归因"一条原则，没有分类词表与复现阶梯。
- **机制缺位**：DSH 的性能门让"慢"变成红灯，且**预算是审查过的源常量、环境变量不得覆盖**；
  flake 八类词表让"时好时坏"变成可归因的签名。
- **证据**：根 `package.json` 无 bench 脚本；`docs/testing.md §3.4/§3.5` 只有原则。
- **后果**：UI 面（公司页签、长会话渲染）的性能回归**不可见**；flake 的处置压力会落到"加超时/重试"，
  恰好撞上 §3.5 的掩盖黑名单——有禁令、无替代程序。

## 4. 我们领先的三处（对账时别为了"像 DSH"而回退）

### A1 机械新鲜度：环外资产有自动化的腐烂信号

`replay-fixture-freshness` / `replay-ui-freshness` / `ui-golden-freshness` / `dist-freshness` /
`replay-scene-liveness` + `snapshots-budget` / `snapshot-index`：把"注入面漂了""金样与注册面不一致"
变成 `pnpm verify` 的红或**显式 SKIP**（`run-gates.mjs` 的 `EXPECTED_SKIPS` 精确集合，新增一个静默跳过必须改代码）。
DSH 对同类问题靠"每个 diff 人工 review"；本仓没有人肉 reviewer 的预算，所以做成了机械门——**这是方向正确的一条，应扩大而不是削减**。

### A2 反顶替：`spec-duplicates` 与负例夹具的自我防腐

`spec-duplicates` 从一次真实事故长出来（`d6d1f92` 把 `tests/lib/dag.spec.ts` 整文件覆盖成另一个 spec 的字节副本，
全绿）；`checks/smoke/lib/mutation.mjs` 让"负例夹具的 replace 变 no-op"直接断言失败——**守卫自己的腐烂被守卫住了**。
DSH 没有对应机制（它假设 patch 不会把测试顶替）。

### A3 「无对象 ≠ 通过」与 skip 预算

`run-gates.mjs` 把 `skip` 与 `PASS` 分开印，且 `EXPECTED_SKIPS` 精确匹配；`tests/harness/repo/skip-budget.spec.ts`
要求新 skip 配「预期 N 个真跑」。DSH 的同类思想在 CI 层（grep "Test Files N passed"）；本仓把它下沉到了**单测层**，更早生效。

## 4.5 用 DSH 的插件五台阶给自己打分

本仓本身就是一个 DSH 插件（bundle + host + client + presets），所以 DSH 给插件作者的「五级台阶」
是比抽象分层更贴身的尺子。逐阶对：

| 台阶 | DSH 要求 | 本仓载体 | 判定 |
|---|---|---|---|
| 1 导出形态守卫 | 无 default、named exports、`name`/`inject` 齐 | [pack-exports.spec.ts](../../../tests/harness/repo/pack-exports.spec.ts) + pack-shape / pack-source 门 | **有** |
| 2 行为 spec | 边界、错误路径、事件顺序 | `tests/host`（58）+ `tests/lib`（14）+ `tests/client`（62） | **有** |
| 3 注册生命周期 | dispose 贡献 fiber → 断言贡献消失 | client 面：[company-client-composition](../../../tests/client/company-client-composition.spec.ts) / company-tab-registration / style-lifecycle / instance-guard | **client 有；host 侧 registry 的 dispose 未被点名（未测）** |
| 4 REAL composition | 真 Loader/boot，不手搭 `ctx.plugin` | [client-load-smoke](../../../checks/smoke/client-load-smoke.mjs)（真 `bootClient` × web profile roster）+ [preset-smoke](../../../checks/smoke/preset-smoke.mjs)（真挂载） | **有，但不在 required lane（D5）** |
| 5 组装转录 | 同 PR 录制场景，keyless 回放 | — | **缺（D6）** |

**读法**：按 DSH 的采用等级，本仓是**「L1 产品可见」但台阶 5 缺位、台阶 4 不在必需 lane**。
这恰好解释了两个长期症状：文案/行为判据的验证只能靠真模型冒烟（台阶 5 缺），
每次收口要临时决定跑哪几条（台阶 4 不在 required lane）。也说明差距不在「没写测试」——
1–3 阶是齐的，缺的是**组装证据的形态与它的位置**。

## 5. git 病史 → 缺口映射（为什么最近老在补测试资产）

近 200 个 commit 里，碰过 `tests/` 的有 **112** 个，碰过 `packages/company-pack/src/` 的有 **70** 个（67 个两者都碰）——
测试面不是"配套"，是**比源码更高频的返工面**。把最近的测试类 commit 按缺口归类：

| commit | 干了什么 | 指向缺口 |
|---|---|---|
| `a3efa236` 测试资产围栏 P0 | 修两条红资产（two-axis / replay）+ 建 `smoke:fast` | **D1**（资产存在但无人跑） |
| `05784e6c` / `9e25744c` 对抗性边界矩阵 | 13 形状 / 6 写入口 / 进程矩阵 / TOCTOU | **D2**（缺失败类矩阵，66 个 bug 靠外部审计才现形） |
| `9f74ce71` 0.11.6 发布 | 发布验收静默红修绿（plain-node TS 语法） | **D5**（真入口证据不在 required lane） |
| `ea21dee7` / `aad75b37` clean clone 复核 | 3 处腐化指针 + React 双副本 | **D5/D3**（干净环境与暖树的差异没有常驻 lane） |
| `1b307755` / `50878cd6` / `d31d8366` 等 BUG 收口 | BUG-080..151 批次 | **D2 + D4**（边界/写入口类失败无行可落） |
| `aad9bb4` BUG-151 | upgrade log 叶子目标 + 矩阵清零 KNOWN_GAP | **D4**（KNOWN_GAP 靠矩阵自己记，无全局账本） |

**读法**：这些 commit 的动机都对（每次都在"吸取好 practice"），其中 3 个带着局部机制
（`smoke:fast` lane、对抗矩阵 + 载体登记门），但**没有一次把"选中 / 下限 / 必跑 / 账本"补成系统**；
另外 3 个是纯症状修复（发布验收、腐化指针、单 bug）。这就是"短视"的准确含义：
不是不努力，是努力都花在事后。

## 6. 我们明确没测的（诚实边界，不进上面的对账）

- 真浏览器交互全路径（`client-load-smoke` 只证挂载；`ui-scene-smoke` 只证页签可见与金样）；
- 多人/协作 UX 面（已有 4 条真模型探针，常驻但不自动跑）；
- 性能与内存（无层）；
- Windows / Node 22 以外的平台；
- 发布通道的真实 npm 侧（`channel-matrix-smoke --channel all` 需网络+全局包）。

## 7. 不借的清单（避免把 DSH 的规模抄成我们的债）

| 不借 | 理由 |
|---|---|
| per-file 100% 一步到位 | 本仓 188 文件、3 个 0%、30 个 <80%；一步到位只会逼出"为覆盖率写测试"。借的是**棘轮机制**，不是数字 |
| 27,000 条用例 / 250 场景 | 规模绑定模型厂的自研预算与 runner 池；本仓的等比目标是"每个失败类至少有一条能红的证据" |
| with-key 不设限 | 我们是成本受限的一天一结项目；真模型证据要靠**回放**降本，不靠多跑 |
| 9 个必需 CI job + 自托管矩阵 | 我们的 CI 连 test 都跑不了（vendor 构建）；该借的是"必需 lane 的**形状**"，落到 pre-push + 按面触发 |
| test-support 包农场 | 本仓已有 `tools/lib`（纯逻辑）+ `tools/drivers`（真驱动）+ `checks/smoke/lib`（夹具）；再造一层只会多一处漂移 |
| 「没有普适本地基线」 | DSH 敢薄 hook 是因为 CI 穷尽；我们 CI 只有结构门，**pre-push 必须更厚**——这反而让"选层程序"更值钱 |
