# 能力归位与质量环：怎么让 SA/SQA 这类东西不再写死在 preset 里

> 问题：VP-Eng 拿到复杂产出时，怎么让"做的人"和"验的人"在独立上下文里对抗，同时把"方法"留在外部约定里、不写死进 preset？以及以后新增内容时，怎么让 agent 先想架构和抽象层次，而不是只改手上的文件？
> 消费者：用户（2026-11-10 探索与定稿）；落成两张卡：[内容宪章](../../_archive/settled_issues/2026-11-10-content-charter.md) 与 [producer/verifier 质量环](../../issues/2026-11-10-producer-verifier-quality-loop.md)。
> 产出的卡：[2026-11-10-content-charter.md](../../_archive/settled_issues/2026-11-10-content-charter.md)、[2026-11-10-producer-verifier-quality-loop.md](../../issues/2026-11-10-producer-verifier-quality-loop.md)
> 结论：人/流程/方法/政策四槽分开——能力档进 preset、流程进通用层、方法进角色方法层、政策进公司层；再用"宪章 + 归位 skill + 结构门 + 卡/Note 字段"把归位变成以后每次新增的默认动作。
