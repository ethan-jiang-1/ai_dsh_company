# 测试树与源码树的对应：两根轴，别装成一根

> 问题：`tests/` 的子目录能不能跟 `packages/company-pack/src/` 一一对应？不能对应的那 62 个 spec 该按什么分？对应关系现在由谁保证？
> 消费者：用户 2026-11-15 点名（「测试底下要拆分出的子目录，最好是跟源码能对应起来」）；产出卡见下。
> 产出的卡：[2026-11-15-tests-tree-axis](../../issues/2026-11-15-tests-tree-axis.md)
> 结论：**镜像只对「有一个源组」的区成立，且现在是散文不是不变量**（四个 owner、三种说法、零门禁，已漂 5 处）；`tests/repo` 的 35 个 spec 没有源码对象，应换 owner 轴并明说不是镜像区；`src/lib` 的镜像是「都平铺」，缺口补在覆盖不在目录。**做** = 一条 set-equality spec + 六个 owner 目录 + 删掉文档里的组数枚举（空壳 harness 目录已随 `51a1c61b` 删除，不再是动作）。
