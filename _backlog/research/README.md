# research/ · 研究题（名头）与活跃材料

研究按**研究题**组织：一个研究题 = 一个目录 + 一张题名页（`README.md`）。题名页是这轮研究的**名头**：
它回答「研究什么、服务谁、长出了哪些卡、有哪些材料」。研究材料住在题名目录内；研究收结、委托它的
最后一个活消费者离开后，整个目录原样迁入[研究归档](../_archive/research/README.md)。

短结论回 [issues](../issues/README.md) 或 [bugs](../bugs/README.md)，较长的证据阅读、综述、机制笔记住这里。
先从卡片链接选读，不必通读目录；半成品合法。

## 一个研究题长什么样

```
research/
  README.md              ← 本页：活跃题名索引（一题一行）
  <slug>/                ← 研究题（目录名 = 稳定 slug）
    README.md            ← 题名页（不是研究正文）
    YYYY-MM-DD-<slug>.md ← 研究材料
    ux/...               ← 同题资产
```

题名页模板（`> 归档：` 行只在归档后填）：

```markdown
# <名头>：<一句话>

> 问题：这轮研究要回答什么
> 消费者：<发起 / 使用它的卡、bug、Note 或授权工作；写链接>
> 产出的卡：<研究结论落地后新立的卡；没有写 —>
> 归档：YYYY-MM-DD（归档后补）

## 材料
| 文件 | 作用 | 日期 |
|---|---|---|
| [YYYY-MM-DD-<slug>.md](YYYY-MM-DD-<slug>.md) | 一句话作用 | YYYY-MM-DD |
```

## 约定

- **slug**：小写 kebab-case，不带日期；归档不改名。已有目录名保持原名，题名页给可读名头。
- **研究材料**：`YYYY-MM-DD-<slug>.md`，frontmatter 首字段 `topic`、第二字段一行 `intent`，不写 `status`。
  文件名日期 = 材料首写日期；`topic` / `intent` 说这份材料自己，不替代题名页。
- **题名页**：必须逐份点名 `.md` 材料（资产按目录或文件点名即可），并写全 `> 问题` / `> 消费者` /
  `> 产出的卡` 三行——缺一行就是名头没交代清楚。材料只住题目录内，research 根不落散件。
- **消费者与产出的卡**：消费者 = 谁委托 / 使用这轮研究；产出的卡 = 研究结束后由它长出来的 issue / bug 卡。
  两者都写相对链接，没有就写 `—`。「产出的卡」是研究 → 卡的反向线索；卡正文里再链回题名页，形成双向可回溯。
- **归档**：最后一个活跃消费者离开后，`git mv` 整个题名目录到 `_archive/research/<slug>/`；题名页补
  `> 归档：YYYY-MM-DD`，归档索引只加题名一行。材料正文不重写，只修搬迁所需的相对链接。归档后仍可被
  活跃卡引用；引用不等于让研究「复活」。

## 证据纪律

- 原始证据保留 URL、原句、版本 / 样本、获取限制与反证；分清事实、推论和实现状态。不能从 schema、
  一次运行或代理读数推出收益与真实采纳。
- 材料可服务多张卡。最后一张使用它的活卡离开时随题归档。
- 结构检查（`pnpm verify` 的 `backlog-liveness`）只证形状——题名页在场、三行在场、索引按题登记、
  材料被题名页逐份点名；它不证明证据质量或方法有效。

## 收什么 / 不收什么

- **收**：服务活跃卡、值得保留的调研材料——推敲时攒的、被卡引用的、喂毕业判断的；半成品合法。
- **不收**：抛弃型草稿（按[开发环 §11](../../docs/guides/dev-loop.md)留在仓内 gitignored 工具区）；价值
  越过所有卡的留存型参考（那类材料向[下游](../../notes/README.md)申请处理，不自行变成 Note）。

## 维护

- 新研究先建题目录与题名页，再写材料；不要先在 research 根落文件。
- 题名页的「消费者 / 产出的卡」随卡的生命周期更新；卡片归档时，若研究已无活跃消费者，整目录迁走。
- 本页只列活跃题名一行；归档索引一题一行。逐文件清单不在两个索引里重复。
