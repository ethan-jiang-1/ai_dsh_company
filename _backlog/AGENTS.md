## 五道门：`status` 就是你的位置

研究 → 定性 → 落地 → 审 → 归档。看 frontmatter `status` 对下表；一格只有一个出口物，写不出来就翻不动（`pnpm verify` 查形状）。

| `status` | 下一步 | 出口物（写不出就翻不动） |
|---|---|---|
| `推敲中` / `调查中` | 补事实或命名结论（做 / 以后做 / 不做 / 消化）；只有缺人的选择才 `等人拍板` | 结论 + 范围与排除；做 → 门票 + `去向` |
| `待落地` | 有用户点名或已批 RFC 就实施，否则等——**卡本身不是授权**；交付与 Note、归档同一次变更 | `## 验收标准` 非空 + `去向 ∈ rfc｜note｜implementation` + 毕业头 `做` |
| `修复就绪` | 门票即授权（限 P1/P2 修复型）；**排除项见[章程](README.md)「缺陷的通道」**，此处不复述 | `## 已修判定` 非空；落树翻 `修复已落地` |
| `修复已落地` | 判据与证据齐了，记 `审查：`，归档 | `审查：agent｜用户｜跳过 — 理由`（跳过要写理由） |
| `等人拍板` | 停手，只报告；用户答复才动 | 用户明确答复（🔒 仅用户可判） |
| `已结` / `已修` / `待修` / `叫停` | 归档区，默认不读，点名才开 | — |

`去向` 是封闭集：`rfc`（→ proposed）/ `note`（→ implemented）/ `implementation`（提交即载体）/ `pending`（用户持有）/ `none` / `rejected`（负知识）。写作 `> **结论/去向**：<值> — <落点>`；未落地的落点用 inline code，别链未来文件（`md-links` 会红）。

研究题：[题名页](research/README.md) `status: 调研中｜已定性` + `opened`，`已定性` 要 `> 结论：`；材料不设 status（材料是证据）。模板与字段顺序 = 各目录 README，本页不复述。

## 状态枚举（翻转表唯一家 = [章程](README.md)「双轨状态生命周期」）

- 问题轨活跃 `推敲中` `待落地` `等人拍板`；缺陷轨活跃 `调查中` `修复就绪` `修复已落地` `等人拍板`。
- 离场：`已结` `叫停` `已修` `待修`（出口值只在归档同改翻转；沉默不翻转）。
- 状态行镜像 frontmatter `status`（门禁互查）；问题卡状态行带 `毕业：` 封闭头（未定/做/以后做/不做/消化）。

## 铁律一句话

卡上的状态、方案、建议和交接不授予实施权限（唯一例外 = 上面的 `修复就绪` 自授权）。🔒 卡只由用户判定触发；清单与目录保持一致（`pnpm verify` 查）。
