# _backlog/ · 区门牌（薄——规则唯一家 = [章程](README.md) 与各目录 README，这里只路由）

> 你为什么看到本文件：第一次动 `_backlog/` 下的文件时它随文件操作自动注入（平台机制，整链有字节预算）。看完即可干活；要规则原文按下面指针走，本门牌不复述事实。

## 五个目录是什么

| 目录 | 装什么 |
|---|---|
| [issues/](issues/README.md) | 还没结束的问题卡（推敲层，不是任务源） |
| [bugs/](bugs/README.md) | 这次不修的缺陷卡（修复工作项） |
| [research/](research/README.md) | 服务于活卡的长证据（随末张活卡归档） |
| [methods/](methods/README.md) | 走卡方法（常驻 SOP，不归档） |
| [_archive/](_archive/README.md) | 离开活跃区的卡（默认不读，点名才开） |

## 一件事怎么走

分诊 → 推敲（缺事实查证/读码/原型，缺人的选择就带建议去问）→ 毕业/修复 → 向用户交接（RFC/Note）或归档。完整走法与关闭条件 = [章程](README.md)。

## 两张门票（由格式承载，门禁查形状）

- **问题轨毕业**：`## 验收标准`（可执行判据）。
- **缺陷轨修复就绪**：`## 已修判定`——该翻转即门票**且**授权（限 P1/P2 修复型；排除项见[章程](README.md)「缺陷的通道」，此处不列）。

## 状态枚举（翻转表唯一家 = [章程](README.md)「双轨状态生命周期」）

- 问题轨活跃 `推敲中` `等人拍板`；缺陷轨活跃 `调查中` `修复就绪` `修复已落地` `等人拍板`。
- 离场：`已结` `叫停` `已修` `待修`（出口值只在归档同改翻转；沉默不翻转）。
- 状态行镜像 frontmatter `status`（门禁互查）；问题卡状态行带 `毕业：` 封闭头（未定/做/以后做/不做/消化）。

## 铁律一句话

卡上的状态、方案、建议和交接不授予实施权限（唯一例外 = 上面的修复就绪自授权）。🔒 卡只由用户判定触发；清单与目录保持一致（`pnpm verify` 查）。
