> 性质：**点子进入 RFC / 实施之前的推敲空间 + 一切"不在活跃任务流"的项的家**——「该不该做、何时做、
> 次序如何、是否放弃」四问在这里成熟。**不承载调度**：没有中心排序文件（D32）——实施次序 = 用户
> 逐条给，授权唯一 = dev-loop §0.5。D23 教训：plans 层一旦开始排任务就会长成第二个队列
> （2026-09-24 退役过一次）——本目录永远不做调度。
> 来源：借鉴 `ai_deerflow_deep_research_v2` 的 `_backlog`（plans/bugs/done 三件）；判定、取舍与
> 不借清单 = [收尾 Note](../notes/implemented/2026-09-28-backlog-deliberation-space.md)（D31）。

## `_` 前缀语义（借 deerflow；`_` 只表示「不在活跃队列」，不表示禁读）

- **归档件**（会关闭；fresh agent 默认忽略，点名才读）：`_done/`。
- **活跃推敲卡**住无前缀目录（`plans/`、`bugs/`）；**已裁决的搁置/磨活** = 本目录两张表
  （`suspended.md` / `polish.md`）。

## 目录

```
_backlog/
├── README.md            # 本文件（规矩手册）
├── plans/               # 推敲卡：设计 / 分析 / 调研（含原 notes/research 的未完结调研，D31）
├── bugs/                # 缺陷卡：已发现、不当场修的缺陷（当场修掉的不建档）
├── suspended.md         # 搁置池（已裁决"不做/不现在"，复活条件必填；D32 自 ROADMAP 迁入）
├── polish.md            # 磨清单（低优先磨活，谁来磨/何时磨；D32 自 ROADMAP 迁入）
└── _done/               # 归档（位置即状态）：_closed_plans/ + _fixed_bugs/
```

## 推敲卡（plans/）的生命周期：毕业四门

每张卡首部带状态行（格式见 [plans/README.md](plans/README.md)，机械门禁 `plans-liveness` 强制）。
推敲的产出是**一个毕业判断**，不是开工。四条出路：

| 判断 | 出路 | 卡的去向 |
|---|---|---|
| 该做（现在/近期） | RFC 落 [notes/proposed/](../notes/proposed/)，状态行记「批准：」（门禁查）；实施由用户逐条点名。小修可不设 RFC → 进 [polish.md](polish.md) | 关闭迁 `_done/_closed_plans/`，状态行记去向指针 |
| 该做但不现在（待触发） | [suspended.md](suspended.md) 行（满足其准入判据，复活条件必填） | 同上 |
| 不做（证伪/否决） | 结论并入 owner Note「输掉的方案」，防复犯价值高的迁 [notes/rejected/](../notes/rejected/) | 同上 |
| 不用单独记（消化） | 结论已并入某 Note/合同 | 同上，状态行记消化落点 |

**边界**：推敲卡 ≠ 提案——卡可以只有问题没有方案；RFC 必须有问题/方案/验收三件。
推敲未到 RFC 程度时卡停在活跃区继续熟，状态行写「下一步 + 触发」。

## 缺陷卡（bugs/）的边界

**当场修掉的不建档**（保持轻；轮次 Note 照旧）；**发现时决定不当场修的必须建档**
（症状 / 根因假设 / 复现 / 严重级 / 修复关联），否则缺陷散在轮次 Note 里不可检索、无 triage 状态。
已有归宿的旧缺陷（搁置池 vendor 缺陷行、走查不修清单）不迁移。把每个 bug 当**契约探针**——
一个具体缺陷往往牵出一类失败，顺藤摸瓜值得横切排查（借 deerflow 口径）。

## 铁律（借 deerflow 搬迁规矩）

- **位置即状态**：`git mv` 过去、文件名不变、**内容不重写**——推敲过程本身就是证据；
  毕业/关闭只在状态行加去向指针。
- **README 永不删除**，只更新索引行。
- **编号权威住归档侧**：`_done/_fixed_bugs/` 持有 Next BUG ID（新号 = 已分配最大号 + 1，
  活跃 ∪ 归档一起算）；plans 卡无编号，**文件名 = `YYMMDD-<slug>.md`（日期 = 立卡日）**——
  时间轴在文件名上，归档后日期流一眼可见；文件名跨迁移不变。

## 谁写、谁读、何时读

- **写**：收割 / 走查 / 升 pin 重校 / 用户对话 / 自主探索（D29）中出现「值得推敲但未到裁决」的
  思考时立卡。**不成熟的思考不许进 proposed/ 或队列**（那边有归宿门禁）。
- **读**：① 立新卡前先检索（防重复推敲，同 Note 生命周期「新增触发取代检查」精神）；
  ② 用户点名继续推敲某卡；③ 打磨型 goal（dev-loop §0.5）可把「把一张卡成熟到毕业判断」当输入源
  （产出 = 呈批，不是开工）。
- fresh agent 的任务源 = 已批 RFC + [polish.md](polish.md)（dev-loop §0.5 分支②）：**推敲卡不是任务**。
