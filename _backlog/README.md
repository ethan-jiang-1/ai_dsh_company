# _backlog · 推敲空间（正式加工之前的思考加工层）

> 性质：**点子在长成 RFC / 队列项 / 实施之前成熟的空间**——「该不该做、何时做、次序如何、是否放弃」
> 四问在这里熟。只承载**判断材料（问题、证据、候选、取舍）**，永不承载调度与授权：变更痕迹住
> [notes/proposed/](../notes/proposed/)，实施次序 = 用户逐条给（D32）。它是**机加工线前的打磨场**：
> 石料（想法、缺陷）在这里打磨——研究、权衡、给触发条件——只有 `notes/` 把它们加工成决定；
> 本目录里的任何东西**本身不成为系统行为**。
> 来源：D31（2026-09-28）借 `ai_deerflow_deep_research_v2` 的 `_backlog`（plans/bugs/done 三件）；
> 该制度经 ai_dsh_architect 传入 ai_dsh_loop_advisor 后，又从 ai_deerflow_dr_v3 吸收了主干框架与
> 两只桶。**2026-10-03 章制回借（D33，用户令「从 advisor/_backlog 学习整理」+ 两项拍板）**：主干
> 框架与三条硬规则、索引交叉核对门禁、`_suspended_*`/`reference/` 两桶解禁再借、卡名改全日期。
> 回借判定、取舍与落地证据 = [收尾 Note](../notes/implemented/2026-10-03-backlog-charter-refit.md)。

## `_` 前缀语义（`_` 只表示「不在活跃队列」，不表示禁读）

- **归档件**（fresh agent 默认忽略，点名才读）：`_done/`——两种诚实的离场卡分目录住：**做完的**
  （`_closed_plans/`、`_fixed_bugs/`）与**暂停的**（`_suspended_plans/`、`_suspended_bugs/`——
  非-done 也非-删），外加随卡归档的研究材料（`_reference/`）与 2026-09-28 整池退役的历史池
  （`_misc/`，不再收新件，点名才读）。
- **活跃区**住无前缀目录：推敲卡 `plans/`、缺陷卡 `bugs/`、喂卡的研究材料 `reference/`。
  活跃区里放的 = 本仓还打算做的全部——做完的绝不停留。

## 目录

```
_backlog/
├── README.md            # 本文件（规矩手册 = 章程；其余 README 是账本）
├── plans/               # 推敲卡：设计 / 分析 / 调研（含待触发等待卡）
├── bugs/                # 缺陷卡：已发现、不当场修的缺陷（当场修掉的不建档）
├── reference/           # 打磨上述卡时收集的研究材料（喂卡的证据半边）
└── _done/               # 归档（位置即状态）：_closed_plans/ + _suspended_plans/ + _fixed_bugs/
                         #   + _suspended_bugs/ + _reference/ + _misc/（退役历史池）
```

## 主干：缓冲区 → 加工线 → 回流（D33 借 deerflow_dr_v3 框架）

`_backlog/` 是机加工前的打磨场；`notes/` 是加工线（RFC 进 [notes/proposed/](../notes/proposed/)，
决定记录进 `notes/implemented/`）。一条主干，一次说清：

```
输入面（半成品合法——缓冲区收问题、证据、缺陷、原始研究）
  ├─ 设计/分析推敲        → plans/     （背景 → 已知/未决 → 候选 → 四门）
  ├─ 缓修缺陷             → bugs/      （症状 → 根因 → 暴露类 → 修复关联）
  └─ 打磨时收集的研究     → reference/（喂上面两类的证据）

毕业——从缓冲区到加工线的唯一票（一个判断过四门）

加工线——唯一实施通道 = notes/
  notes/proposed/ RFC → 人审 → implemented/ → 变更落地

回流与写回
  做完的卡 → _done/ 对应子目录（铁律见下）
  无判断被搁置的卡 → _done/_suspended_{plans,bugs}/——暂停，不是做完
  喂卡的研究材料 → 随卡 git mv 进 _done/_reference/
  下游发现的缺口 → 新卡回本区——绝不夹带进 Note 或变更里
```

三条硬规则随主干同行：

- **无 RFC，不生效。** 再成熟也不行：本目录里的任何东西自己不成为系统行为；唯一实施之路经
  `notes/proposed/`。
- **卡记思考，Note 记决定。** 一处事实一个家：卡的状态行指向落地的 Note；Note 不复述推敲过程。
- **写回，不夹带。** 毕业卡下的实施常暴露下一个问题——回缓冲区立新卡，不在 Note 里搭车。

**与变更痕迹规则的合成（一次说清）**：卡是变更前的推敲；判断一旦是「该做」，变更痕迹落
`notes/proposed/`、卡关闭——两层组合而不竞争。反过来，已在归属 Note/合同里以「待触发」落位的项
**不另立卡**——归属 Note 是它的家；第二个队列正是源制度记录过的失败（D23 同款病）。

## 推敲卡（plans/）的生命周期：毕业四门

每张卡首部带状态行（格式与门禁见 [plans/README.md](plans/README.md)；`backlog-liveness` 强制）。
推敲的产出是**一个毕业判断**，不是开工。四条出路：

| 判断 | 出路 | 卡的去向 |
|---|---|---|
| 该做（现在/近期） | RFC 落 [notes/proposed/](../notes/proposed/)，状态行记「批准：」（门禁查）；实施由用户逐条点名。小修可不设 RFC，由用户点名直接做 | 关闭迁 `_done/_closed_plans/`，状态行记去向指针 |
| 该做但不现在（待触发） | **触发条件住唯一事实家，二选一**：无归属 Note 的债 = **等待卡**（留活跃区，状态行写「待触发 + 复活/判收条件」，触发兑现并判收后才毕业——本仓口径，2026-10-02 治理轮既定、D33 确认）；已有归属 Note/合同的，触发条件住那边、不另立卡（见合成规则） | 等待卡毕业时同左迁档 |
| 不做（证伪/否决） | 结论并入 owner Note「输掉的方案」，防复犯价值高的迁 [notes/rejected/](../notes/rejected/) | 关闭迁档，状态行记去向指针 |
| 不用单独记（消化） | 结论已并入某 Note/合同 | 同上，状态行记消化落点 |

**边界**：推敲卡 ≠ 提案——卡可以只有问题没有方案；RFC 必须有问题/方案/验收三件。推敲未到判断时
卡停在活跃区继续熟，状态行写「下一步 + 触发」。**未到任何判断就被搁置的卡不经过四门——那是搁置**
（见铁律：`_done/_suspended_plans/`）。**已毕业的卡永不复活**：归档记录的是「判断已落地」；待触发
项的触发兑现后，以**新卡或新 RFC 回场并引用旧卡**（写回规则，不是复活）。

## 缺陷卡（bugs/）的边界

**当场修掉的不建档**（保持轻；轮次 Note 照旧）；**发现时决定不当场修的必须建档**
（症状 / 根因假设 / 复现 / 严重级 / 修复关联），否则缺陷散在轮次 Note 里不可检索、无 triage 状态。
已有归宿的旧缺陷（`_done/_misc/` 历史池行）不迁移。把每个 bug 当**契约探针**——一个具体缺陷往往
牵出一类失败，横切排查值得在卡上点名（模板见 [bugs/README.md](bugs/README.md)）。

## 研究材料区（reference/）

打磨卡会产生研究——证据阅读、综述、机制笔记——它需要一个既不是卡（卡只放判断材料）、也不是仓外
（打磨废料留仓外）的家。`reference/` 就是这个家；完整契约 = [其 README](reference/README.md)。要点：

- **它跟着卡走**：卡毕业时 `git mv` 进 [`_done/_reference/`](_done/_reference/)，文件名不变、内容不重写。
- **无状态行、无逐文件门禁**：纯约定；唯一的文件级检查 = 索引点名（`backlog-liveness`），对
  plans/bugs 同样适用。
- **活得比卡久的东西不住这里**：留存参考语义 = [docs/index.md](../docs/index.md) §外部研究材料登记
  与 [notes/archived/](../notes/archived/)。

## 铁律

- **做完 = 离开活跃区。** 卡一毕业、bug 一修复，`git mv` 进 `_done/` 对应子目录，索引同步更新
  （活跃列表该行出去、归档索引该行进来）；喂卡的研究材料随行进 `_done/_reference/`。
- **搁置，绝不假装做完。** 用户明确暂停、且**无**毕业判断的卡 `git mv` 进 `_done/_suspended_plans/`
  （缺陷：`_done/_suspended_bugs/`）——暂停既非做完也非删除：上下文、风险与重启条件随卡走，索引
  更新，卡离开工作序。**搁置是队列决定**——跟明确指令走（用户的，或状态行已记录 parked 的）；
  agent 不得因自己判断某卡「不活跃」就搁置它。重启 = `git mv` 回活跃目录 + 恢复索引行，须新的明确
  优先级决定；搁置卡永远不是实施授权。**已判断的待触发项不是搁置**——它的家是等待卡（活跃区）或
  归属 Note（待触发门）。搁置不改任何内容（连状态行都不改：没有判断落地，就没有去向指针可加）。
- **位置即状态**：`git mv` 过去、文件名不变、**内容不重写**——推敲过程本身就是证据；毕业只在状态行
  加去向指针，指针指向的 Note 将来搬家时随行维护（状态行是归档卡唯一活着的部分）。
- **本文件是章程，树里其余 README 是账本。** 本文件在一般层面陈述制度（布局、四门、铁律），只在
  制度级决定时动（一次借鉴、一门或一条铁律改动、一次门禁升格），每次落地带流程 Note；卡的生命
  永远不碰它。账本为另一种理由、另一种节奏而动：活跃列表的行随卡走，归档索引随落地收行，Next
  BUG ID 随发号跳。检验法：**凡点名活卡、计数或现值的，进索引——永不进章程。**
- **README 永不删除**，只更新索引行。
- **编号权威住归档侧**：`_done/_fixed_bugs/` 持有 Next BUG ID（新号 = 已分配最大号 + 1，活跃 ∪ 归档
  一起算）；plans 卡无编号，**文件名 = `YYYY-MM-DD-<slug>.md`（日期 = 立卡日；2026-10-03 D33 用户
  裁决由 YYMMDD 改全日期，与 notes 树统一为全仓一种日期格式）**——时间轴在文件名上，归档后日期流
  一眼可见；文件名跨迁移不变。

## 谁写、谁读、何时读

- **写**：收割 / 走查 / 升 pin 重校 / 用户对话 / 自主探索（D29）中出现「值得推敲但未到裁决」的思考时
  立卡；打磨时收集的研究材料进 [`reference/`](reference/README.md)。**不成熟的思考不许进
  proposed/ 或队列**（那边有归宿门禁）。
- **读**：① 立新卡前先检索（防重复推敲）；② 用户点名继续推敲某卡；③ 打磨型 goal（dev-loop §0.5）
  可把「把一张卡成熟到毕业判断」当输入源（产出 = 呈批，不是开工）。
- fresh agent 的任务源 = 已批 RFC + 用户点名（D32）：**推敲卡不是任务**；`_done/` 默认忽略。

## 机械门禁

- **现在**：`backlog-liveness`（原 `plans-liveness`，2026-10-03 D33 升格）——① 每张活跃卡自带状态行
  户口（plans 卡含「毕业门判断」；bugs 卡含状态）；② 制度目录在场；③ **索引交叉核对**：每张卡/
  材料文件必须被 plans/bugs/reference/_done 四份 README 之一点名（升格依据 = 本轮实测两处活违规：
  两张已毕业卡不在归档索引、两张活跃卡不在活跃列表；反向——索引行指向不存在的文件——由
  md-links 硬档扫描覆盖）。清单唯一源 = `scripts/verify.mjs`。
- **有压力再借**：见「明确不借」表末行。
