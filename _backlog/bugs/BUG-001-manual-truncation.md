# BUG-001：公司手册超出 agent-instructions maxBytes——尾部在所有角色会话被截断

> 严重级别：P1（重要）｜发现：2026-09-30（第二轮评审盲审 F 附带发现）｜状态：活跃

## 症状

公司手册（`company-workspace/AGENTS.md`）实测 **16768 字节**，而五个角色 preset 的
agent-instructions 行 `maxBytes: 16384`（`presets/*/agent.cordis.yml`，ceo 为 :148）⇒ 按 vendor
预算规则（超预算时**最具体文件被截断**），手册**尾部约 384 字节不进任何角色会话**的注入——
真盘与排练场同等（排练场 AGENTS.md 是指向真盘手册的符号链接）。受影响的是手册尾部的工作纪律
条目。**行数门（`DOC_LINE_BUDGETS` 186/195）是绿的——行数门与字节顶脱节，这是它漏网的原因。**

⚠ **缺口大于 384 字节（2026-09-30 提交时核对补正）**：`maxBytes` 卡的是**渲染后的整条基线消息**
（vendor `agent-instructions` README:61/72 —— intro 文本 + 各文件 `Instructions from: <path>` 节头 +
链上其余文件），不是 `AGENTS.md` 单个文件的裸字节。⇒ 手册实际可用额度 < 16384，被截掉的
**多于** 16768−16384=384；上句 384 是下界不是量。裁定具体截点前不要引用 384 当精确值。

## 根因（假设）

agent-instructions 的 `maxBytes: 16384` 是 rc.2 组合行定值；手册随改文持续增长（09-26 密集立法后
越线）；verify 只有行数预算没有字节预算 ⇒ 这个约束无门禁盯守。

## 复现

`wc -c company-workspace/AGENTS.md` → 16768 > 16384；起任一角色会话核对手册尾部条目是否在场
（截断边界按 vendor 截断规则以字节计，具体截到哪一行待实测钉住）。

## 修复关联

候选：(a) 调 `maxBytes`（preset 一行改动 + `preset-smoke`）；(b) 手册瘦身。
**约束**：布局卡（修正 7）与日期卡（改文面 1）的手册改文**都加字节**——本缺陷的修复须先于/伴随
那两张卡的 RFC，否则改文加重截断。两卡已登记与本缺陷共享同一预算池（行数棘轮 + 字节顶双约束）。
