# 内容宪章：按寿命分层，按成本抽象

> 什么时候读：新增或修改角色、能力、方法、模板、流程、政策之前；或不确定「这段内容该住哪层」时（理由与输掉的方案 = [落地 Note](../notes/implemented/2026-11-10-content-charter.md)）。
> 性质：**归位与抽象层次的唯一家**——四槽、三层、四问、两测、成本判据住这里。步骤住
> [capability-addition-definition](../.agents/skills/capability-addition-definition/SKILL.md)，机械不变量住
> [checks/gates/](../checks/gates/)，层内放什么的现行清点住 [content/README](../packages/company-pack/content/README.md)
> 与 [manifest.json](../packages/company-pack/content/manifest.json)。
> 适用：动任何东西之前先答第 5 节四问；答不出，不动笔。

## 1. 一句话

**先问「这段内容跟谁一起变」，再问「它该住哪一层」，最后才写。**
归位不是分类学，是寿命；抽象不是审美，是改动成本。

## 2. 你放的是哪一样？四槽

| 槽 | 长什么样 | 换公司会变吗 | 住哪 |
|---|---|---|---|
| **人** | 身份、能力边界、工具面 | 不变 | 通用层 preset |
| **流程** | 谁先谁后、交接、轮次、裁决 | 不变 | 通用层 skill / content |
| **方法** | 怎么做、检查表、判据、术语 | 会变（公司/产品类型/项目） | 方法层 |
| **政策** | 什么条件下强制、阈值、升级线、谁签字 | 会变（公司） | 公司层 |

架构不是第五槽——架构是这四样的摆放方式；四样放对，架构就对了。

## 3. 三层秩序（+ 两条正交轴）

三层 = **通用 / 产品类型 / 公司**；机制是引擎，方法是正交轴，不塞进三层里。

| 层 | 回答的问题 | 换什么时改 |
|---|---|---|
| 引擎/契约 | 系统怎么跑 | 随 DSH pin（`<company-content>/contracts/`、preset 工具行） |
| 通用 | 所有公司都成立吗 | 跟产品版本（`<company-content>/generic/`、`packages/company-pack/presets/_shared/skills/`） |
| 产品类型 | 换行业/产品类型要改吗 | 换产品类型时 |
| 公司 | 只这家公司成立吗 | 换公司时 |
| **方法（正交）** | 换做法要改吗 | 换方法/项目时 |

目录 ↔ 层的现行对应 = [content/README](../packages/company-pack/content/README.md)：本表只给判据，不复述目录清单。

## 4. 三条铁律

1. **骨架不放实例**：身份、工具面、流程契约只写「是什么、边界在哪」，不写这家公司/这个行业/这个做法。
2. **方法不进 persona**：能力档只声明「需要方法」，不声明「用哪个方法」；方法必须是外部可替换的输入。
3. **一个事实一个家**：政策数字、公司事实、领域词、方法步骤各住一层；重复即错。

## 5. 动笔前的四问（顺序固定）

1. 换公司要改吗？→ 公司层
2. 换产品类型要改吗？→ 产品类型层
3. 换做法要改吗？→ 方法层
4. 只有机制本身变才改吗？→ 通用层/契约层

四问全「不」⇒ 你还没找到不变量，停，别写。

## 6. 两个测试

- **换公司测试**：删掉公司名、行业词、人名、具体阈值，骨架还成立吗？
- **换方法测试**：删掉方法名、层级名、编号族、检查表，骨架还成立吗？

不成立 = 放错层。结论写进卡里，不写「我觉得」。

## 7. 两个消费者（「通用」的门票）

声称通用 ⇒ 点名**第二个真实消费者**：第二家公司、第二个产品类型，或第二套 fixture。说不出 ⇒ 放低一层。
确有平台理由 ⇒ 登记**单例例外**：复审日期 + 搬家成本 + 触发条件。「以后可能有人用」不算消费者。

## 8. 抽象度按成本定

| 以后搬它的成本 | 例子 | 现在放哪 |
|---|---|---|
| 高（改 preset/代码/测试） | 身份、工具面、流程契约 | 第一天就抽象 |
| 低（一个 skill/模板） | 方法、检查表、领域词 | 可以先具体，放方法层 |
| 低（数据） | 政策、阈值、公司事实 | 放公司层 |

不为了整齐提前抽象低成本内容；也不为了快把高成本缝焊死在实例上。

## 9. 红牌（出现即打回）

- 通用层出现公司名、行业词、具体阈值。
- persona 里出现方法名、层级名、编号族、学科清单。
- 声称可复用的能力档没有方法槽。
- 为单一消费者造「通用」层。
- 把例子当规则贴进规则文件；把政策数字写进代码或注释。
- 新内容没进 [manifest.json](../packages/company-pack/content/manifest.json) 或对应索引。

## 10. 变更协议

- **卡**：新增/修改内容，卡里必须有 `## 抽象度`——四问答案 + 第二消费者（或例外）+ 搬家成本；缺这节，定性不算完成。
- **门**：合并前过 `pnpm verify` 的结构门（清单与判据 = [checks/gates/](../checks/gates/) 目录，本文件不复述）；本宪章对应的机械面 = 内容唯一家、载入清单、通用面零特殊性、preset 结构与名册。
- **Note**：收尾写「归位」一节——为什么这层 / 什么会逼它搬家 / 哪个更低的层被排除（规则 = [notes/README](../notes/README.md)）。
- **语义审**（[policy §P5](./policy.md)）只问一句：换公司/产品类型/方法，这段要改吗？要改 preset 或代码 = 错层。

## 11. 宪章自己的修改

只有两种情况改本文件：**四层秩序变了**，或**「改动成本」的判据变了**。改宪章 = 一张卡 + 一次语义审 + 同 diff 更新指针，不接受「顺手改一句」。
宪章不放操作步骤：步骤漂了改 skill，判据漂了改门禁，宪章只改原则。
