# 政策：授权边界与常设禁令

> 性质：**政策层**——常设的「必须 / 不许」，回答「这件事我能不能自己做、要不要拉人、能不能写到仓库外、
> 自动化能跑多久」。什么时候读：开工判断授权、加门禁、跑自动化、要写仓库外路径、阶段收口前。
> 层规矩 = [docs/AGENTS.md](./AGENTS.md)；操作步骤与命令 = [开发环](./guides/dev-loop.md)（本文只写规则，不写步骤）。

## P1 任务入口与授权（D23 / D32）

入口步骤（三种分支怎么走）= [开发环 §1](./guides/dev-loop.md#1-任务入口与交接)。下面是常设规则：

三种分支都只读相关 Notes（`implemented/` 与各 Note 的「输掉的方案」节里仍有效的决定与约束；被推翻/过时的研究稿在 [`notes/rejected/`](../notes/rejected/README.md)（D30 修订设立——2026-09-25 的「不设目录」裁断已废），需要时一并读），不扫全树。行动前确认结果、owner、范围和验收；用户指令定义目标和授权，合同定义预期，Note 解释取舍，实现与日志证明实际。发生冲突时查关联决定并做区分“实现缺陷/事实过期”的窄检查；关键需求或授权仍不明确时先问人。扩大范围或遇到未授权的关键选择，先确认。

**先澄清问题，再形成 RFC**：
- 问题、用户结果、范围或验收尚未明确时，先在 `_backlog/issues/` 与其专属内部作业手册 `_backlog/methods/` 中推敲，短结论记在问题卡，长依据放 `_backlog/research/`（`_backlog/` 是上游沙盒，不构成 `docs/` 权威依赖，也不自动授权实施）。
- 简单问题可简写；大问题先列粗粒度判断依赖，只细化本轮分支；能独立决定和关闭且结果/触发不同的事项才拆卡。
- 申请默认向用户提出；结论未确认留 `等人拍板`；结论已确认但下游未受理记 `去向=用户（日期）` 可关闭；受理后落 `notes/proposed` 的 RFC（遵守 [proposed 合同](../notes/proposed/README.md)）或同轮 `notes/implemented` 的 Note。

**Plan Mode（D23 本仓政策）**：feature 类任务默认先进入 Plan Mode 并用 `exit_plan_mode` 呈批，获批后按批准范围实施；用户已明确批准具体计划时不重复求批。明确授权的机械单步修正可直接做。需 Plan Mode 时用 `/plan` 进入；仅在模式中调用 `exit_plan_mode`。

**长程 goal 的目标写法（两形态 + 三类停止条件）**：
- **交付型**：按用户指定的已批 RFC/条目清单逐条实施（清单空即收口）。
- **打磨型**：限定预算（时间/轮次）+ 明确输入源（执行期审计发现或用户点名的 `_backlog/issues/` 卡——产出有依据结论或具体阻塞，不擅自开工），枯竭即收口。
- **三类停止条件**（必须写进 objective）：① 预算耗尽 → 自评收口；② 清单/输入源空 → 收口并报告；③ 真卡住（机制证伪/验收无法变绿/需人裁决）→ 停并报阻塞与证据，不硬闯。
- **节奏与边界**：每条一个 commit + push，收尾简报附「资产增量」行（并入收尾六行回执）。objective 引用条目/授权原文，不自拟、不扩围；扩围须回授权。

## P1-B 缺陷材料性与修复自授权边界（唯一定义家）

- **材料性（唯一定义）** = `P0`，或修复/结论触碰下列任一项：章程 / 常设指令、`docs/` 合同、`company-pack` 公开行为、已记录决定（`notes/implemented/` 状态行）。一份清单两个消费者：能不能自授权修、要不要留痕裁决。
- **修复自授权边界**：`_backlog/bugs/` 中缺陷卡翻至 `修复就绪` 的门票即授权，**仅限 P1/P2 非材料性修复型**（必须具备复现命令、根因与证据、失败类与同类排查、已修判定四节证据）；**材料性缺陷不自授权**，须翻 `等人拍板` 请示用户并留痕；归档已修卡须满足 `fix-evidence` 四行证据（改动面 / 红 / 绿同一条命令 / 可对账提交）。非材料性快修不建卡，由 commit 记根因与影响面。

## P2 门禁准入、原语垄断与资产封顶（2026-09-28 立；2026-11-14 升格）

1. **准入与总量封顶**：新检查须满足「具体错误复发过 + 可机械判定 + 负例与分支变异必漏」；语义判断不进 gate。`checks/gates/` 门禁文件数与 `probes/` 活跃探针数实行**只降不升棘轮**（加新必先并入既有 owner 门禁或退役冗余资产；活跃探针 `未分类` 必须为 0）。口径 = **登记资产**：分类迁移（如工具迁入探针面）可同 diff 校准 cap 并在 Note 论证，实际新增仍须先退役。
2. **横切语义禁裸解析**：门禁与各面 `lib/`（`tools/lib/` 共享地基、`checks/lib/`、`probes/lib/`）严禁手写裸 Markdown 节切分、裸 YAML frontmatter 正则或裸 `.dsh-company` 路径拼接，一律消费唯一注册原语（复用 `vendor/dsh` `mdast` + `js-yaml` / `company-root`；静态门强制；工具盘直写入口须在 `carrier-registry` 的 `WORKSPACE_TOOLING` 登记理由）。

## P3 自动化只许是轻任务（硬上限，不许无限跑）


**背景原则**：不要把"跑一场多人动议"当无人值守自动化任务启动，无预算无刹车会无限消耗上下文与轮次。
用户裁定：**"自动化的任务都一定要变成轻任务，别跑得没完没了。"**

**纪律（写进所有脚本/后台任务）**：

- **先定预算再开跑**：每个自动化任务在启动前写下三个上限——**最长墙钟**、**最多轮次/工具调用**、
  **最多输出量**；到限即停并汇报"跑到哪、还差什么"，不许"再跑一会儿看看"。
- **能 ping 就别跑全套**：门禁默认连通档（[tests/README §验证分层与预算](../tests/README.md)）；只有明确需要内容结论时才升档，且升档也要带上限。
- **可中断**：长任务必须能被取消（web 会话用 `session/cancel`；teammate 各自的 turn 要逐个取消），
  取消后**用已有产物收口**，不重跑。
- **一次一件事**：多智能体编排（spawn teammate / 多轮互审）只在人工在场、明确要求时启动；
  绝不放进无人值守的自动流程。
- **收口优先**：任务已产出关键证据（文件/事件/日志）后，剩余步骤要么用"只做收口"的受限指令
  （明确禁新调研、给工具调用上限），要么人工接手——不要为了"跑完整"再放开跑。


## P4 工具态与越界写入


**背景原则**：工具默认把缓存或元数据写进 `$HOME`（如 `~/Library/Caches/pnpm`）会触发沙箱越界与离线恢复故障，必须提前在仓库内重定向。

**原则（三条）**：

1. **repo 内 = 自由区**：仓库及其 gitignored 运行态区（`runtime/harness-home/`、`.pnpm-store/`、
   `runtime/rehearsal-workspace/`、`runtime/harness-home/cache/`）内的读写不需要任何授权。
2. **越界需求优先用"重定向"消灭，而不是申请**：凡工具要把状态写到 HOME（缓存 / store / 配置），
   **先配置重定向进仓库 gitignored 区，再首次使用**。已有落点：
   - DSH 数据层：`DSH_HOME=runtime/harness-home`（env.sh，双 home）
   - pnpm store：仓库根 `.pnpm-store/`；dev profile 的 `.npmrc` 把 `store-dir` / `cache-dir` 钉在 repo 内
   - dev profile 的 pack：默认 `npm pack` + `plugin add file:<tgz>`（用户侧同形）；`pnpm company --link` 是显式快速通道
   - 排练/探针 cwd：`runtime/rehearsal-workspace/`
   **新工具进工具链时，重定向配置必须在首次使用前完成**——这是引导配方（[bootstrap](./guides/bootstrap.md)）的一部分。
3. **确需越界（重定向覆盖不了的场景）**：先问人，一次说清"写哪个路径、为什么没有替代"；沙箱是最后防线（[run-ops §1](./guides/run-ops.md#1-运行环境双-home-与双-dsh-隔离)），不拿它当默认方案。（反例：`~/Library/Caches/pnpm` `synthetic-from-store` 合成元数据。）


## P5 自主优先协议（D29）

> 依据 = 用户令归纳：「尽量遵循 DSH 的研发流程」「尽量想办法自主解决问题（探索、借鉴成熟 DSH 插件思想）」「能自主审的先自主审，阶段收口不得不让人介入 REVIEW 时再拉人」。适用 = 开发代理对维护者（手册「待办」/问询节流是同精神条款，本节不替代它）。

**三条规矩**：① **遵循 DSH 研发流程**（D13/D23 已立，纪律表 = 落点索引）；② **自主解决问题**——动手发明前**先探索**，优先借鉴**成熟 DSH 插件**既有思想与现成载体（探索产物按 research 层生命周期落盘）；③ **REVIEW 分级**——能自主审的**自主审**，**阶段收口、不得不人审时才人审**，人审形状 = 下述四件套。

**语义审最小清单（验收权分立）**：凡**问题卡归档、门禁增改、跨模块/共享原语收口**，严禁作者同上下文自查顶替 `审查：agent`，**必须拉起无历史上下文的只读独立子代理盲审**（仅机械单步修正可自查）。盲审输入 = **当前 `git diff` + 下列四样判据**（缺一不许出结论；本清单是唯一家，skill/卡片只链接）：
- ① **授权/验收原文**：有否缩水成玩具骨架，或把未完成的原定验收塞进 `## 未覆盖轴` 销账？
- ② **该面合同文档**：docs 只写 now，事实落点是否同 diff 更新？
- ③ **证据选层与注释↔实现一致性**：选的检查能证明承诺的性质吗（[testing.md §1](./testing.md)）？注释声称过滤的语法，代码真过滤了吗？
- ④ **Note 完整性**：决定、输掉的方案、真跑红绿证据、`## 未覆盖轴` 分类前缀与实盘文件锚点齐吗？

blocker 未清零不许归档；结论记入收尾 Note 与卡头。**归位类改动另问**：换公司/产品类型/方法要改吗？要改 preset 或代码 = 错层（[内容宪章](./contracts/content-charter.md)）。

**拉人前自检三问**（全部「是」才许拉人）：① 机器能判的都判了吗（门禁/探针/自主评审全绿——D15，拉人 = 最后一道真检查、一次到位）；② 剩下的判断是不是只有人能做（品味/心智模型/授权裁决）；③ 实例与落点备好了吗（四件套下）。

**人侧请求的唯一合法形状（四件套，缺一 = 违规）**：
① **跑起来的实例**（URL 或一行能起的命令；token 每进程一份从启动横幅读，端口是环境状态）；
② **单页走查单**（看哪里 / 点什么 / 判什么 / 约几分钟，精确到落点——「你去体验一下」类无实例无落点请求 = 违规）；
③ **一次一件事**（一张卡只放同一性质的决定，上下文备到一眼可决——同手册问询节流）；④ **收尾留动作**（每轮收尾给人一个明确的最小动作，或明说「无事可做」）。

**节奏**：默认自主推进到「差不多」，收口点一次性拉人体验；反馈 → 修 → 机器复验 → 有新东西才给新实例。
本节不改变[开发环 §1](./guides/dev-loop.md#1-任务入口与交接) 的授权规则，只规定自主的**方法**与拉人的**形状与时点**。

## P6 维护面契约（两层 · 三面，D63）

> 判据一句话：**主要产出什么？** 裁决 → judge（`checks/`）；证据 → show（`probes/`）；持久状态 → operate（`tools/`）；例外登记 = [surface-exceptions](./reference/surface-exceptions.md)。

- **两层（先判在不在面内）**：① **oracle** = `pnpm test`（vitest，`tests/**/*.spec.ts`）或 `pnpm test:checks`（node:test）跑的测试 → `tests/`（不是面；判 runner，不判进程数）；② **entry** = 需自己起命令/进程/浏览器 → 下述三面。
- **三面（只对 live entry）**：
  - **judge（`checks/`）**：产出裁决——会红，且由 hook/CI/验收据此放行或退回。
  - **show（`probes/`）**：产出证据（截图、摘要、报表、导出）；红了只是给人看，不阻塞变更。
  - **operate（`tools/`）**：产出持久状态（环境/仓库/发布物/生成物），分 **run**（起/复用进程，失败重试即可）与 **act**（持久改动，失败需 converge/repair）。
- **两个前置轴与方向**：
  - **生命周期**：头注 `状态：已耗` → 非面（归档候选），由 `script-status` 门禁强制。
  - **管道件**：lib / driver / fixture / runner / reporter / 纯查询 / support → 非面，跟消费者住（跨面 `tools/lib/`；judge-wide `checks/lib/`；gate-local `checks/gates/lib/`；lane-local `checks/lanes/lib/`；show `probes/lib/`；test-only `tests/support/`）。方向：共享地基不得 import 面库；judge ↛ show/test；show ↛ judge/test；local 只许子树消费。索引生成器纯逻辑跟消费者，写盘命令归 operate（`tools/repo/*`）。
- **判定顺序**：1. 已耗 → 非面；2. 管道件 → 非面，跟消费者；3. 主要产出 → 裁决/证据/状态；4. 混合件按终端产物、双模件按主产物、被 judge 调用不改变面；5. 仍冲突按 **产物 > 失败语义 > 名字**。
