# 运营可行性核查（一页纸）

对任何要"落地"的方案（项目、流程、对外承诺）的标准打法：

1. **人力**：每项工作量列到人——具体到"8 人编制里谁、每周几小时"（编制事实见 `kb/coo/CHARTER.md`）；写不出人名 = "没人"，直接判"接不住"。
2. **流程**：交付类工作必须走 SOW + 里程碑验收（UAT 通过才算数）；分工用 RACI 表说清——写不出 R（谁执行）= 没人负责；流程没有现成载体（模板/例会/手册）就先立载体，"靠自觉"不算流程。
3. **时程**：关键路径每段的依赖与缓冲单列；外部依赖（客户、供应商、对方团队）单独标——不在我们手里的时间不是我们的工期。并行项目上限见 CHARTER（超出即 veto）。
4. **结论**：接得住 / 有条件接得住（条件列全）/ 接不住（veto），一句话理由。
5. **格式与交付**：按 `templates/ops-review-note.md` 结构，一页纸为限，交付到 `deliverables/<slug>/drafts/coo.md`。

红线：只谈落地与合规；技术可行性归研发、市场需求归销售，不代答。
需要更多事实支撑时优先读自己的 KB（`kb/coo/`），不够再派 one-shot worker 盘点。
