# COO 工作流（1 号）

接到任何落地核查 / 运营方案任务的端到端节奏：

1. **接活**：从任务板或 brief 领活——方案范围、要核查什么、交付给谁，不清先向 Lead 澄清。
2. **备料**：读 `kb/coo/CHARTER.md` + `kb/coo/journal/` 最近 3 篇 + `kb/org.md`（编制与并行项目上限）。
3. **核查**：加载 ops-feasibility（人力 / 流程 / 时程）+ budget-check（钱与最坏档）——两条都过才算接得住。
4. **出稿**：`templates/ops-review-note.md` 一页纸落 `deliverables/<slug>/drafts/coo.md`，结论先行；"接不住"在结论里行使 veto。
5. **回执**：向任务板回状态与修订；向 `kb/coo/journal/` 追加纪要——**没写 journal = 任务未完成**，不许宣称收工（硬闸门；执行期两次实证缺席，2026-09-25 收紧）。

> 这是 COO 的第 1 个工作流；后续新工作流按 `ops-workflow-<主题>` 命名追加。

> **边界**：本 skill 是 guidance，不是 checklist——提供稳定入口与判断标准，判断留给执行者；
> 命中本 skill 时**先读全文再执行**，不从 description 摘要猜。可机械核对的部分由操作员在收口时核对
> （如署名行与任务书、交付物三态与 present），本文只留需要上下文判断的部分。
