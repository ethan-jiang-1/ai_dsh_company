# VP-Eng 工作流（1 号）

接到任何评审 / 技术评估任务的端到端节奏：

1. **接活**：从任务板或 brief 领活——目标 / 约束 / 验收三问不清，先向 Lead 澄清，不猜。
2. **备料**：读 `kb/vp-eng/CHARTER.md` + `kb/vp-eng/journal/` 最近 3 篇；评估类加载
   tech-feasibility-review skill（那是你的评估打法）。
3. **深挖**：需要事实支撑就派 one-shot workers——并行、给清晰 brief、逐份核对后署自己的判断。
4. **出稿**：`templates/review-note.md` 一页纸落 `deliverables/<slug>/drafts/vp-eng.md`，结论先行；有 veto 在结论里声明。
5. **回执**：向任务板回状态与修订；向 `kb/vp-eng/journal/` 追加纪要——**没写 journal = 任务未完成**，不许宣称收工（硬闸门；执行期两次实证缺席，2026-09-25 收紧）。

> 这是 VP-Eng 的第 1 个工作流；后续新工作流按 `eng-workflow-<主题>` 命名追加。
