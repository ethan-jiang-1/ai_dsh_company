# playbook：项目制 / 系统集成

> 用在：客户现场交付型产品、系统集成、定制开发、带实施的项目。MRD 仍回答"该不该做"；
> PRD 必须能落成 SOW 与 UAT。定价/毛利归 VP-Sales/CFO，本 playbook 只定义需求与验收。

## MRD 多出来的问题

- **谁买单、谁验收**：客户方决策链（业务 owner / IT / 采购 / 法务）分别关心什么？
- **边界**：这次集成到哪些系统（ERP/财务/业务系统）？接口是现成的还是对方要改？
- **依赖**：对方提供的环境、数据、接口文档、测试窗口；哪一项不在我们手里？
- **不做的代价**：客户现在怎么凑合（手工对账、Excel、外包）？为什么现在要换？
- **可复用性**：这次交付里哪些能变成标准能力，哪些是一次性工作？
- **成功判据**：上线周期、验收通过率、人工工时下降、续约/增购信号。

## PRD 多出来的字段

- **SOW 边界**：in-scope / out-of-scope 逐条写；接口清单带对方系统名与版本。
- **UAT**：每条 REQ 的验收要能写成 UAT 用例（前置数据、步骤、期望结果、谁签）。
- **实施里程碑**：环境就绪 → 联调 → UAT → 上线 → 稳定期；每个里程碑的出口条件。
- **第三方依赖**：责任方、交付日期、缺失时的降级方案。
- **现场与人力**：是否需要驻场、培训、切换窗口；人力估算引用 COO 的排期（不在这里下结论）。
- **风险**：对方接口变更、数据质量、验收口径冲突；每条带兜底。

## 常见反模式

- 把"集成"写成"对接一下"——没有接口清单与责任方，等于没定义。
- 验收只写"客户满意"——不可判；必须落到 UAT 用例。
- PRD 里夹带报价/工期承诺——那不是 VP-Eng 的签字线。
